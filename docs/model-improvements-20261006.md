## 1．模型不稳定优于简单基准

新增独立命令 `football_model.quality`，先冻结协议，再比较联赛平均进球泊松、原球队泊松、两者50%比分概率混合。每日UTC原点只用开赛已满4小时的此前赛果重新拟合；原半衰期180天、ridge=3、至少180场不变。另考察仅按此前已成熟共同样本选型的政策，前40场不足时用平均进球基准。候选不能使用当天结果选型，混合的是完整概率矩阵。

研究区间为2025-09-01至2026-10-06。以下为相同覆盖样本的胜平负Log loss，越低越好：

|赛事|共同样本|均值基准|50%混合|球队模型|历史序贯政策|
|---|---:|---:|---:|---:|---:|
|欧国联|78|1.07923|1.05618|1.05117|1.07100|
|MLS|526|1.06265|1.04359|1.04672|1.05115|
|墨西超|363|1.06447|1.03406|1.03639|1.04514|
|英超|398|1.09162|1.05050|1.03276|1.04197|

墨西超另有1场、英超另有2场球队模型不能覆盖，政策回退均值，这些场次没有混入共同样本。窗口数分别13、113、127、121；本次没有优化触边拟合，代码仍按生产规则拒绝触边候选。

**问题1仍未完成质量验收。** 新研究的日期、样本和每日重拟合与旧固定留出不同，不能直接减去旧评分声称修复了多少。大2.5在欧国联、墨西超、英超仍落后均值基准，MLS的固定混合与球队模型有所改善；只按胜平负选型的政策不能自动代表大小球最优。程序还报告净胜2球以上、2.25/2.75五态及固定十组校准结果。

以上是使用当前历史文件的开发重演，未证明当时的数据可得性，不是独立前瞻验证。没有同截点赔率，未计算或宣称收益。暂不切换生产模型，也不因为局部历史最优而增加事后调参。

下一阶段应先冻结拟使用的候选、市场与评价规则，再积累真实赛前预测，追加赛果评分，分别检查胜平负、让球及大小球。基本面特征须在有时点样本后进行独立增量比较；数据量应按效果差异和不确定性评估，不能预先承诺准确率或达标日期。命令与协议详见 [quality-research.md](quality-research.md)。

## 2．任务成功但模型超龄、没有可用预测

国内联赛与欧国联采用同样的真实刷新逻辑：有未来比赛，且模型当前或开赛时超过14天，就执行验证和重新拟合，并另存模型历史。数据未变不再导致永久重复沿用超龄参数。没有未来比赛则不为改时间戳重新拟合，明确记录空窗。

报告及索引新增：

- `forecast_availability`：可用、部分可用、全部不支持、空窗或失败，以及场次数和原因。
- `model_freshness`：训练截止年龄、开赛时年龄、最新训练赛果年龄、实际评估时刻。
- `model_refresh`：刷新原因、是否实际执行、原模型版本及训练资料是否变化。

保留14天门禁、未知球队和场地检查、真实完成时间检查。拟合失败保留旧文件，但阻止把旧预测当作本次成功。新拟合使用同样赛果并不等于获取了新消息，报告会明确披露。

真实英超810场已保存赛果进行了离线工程回放：输入指纹与旧模型完全相同；旧模型在目标开赛时年龄17.9794天，真实重新拟合后3.9866天；1场生成可用基线，单场命令实际复算一致。最近训练赛果仍已15.8467天，未掩盖资料年龄。传输使用模拟包装，没有真实API请求、没有生产写入，也没有重新核实该场当前赛程、场地或阵容；不能当作实际赛前分析。

## 3．基本面没有可靠进入量化流程

新增 `fundamentals.py` 和 `collect_fundamentals.py`，先完成可审计的数据与特征层：

|资料|已实现内容|保留的限制|
|---|---|---|
|伤停|球员ID、缺阵/存疑原类型、原因、抓取时间、一致重复去重|空响应不等于全员健康；没有已验证球员强度或概率系数|
|首发|11人完整性、上一场延续度、历史常用首发频率|未公布保留缺失；上一场缺名单不能悄悄替换成更早一场|
|历史xG|只读真实 `expected_goals`，双方配对覆盖及近场均值|字段不存在、null和0分开；本场赛后数据不能进入本场预测；排除加时统计|
|休息间隔|已保存同赛事历史的开赛时间间隔|不是完整跨赛事工作量或疲劳强度|

快照绑定比赛ID、主客、开赛时间、端点、原始响应、上下文观测时间和内容指纹，以内容寻址追加保存。当前下载的历史首发可以服务未来比赛特征，不能倒填成旧比赛赛前已知。目标赛事先重新查询精确身份及未开始状态；请求结束后使用真实截点，若已开赛只保留证据，不发布赛前特征。

复核仓库既有真实API探测附件：GitHub artifact `11361335147`、run `37346571535`，ZIP SHA-256为 `75ac0356472f44e1beb4d3d11dcdd1e77d74e7b5801206bd871e14489a350316`，观测于2026-10-05。4份独立统计和1份伤停原响应通过规范化；批量16场另外做了派生结构解析，未冒充独立原请求。32个球队统计中12个有xG、6个为null、14个无字段；26行伤停实际是13名球员各重复两次。供应商覆盖不能统一假定完整。

生产概率仍明确标记 `fundamentals_used_in_probabilities=false`。没有凭经验给伤停或xG硬加减λ；人员价值、战术及基本面系数训练尚未完成，预测增益更未验收。

### 采集入口

```bash
python -m football_model.collect_fundamentals --runtime runtime --config config.json --league all --horizon-hours 24
python -m football_model.collect_fundamentals --runtime runtime --config config.json --league epl --match-id ACTUAL_MATCH_ID --horizon-hours 168
```

第二条需替换为实际整数比赛ID。命令需已有可信索引和预测身份，以及正常安全环境变量中的API凭据。不会训练或改写模型概率。默认收集双方各最近5场同赛事历史，明确不保证全赛事完整。

日常训练后自动采集未来24小时比赛的基本面；基本面失败单列，不把比分模型成功误报成基本面成功。首发只在目标开赛前90分钟尝试，每日一次不能保证取得临场首发，因此另有手动工作流 `fundamentals.yml` 可更新指定比赛，不新增自动轮询日程。

仍使用已有每日5000次配置、供应商实际剩余额度、缓存与限速；不增设任意小的每轮次数上限。采集软截止15分钟，预算不足留存已有证据并明确延期；不因某一场失败丢弃其他场次。快照、特征及逐次报告随完整runtime长期保存。
