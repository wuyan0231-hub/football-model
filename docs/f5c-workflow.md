# F5-C影子发布与持久状态验收

本轮只从已有生产180天预测派生总球收缩候选，生产模型、参数、固定留出、数据规则和北京时间09:17日更不变。F4的90/180/365天对照仍使用原协议和目录，新F5-C记录保存到独立 `runtime/total_shrink_shadow/`。

## 两条运行路径

- 原 `.github/workflows/football.yml` 保留日更及已有训练/场地/数据发布路径；`train`运行在既有步骤之后追加F5-C派生和评分。没有新增定时采集。
- 新 `.github/workflows/football-total-shrink.yml` 是本轮影子模块及纯保存/摘要改动的main push验收路径。它只加载完整旧状态、从已有生产预测派生全部赛事候选、评分已有影子记录、检查和保存完整状态、上传便捷证据及分层摘要，不调用生产训练、F4影子拟合或API采集。
- `state_storage.py`、`run_summary.py` 的push路径已从原训练工作流移至新验收路径，避免仅修复压缩或摘要就触发重复欧国联训练。原训练/场地/数据相关路径继续保留。
- 两工作流的并发组均为 `football-model-state`，不取消运行中任务；同一时间仅有一个状态写入者。本轮代码合并触发新验收，正常情况下不再次手工派发。

## 失败不能被保存成功掩盖

派生和评分均运行，即便前一项非零退出也保留后一项的实际结果。工作流使用 `steps.*.outcome` 记录原始执行结果；`continue-on-error`仅使后续检查、保存、报告有机会完成，最终门禁会把派生/评分或状态保存等必要步骤失败标记为作业失败。

摘要在保存步骤之后生成，分别报告恢复、影子派生/评分、输出检查和保存的实际outcome。专用模式为 `shadow_only`，不要求未运行的模型训练、回放录制或API步骤成功。摘要附件不冒充已进入同次model-state提交。

`FOOTBALL_API_KEY`仅向 `cloud_state.py check/save`提供，用于检测输出中意外出现的凭据，不向F5-C派生/评分提供，也不输出密钥。运行没有API访问。

## 无损持久保存

`state_storage.should_archive`把 `total_shrink_shadow/` 中摘要目录以外、以64位内容地址命名的JSON原件纳入原有gzip无损传输。`reports/`保持普通路径直接读取，未经内容寻址的JSON保持inline。恢复先验证完整清单、压缩/原字节指纹、路径及容量，再恢复原路径和原字节；研究应用目录不被压缩改写。

新记录的保存预算仍复用 `state_storage.storage_cost` 和 `estimate_runtime`，保存上限、逻辑大小、单文件限额及容量延期记录均保留。新增支持不能证明长期增长问题已彻底解决。

## 真实云端验收

F5-C从成功load后的应用标记读取所加载model-state提交，先核标记源码与本轮`GITHUB_SHA`一致，再把真实`state_oid`写入候选父证据；不读取凭据。

合并之后须读取实际运行日志和保存后的固定model-state提交，逐项核对：完整旧压缩状态加载、F5-C协议登记时间、生产父原件与候选原件、版本数和独立比赛数、冷启动与不准入原因、评分状态、压缩清单及实际保存大小。真实退出与步骤outcome、远端提交和归档恢复分别核验，不能由CI测试或工作流绿色结论代替。

影子派生验收成功只证明工程运行和证据保存。未来样本待赛果、概率评分、准确率、等级、实际报价和收益仍是不同验证任务，不能据此宣称准确率或收益提升。
