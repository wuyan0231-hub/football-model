# F4 首轮：半衰期历史实验

`football_model.quality_half_life`复用原`fit_model`、`score_distribution`及`quality`矩阵摘要/校准口径，仅新增离线研究。生产公式、参数、固定留出、每日任务均不改变。它不是原任务回放，亦不能自动批准模型上线。

## 先冻结再运行

每联赛单独输入当前已核准的90分钟加补时终场比分。CLI先保存协议并绑定输入原字节SHA-256，再读取同一协议执行；拒绝数据改变和结果覆盖。保存时间是真实运行时钟，本地文件不能充当外部时间戳认证。源码提交、状态提交与数据准入证据由调用者一同归档。

```bash
python -m football_model.quality_half_life --matches FIXED_DATA.json \
  --start 2025-10-07T00:00:00Z --end 2026-10-07T09:54:42Z \
  --ridge 3 --min-train 180 --freeze-protocol NEW_PROTOCOL.json
python -m football_model.quality_half_life --matches FIXED_DATA.json \
  --protocol NEW_PROTOCOL.json --output NEW_RESULTS.json
```

开始/结束日期须在检查效果前确定。示例不是保证该联赛有足够数据。

## 固定对照

- 半衰期只比较180（基线）、90、365天，其他原参数不变。保留训练均值Poisson基准。
- 每7天一个拟合截点；窗口内比赛均用窗口起点的模型。训练只允许截点前已满4小时的结果；仍须上游核实终场状态。
- 外层评价开始前180天产生内层验证预测。每个外层截点只在过去180天、结果已经成熟、三种半衰期共同覆盖的内层预测上选择1X2对数损失最低者；至少40场，并列优先180、90、365，不足用180。
- 之前外层比赛的结果可以在之后截点成熟后进入内层，属于预先固定的顺序验证。当前及未来外层结果不能选择当前参数。内层预测只需计算一次，避免相同原点重复拟合。
- 被选模型对本场不可用时明确回退180；180仍不可用则弃权，不偷偷借均值补齐。均值独有覆盖另列。拟合失败、边界参数、未见球队均保存。
- 主要比较为“按上述规则选择的政策减180”。90、365和均值的固定对照为探索诊断，不从这些外层成绩事后挑胜者并称已验证。

## 指标与解释

使用`quality`既有1X2、大2.5、主净胜2+及大2.25/2.75五态指标，附1X2最大概率命中率。比分与总球采用同一原模型λ的未截断Poisson对数损失，净胜球采用Skellam分布（概率下限1e-15），另给总球/净胜球均值绝对误差。1X2仍使用生产实际归一化矩阵，截尾信息随预测保存；两类口径明确区分。

所有候选共同样本、每个候选自身覆盖、每项与180的配对样本分别报告。新增覆盖、丢失覆盖、双方皆缺的比赛ID不可删除；不同候选自身覆盖的分数不可直接当增量比较。

配对损失按从评价起点划定的28天块聚类；有至少8个非空共同覆盖时间块才给固定种子、2000次重采样的95%百分位区间，否则保留缺失原因。这只是历史开发的描述性近似，不处理全部长程依赖或跨联赛多重比较，也不是盈利/上线门槛。比赛数、周数和块数分开；同场三模型不是三场独立样本。

原模型按时间窗口及实际总球0—1、2—3、4+诊断误差。后者用赛果分组，仅用于定位问题，不能成为赛前选择规则。

所有输出固定`historical_development_replay`、`point_in_time_sources_verified=false`、`prospective_validation=false`及`deployment_approved=false`。当前已修订的历史比分、登记和供应商信息不能冒充旧时点可得快照；四小时只是假设延迟。没有历史真实赔率、费用和成交证据，因此本轮不计算收益，也不因历史领先替换生产模型。
