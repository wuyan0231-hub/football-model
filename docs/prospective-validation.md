# 真实前瞻预测与独立评分账本

此模块冻结实际取得的未来比赛预测，随后连接常规时间赛果。它不重新拟合球队模型、不倒填历史预测，也不代表预测质量或收益已通过验收。开发回放与本账本分开。

```bash
python -m football_model.prospective --runtime runtime --config config.json
```

生产CLI在每个联赛预测完成后即以真实时钟冻结，独立 `capture_checkpoints/` 与 `capture_runs/` 通过本次 `run_id` 关联最终报告；它们不宣称后续联赛或持久保存已经成功。工作流在全任务后仍运行上述命令核查补漏和评分，保存整个 `runtime/prospective/`。返回 `0` 表示本次记录和评分流程完成，`1` 表示有局部拒绝或错误，`2` 表示全局失败。无论评分成功与否，模型和原预测文件均不由本模块修改。任务调用者必须单独保存和展示评分状态。没有 `--as-of` 参数；测试时的注入时钟不属于公开命令。

## 冻结与资格

只读取 `reports/latest.json` 指定本次 `run_id` 的预测文件，不在本次缺失时读取其他历史目录冒充本次成功。报告未完成、无预测、unsupported 和拒绝原因进入覆盖记录；完整预测文件、报告、原模型、规范化数据分别有内容指纹和冻结副本。

预测行必须有匹配的比赛/球队/开赛时间、模型版本、训练指纹、完整合法比分矩阵及已说明的行列含义；胜平负概率要与矩阵相符。真实抓取、生成、报告、登记时间须自洽，**登记时仍未开赛**，训练截止/拟合时间不能晚于预测生成。`research_replay` 报告或预测，以及运行目录或父目录的 `RESEARCH_REPLAY.json` 标记均拒绝进入前瞻账本。

每个协议、赛事、比赛的**首个合格实际赛前登记**是主评分版本。若比赛改期，以首个与最终赛果身份（含开赛时间）一致的合格快照评分；旧时间快照明确保留为 `result_identity_changed_unscorable`，不能用旧快照永久阻断正确的新预测。同场后续预测保留版本，不增加独立样本；相同时钟精度下以追加序号确定先后。首次安装后取得的旧赛前文件，如果此刻比赛已开始，只留拒绝记录，不补造历史前瞻。

以下目录为仅追加且按内容 SHA-256 命名的对象；读取时校验内容指纹，路径穿越、符号链接和并发写入受保护：

| 目录 | 保存内容 |
|---|---|
| `protocols/` | 事先固定的市场线位、选版、评分、报价模拟规则 |
| `sources/` | 原报告、模型、预测、规范化数据的完整内容与原字节指纹 |
| `forecasts/` | 真实捕获时间、比赛身份、完整原预测和基准分布 |
| `coverage/` | 每次运行的预测覆盖、unsupported、拒绝和无文件状态 |
| `results/` | 赛果与观测时间；更正追加新版本并指向旧版本 |
| `quotes/` | 报价输入、实际登记时间、合格或不可用原因 |
| `runs/` | 每次派生评分报告，保留历史计算结果 |

`latest.json` 只是可更新的派生视图，不是原始账本。内容指纹可检测意外修改；它不是外部可信时间戳服务或防管理员篡改保证。

## 赛果与三市场评分

只从已有数据流水线生成的 `runtime/data/<competition>.json` 读取90分钟加补时的规范赛果，核对双方/开赛身份、真实 `observed_at`，以及已有四小时保守缓冲。该口径依赖上游对 API-Football `score.fulltime` 和终场状态的核准；四小时本身不能证明完赛。无赛果保持 pending；身份变化或未来观测拒绝评分。

后续观察到比分修订时，追加结果版本，不覆盖原赛果或原预测。最新视图使用最新合格结果，旧运行评分仍保存。模型与联赛均值基准在**相同比赛集合**比较；基准只有在同截点可用数据重建出的训练指纹与原预测完全一致时才冻结，否则明确缺失，不用后来数据回填。

每项报告给独立比赛数、Log loss、Brier 和固定十箱校准计数/预测均值/实际频率。Brier 使用 `mean(sum((p-y)^2))`。`log_loss` 是使用 `1e-15` 数值地板的展示值，同时明确保存地板、受影响数量及真实发生事件原概率为0的数量。原概率为0且事件发生时，数学Log loss为正无穷，记录 `mathematical_log_loss_status=positive_infinity`、数值字段 `null`（JSON不能表示无穷）；其他情况另给未经地板处理的数学值。原预测概率不修改，不能用有限展示值隐去零概率失配。这些是描述性结果，没有自动“更准/盈利”通过线。

- 胜平负：三项分类评分。
- 亚洲盘：按选定球队的让球数结算；客队盘口按客队净胜球定义。
- 大小球：按真实总球线与所选 over/under 结算。

统一保存全赢、半赢、走、半输、全输。每条线位的结构性不可能状态由结算数学确定，并从分类校准类别中排除；不能从截断矩阵的零值猜测不可能状态。例如大2.25只有全赢、半输、全输。不同线位/协议不混合评分，同一比赛多种合约的结果具有相关性。

默认预声明诊断线为：主队让球 `-1.5/-0.5/0/+0.5/+1.5` 及各自对侧；大小 `2.25/2.5/2.75` 双侧，共16个合约。这些是**固定诊断线，不是假装取得了市场报价**。可以在新预测登记前于配置新增：

```json
{
  "prospective": {
    "contracts": [
      {"market": "asian_handicap", "side": "home", "line": -0.75},
      {"market": "total_goals", "side": "under", "line": 2.25}
    ]
  }
}
```

协议内容变化产生新指纹，原样本不改协议、不回填新主版本。

## 实际报价登记与固定单位模拟

真实参考报价现在由独立 [Q采集器](quote-collection.md) 保存；API报价不会自动升级为本节严格模拟准入。另有 [采用版与三类协议评分](s2-decision-scoring.md)，与本节原300秒/3600秒协议分开。取得满足本节协议的真实赛前报价后，仍可使用已登记预测 ID 传入 JSON 列表：

```bash
python -m football_model.prospective --runtime runtime --config config.json --quotes quotes.json
```

以下只是输入结构示意，不能作为真实报价使用：

```json
[
  {
    "forecast_id": "替换为forecasts目录下真实文件名去掉.json",
    "competition": "epl",
    "match_id": 123,
    "home_id": 10,
    "away_id": 20,
    "kickoff": "2026-11-01T16:00:00Z",
    "contract": {"market": "total_goals", "side": "over", "line": 2.25},
    "quoted_at": "2026-11-01T15:20:00Z",
    "observed_at": "2026-11-01T15:20:30Z",
    "source": "实际可核查的报价出处或证据引用",
    "bookmaker": "真实公司名",
    "price_status": "open",
    "conditions_status": "satisfied",
    "decimal_odds": 1.95,
    "cost_per_unit": 0
  }
]
```

资格规则固定为：身份匹配；真实登记时尚未开赛；报价时间不晚于观测、不晚于登记；报价最多陈旧5分钟；冻结预测最多陈旧1小时；开放状态和条件已满足；来源、公司、十进制赔率与每单位固定成本明确。0成本也须显式填写。任何缺项均保留为 `not_available`，不能把未知费用或条件当0或已满足。输入来源陈述不等同于供应商认证或成交凭证。

合格报价按“同协议、赛事、比赛、合约首个登记价，固定1单位，不按EV再挑选”结算；后续改变赔率不会替换初始价。输出实际输入线位的概率评分、冻结模型EV和模拟净收益，条件成立后仍无赛果保持 pending。净成本定义是每个结算状态都减去 `cost_per_unit`，不处理按盈利收取的佣金。需要不同费用模型应另设协议。

这是固定登记规则的模拟；报价集合由外部输入选择，不能称已经验证了自动选票策略，更不是实际投注/成交结果。没有合格报价或没有成熟结果时收益为 `not_available`，不填0。此实验准入不是日常定性推荐的统一门槛。
