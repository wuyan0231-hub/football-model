# 足球盘口分析框架 v1.7 修订批次九

版本标识：`football-analysis-v1.7-r9`。本版发布日期：2026年10月13日，北京时间。本版以批次八完整正文为直接底稿，逐项保留原流程、七节项目入口、赔率规范独立调用、F5-C同父核验与评分独立状态；新增按用户2026年10月12日专项授权实施的statsmodels固定基线修正、goalmodel独立候选及双时距影子研究接口。生产180天基线未因本版自动晋级或改用候选；panna暂缓。历史规则、冻结试验和原件身份保留。真实继承清单见`docs/evidence/feature-models-rule-inheritance-20261013.json`。正文真实SHA-256用于核验制品，不能代替修订批次递增。性质：完整执行规范与证据记录要求；文档发布、程序部署、真实流程通过和预测效果改善分别报告。

本框架用于单场赛前分析、临场／滚球更新、赛后复盘及后续验证。执行者按第2节推进，用第3—12节作判断，用第13—17节保存和验证。赔率截图读取直接执行项目内唯一现行《赔率截图读取规范》，不指定其版本；第4节只规定规范调用、证据交接和下游采用边界。日常不需拼接旧框架、历史补丁或审计包；历史报告和既有冻结试验按当时保存的规则核验。

**目标是同时做到：每场判断有明确理由与处理条件；当时用了什么资料、模型和报价可以回查；后续能区分执行改善、预测改善和收益改善。** 完成记录只能为验证提供条件，不能提前宣称有效。

## 1. 任务、对象和基本边界

### 1.1 固定约定

1. 中文交流，用户可见时间使用北京时间；机器时间用含时区的ISO 8601，保留来源原时区。默认只看90分钟＋伤停补时，不含加时和点球大战；常规时间内罚点球进球计入。
2. 默认任务是单场、胜平负／亚洲让球／大小球三个市场、一个相对主方向，并分别判断单关与候选串关腿。未提供其他腿、资金或订单，不阻断单场分析。
3. 支持提前约10小时分析：使用有来源的预计首发和关键替代，不统一等待正式首发。没有xG、模型或普通首发信息，不自动判“不建议”或“条件适合”。
4. 相对倾向、合约适配、证据强度、盈利概率、报价比较、净EV、实际执行分别记录。缺失保持`null／未知／未量化`，不填0、不编概率。
5. 正式适配只有“适合／条件适合／不建议／暂无法判断”。A/B/C/D/U为另行记录的影子等级，尚未证明有效，不替代正式四态，不绑定固定胜率。
6. 生产模型采用当次核实的已部署基线；本版编制时为180天半衰期方案。人员、xG、市场融合、F5候选等未取得相应用途资格的模块不得暗中进入正式概率。
7. 原预测、原条件、失败、弃权、缺件及所有更新版本不可覆盖。更正另存，保留原值、依据、影响和时间。默认不提供资金配置或强制凑串。

### 1.2 先选运行模式

任务类型与验证模式分别登记。例如“赛前分析＋流程试运行”；不能把所有普通分析都自动计入实验。

| 模式 | 必须完成 | 可以得出的结论 |
|---|---|---|
| 普通分析 `ordinary` | 唯一对象、可用资料、合约判断、限制披露；能保存的实际保存 | 本场有据的定性或量化判断 |
| 真实流程试运行 `flow_pilot` | 普通分析要求＋真实输入冻结＋统一输出＋语义核对＋实际保存回读＋当前容量检查 | 这一场哪些流程环节已真实完成 |
| 框架对照 `framework_comparison` | 事前登记＋完整固定政策全文＋共同中立证据／模型＋隔离独立首输出＋统一结果与评分 | 同范围的流程及预定指标差异；效力取决于实验设计 |
| 模型研究／确认 | 固定代码／数据／选参／评分／样本政策；开发与未来确认分开；特征研究按6.6与16.3另记候选和时距 | 相应研究或确认范围内的模型证据；工程影子不自动取得正式确认资格 |
| F5正式确认 `f5_confirmation` | 专属协议、成熟链、容量、捕获资格及不可变未来激活记录均验收 | 仅协议定义的正式确认结果 |

当前框架优化阶段，新比赛优先以`flow_pilot`真实流程试运行执行：在S00登记实际模式与请求，按第10节五门逐项记录证据和通过／部分完成／阻断／不适用／未执行状态，检查读取、计算、语义、保存与回读是否真实走通。用户明确指定其他模式或任务不属于新比赛流程检验时，按实际任务登记，不机械套用。

这项优先要求不是全场发布的硬门槛。某项资料、模型、接口或保存条件不足时，按1.3限制受影响对象和数值，保留流程尝试的失败／未完成记录、原因与影响；仍可完成有证据支持的普通分析，并分别标明本场分析完成度和流程验收完成度。不能把失败尝试删除、改称成功或从已登记实验请求分母剔除；也不能仅因局部流程缺口把所有票统一判成“不建议”。存在身份、合约或硬错误等核心阻断时，仍执行1.3和第10节对应限制。

普通分析和流程试运行不以F5激活为前提。未满足某实验的资格，仍保留该请求和失败原因，并限制该实验的声明；不把它伪装为成功样本。

| 发现的问题 | 处理 |

## 3. 信息截点与原件保存

### 3.1 分清七种时间

| 时间 | 含义 | 禁止替代 |
|---|---|---|
| 来源发布时间 `source_published_at` | 来源自身发布的时间，记录可信度 | 不能当执行者已读时间 |
| 报价变化时间 `quote_at` | 页面该行显示的价格／状态变动时间 | 不能当截图时间、取得时间或成交时间 |
| 实际取得时间 `observed_at` | 本流程首次真实取得该资料版本的时间；重读另记`read_at` | 最初取得未知时保持未知，不能由本次重读、来源发布时间或缓存复制反推 |
| 分析截点 `input_cutoff_at` | 此次输入允许进入的最后边界 | 不能倒填成“赛前” |
| 决定冻结／生成时间 | 输入关闭后结论冻结及文件实际产生的时间 | 不能当聊天已发表或用户已收到 |
| 持久保存完成时间 `durable_saved_at` | 对应外部提交／上传真正完成的时间 | 本地写入不等于远端保存完成 |
| 发表／成交时间 | 各自真实事件发生的时间 | 无凭证保持未知，不能由文件名推算 |

开球时间及其后续修订另存；不得把改期后才生成的文件认证为原计划截点的成功。用于未来评价的资格按预定协议核真实开球、输入取得、预测生成与持久保存，不因后来比分有利放宽。

### 3.2 冻结什么

保存实际使用的规则全文、资料原文／合法摘录与URL、原图、完整采用报价行、模型原件、配置、相关验证与日志。每件带：`source_id、角色、相对路径、sha256、实际取得时间、来源、读取程度、关联比赛`。哈希由文件真实计算；不生成占位哈希。

读取程度固定为“原文已读／仅转录或摘录／仅文件名或链接／未取得”。完整网页不能保存时留实际读到的片段、定位、来源和限制，不写成全文原件。截图须实际保存可读图像；外链或OCR文字不能替代原图回核。

输入、派生计算、独立判断、结果／评分分别存层。结果层和复盘意见不能进入赛前共同输入；清单仅含本次获准读取且实际取得的文件。新资料晚于截点时只进入新版本。

### 3.3 三条证据结论分别报告

- **内容可复现：**有原件及可运行的计算，第三方能按同一输入复算。
- **时点合格：**有证据表明这些输入和输出确实在所声明时点已取得／保存。
- **前瞻合格：**还满足预登记、未暴露未来信息、独立首输出和完整入样政策。

三者不能互相代替。赛后建立的包、填过去的`as_of`、哈希自洽或遮住已见赛果，均不能恢复干净前瞻资格。搜索结果摘要可能泄漏结果；发生时记录暴露范围，不删除该请求。

## 4. 调用《赔率截图读取规范》与报价采用

### 4.1 唯一现行规范

项目内只保留一份现行《赔率截图读取规范》。这是固定调用名称；实际文件名可带版本、批次或其他说明，不要求改名。本框架不固定其版本、发布日期、文件名后缀或内部章节号，也不复制其读图细则。来源配置、行定位、历史观察、赔率转换、截图状态与时间、滚球合约识别、复核、纠错和读取输出，均执行该规范完整正文。

首次使用、新对话或上下文缺失时，实际读取该规范全文并核对文件身份；同一完整上下文中已读且内容未变的副本可沿用，内容变化后重读。不得凭旧记忆、文件名中的较大数字、上传先后或“最新版”字样推断已执行哪份规则。若必要原件缺失、不可读，或出现多份现行文件且无法唯一确认，列明缺口／冲突，阻断依赖该规范的截图读取与采用；不影响已有独立合格证据支持的其他工作。

### 4.2 每场身份与冻结

每个分析版本记录实际使用的规范文件名、正文标题、正文声明的版本／标识、全文真实SHA-256、读取时间和冻结副本引用。规范未声明版本则记未知；无法取得原字节计算哈希或保存副本时，如实标明缺口，不伪造指纹或完整冻结。保存要求与资格按第13—17节处理。

替换项目内规范后，后续新建的普通分析／流程试运行使用唯一现行文件；同一分析版本内不得静默换规。后续更新若采用新规范，另建分析版本，保存父版本、新旧规范身份、改变的读取结果及对结论／资格的影响。历史复盘、重现和既有冻结试验仍用各自原来冻结的规范；新规范重读旧图只能作为追加更正或另列比较，不能改写原始记录、恢复当时不存在的资格，或替换既有试验政策。

旧规范副本保存在对应比赛／试验的证据归档中，不作为项目现行规范候选。这与项目只放一份最新版并不冲突。

### 4.3 读取结果交接

执行者按所用规范交付其要求的报价摘要、可追溯读取记录、原图／来源引用、复核与纠错证据、未知及受限范围；字段和具体读取步骤以该规范为准。本框架核查这些结果足以确定拟采用报价的来源、合约、价格、状态、时间与用途，再进入第7—11节的判断和计算。读取完成、报价可作参考、可成交和适合推荐分别判断，不能互相替代。

分工为：规范负责把截图读成可追溯的报价与合约记录；本框架负责证据采用、代表价选择、足球判断、支付映射、概率／EV、推荐、复盘和效果验证。遇到实际冲突，保存冲突原文及影响，核实真实来源／合约；未解决时限制受影响票，不静默沿用旧读图细则，也不以默认解释覆盖实际订单条款。

### 4.4 下游报价采用边界

比较价格须同比赛、范围、线位、支付事件、状态及可比费用。主胜与主队−0.5在相同范围／条款下支付相同，可比较价格，不算两个独立支持。不同盘口不可只比较赔率高低。

代表价按实际用户可用平台、明确指定来源、同状态较优参考或预注册研究基准选择并写理由。同表有更好可比价未采用时说明原因；不同公司完整1X2可各自按第8节去水，不拼最高价制造市场概率。

报价用途分开：`QUOTE_REF`参考纸面；`QUOTE_OPEN`有对应开放证据的模拟；`QUOTE_ACTUAL`有本场实际成交证据。角色升级必须新增证据，不能因数字存在而自动升级。真实开售、接受和费用仍未知时明确未知。

非截图报价须保留真实原响应，并核定该来源自身的合约／符号规则，不能借用截图来源配置。未获供应商符号认证的API亚洲盘原响应留审计并强制隔离；不得据该行生成新可结算合约或纳入相关票面概率／收益比较。手改标签不能解除隔离；独立核定的合法截图合约可用。不影响不依赖该隔离行且资格齐全的模型分布评价。

## 5. 基本面、人员与反证

### 5.1 最小资料与检索停止条件

优先官方赛事／球队资料、原始发布会或可信球队记者，再用有比赛明细与口径的数据源。取得以下内容即可进入判断；继续搜索只用于会改变本场结论的具体缺口，不为凑来源反复搜索。

| 维度 | 必须说明 | 不能替代的内容 |
|---|---|---|
| 实力基础 | 本赛季样本、主客差异、进失球与主要对手；小样本结合上季变化 | 名气、排名或赔率单独不能代表完整实力 |
| 近期变化 | 实际比赛、对手、比分、红牌／轮换／教练变化 | 连胜连败不自动等于状态趋势 |
| 机会来源 | 双方如何创造／阻止机会；同源xG可用则注明范围，无则用射门、禁区机会和战术资料 | 不拼不同供应商xG；不把历史xG等同本场λ |
| 人员 | 已确认缺阵、预计关键位置、可用替代、消息时间与实际来源 | 不要求猜中11人；传言不作为确认缺阵 |
| 赛制与环境 | 两回合／积分目标、休息、旅行、轮换及有据天气场地影响 | 不空泛添加战意或天气加减分 |

近期检索可从近5场开始、必要时扩到10场；这是取材顺序，不是固定最优权重。统计写实际场数、时间范围、对手及90分钟口径。固定当前线回算的历史胜负，不称真实历史盘口穿盘率或ROI；没有历史价格不得编历史收益。

### 5.2 每个关键因素写成一条可审链

`事实及证据 → 对本场的作用机制 → 支持或损害哪张票的哪个赢／走／输区间 → 最强反证 → 当前处理`。

例如“边路替代导致传中防守变弱”必须指出是否增加对手单球机会、是否足以影响深让幅度或总球门槛；仅证明一队有进球机会，不能同时推出它不败、受让全赢和大球。

同一消息的多篇转载按一项事实，避免重复计权。区分历史模型已吸收的长期缺阵与本场新增变化；未训练人员增量时只作定性／条件，不手工修改λ、胜率或EV。

射门量、射正、机会质量和终结分别解释；低射正不能独立证明创造质量差或某次缺阵的因果影响。没有人员来源不能写“全主力健康”。数据冲突依次核同一比赛、主客列、阶段／人数、供应商／定义和修订版本；仍无解则并列原值并限制定量，不挑有利数据拼接。

### 5.3 A01人员分支与关键条件

为确实可能改变判断的人员安排列：当前最有依据安排、关键替代、各分支的事实来源、对具体合约的影响。未知分支权重不默认各半。

- 各合理安排下主要机制仍支持同票／线／适配：记录普通不确定性，可以继续判断。
- 某个现实且可核实的安排会改变具体票、盘口边界、关键支付区间或适配：列为关键条件，写每个结果的动作。
- 只有最乐观且未确认安排支持该票：不能无条件适合。
- 各合理安排均不支持：不建议，不包装成“等首发”。

“关键”不只指胜负方向翻转。主胜倾向不变，但−1.25不再有幅度依据，也属于具体票的关键变化。

### 5.4 证据强度与反证处理

证据充分要求：双方与对手基础有据、当前机制合理、机制直接支持支付门槛、最强反证已处理。一般表示存在不支配结论的明确缺口；薄弱表示核心仅靠名气／盘口／传言或关键逻辑悬空。强度不映射固定概率，不按网站数量打分。

反证必须落入一个实际处理：普通失手路径／支持减弱／改变票或线／等待明确条件／推翻适配。写“有爆冷风险”而无机制和处理不算完成。优先检查最相关的1—2个现实分支，有更多实质风险则继续披露，不机械列极端情景大全。

参数误差、当前未决阵容分支、未来红牌／先丢球路径分开，不重复扣减同一风险。没有估计误差或分支权重时不造95%区间；任意λ±10%只能标假设演练。有限情景最坏值不是收益下界，普通比赛波动不要求每条条件路径EV都为正。

## 6. 模型调用、用途与资料新鲜度

### 6.1 实际调用链

仓库入口为`https://github.com/wuyan0231-hub/football-model`；`main`存代码与说明，`model-state`入口为`runtime/integration/index.json`。以下是读取流程，不保证每个新会话已有授权，也不意味着本版已访问线上。

1. 发现当前可用授权通道，优先已有连接器，读取实际`AGENTS.md`、`docs/model-access.md`及接入说明。一个网页／git通道失败只记录该通道；成功取得所需原件后停止重复探测。不得索取密钥或读受限认证文件。
2. 查目标联赛最近真实运行／失败范围与保存状态。旧索引可能早于最新失败；只有其他联赛失败不自动否决本场。目标或全局失败影响不明时不声称已清除。
3. 固定完整源码提交、模型状态提交；按固定引用取得配置、索引、参数、预测、训练摘要／数据、验证、运行报告和适用场地证据。保存原字节和指纹，不混每日浮动文件。
4. 核现实比赛ID、队伍ID、主客、赛事、场地／国家、中立属性、开球修订、当前状态与模型对象一致。联赛范围按实际配置核；不按旧清单排除新支持赛事，也不默认新球队／球场已合格。
5. 核参数／预测时间、时效、训练截止、文件对应关系、概率合法、矩阵实际维度、尾部处理与当前任务范围。场地专项按实际代码和证据；不能要求新球场必须在历史训练出现，也不能跳过身份／国家等现实资格。
6. 在合法原件上运行实际接入命令，用原函数复算，保存参数、完整分布、命令、起止时间、退出码、真实输出和容差核对。单场复算不等于重新训练，也不自动取得赔率或计算具体票EV。
7. 将模型原件、训练／预测代码身份、此次复核代码身份、状态来源及采用范围写入模型卡。原预测代码与此次复核代码可能不同，分别记录并核相容性。

可用命令范式见第18节。当前调用不使用倒填的历史`--as-of`制造赛前资格；历史复核必须另标历史用途，按当时真实可得原件验收。

### 6.2 逐队核对新鲜度

不能用“当天更新成功”代替资料齐全。核截至截点、本模型赛事与请求赛季范围内，两队应有且已具合格常规赛果的比赛ID；与实际训练集合按模型真实延迟、清洗及截止规则比对。

记录：应有赛程来源、完整性判断、应有ID、实际入模ID、合法排除原因、缺漏／未决、实际训练摘要。空集合或局部缓存不能证明没有遗漏；供方返回齐全不等于官方赛程分母已独立核定。别把模型本来不训练的杯赛当缺漏。

缺漏无法解释或分母完整性未知时，保留可复算的历史／诊断结果，但限制“本场当前数值完整适用”及强价值声明；仍可定性。新事实例如关键伤停若未量化，另列而不假称已入模型。

### 6.3 数字来源与能力范围

| 标签／状态 | 可用范围 |
|---|---|
| `F`非赔率基本面模型 | 赔率未参与输入、先验、监督目标；在实际覆盖任务内预测 |
| `MKT`市场参照 | 去水或报价拟合；不能当独立基本面证据或同价正负价值证明 |
| `MIX`市场参与模型 | 含赔率信息或经验证融合，明确标源 |
| `SCN`假设情景 | 解释敏感性／算术，不能称真实预测 |
| 无适用模型 | 定性判断；概率、EV、数学最低价未量化 |
| 已拟合可复算、验证有限 | 探索性概率／点估计；不能强称优势已确认 |
| 对相关任务样本外验收通过 | 在该联赛、市场、范围、时距和版本的资格内使用；不无限外推 |

直接1X2只能决定胜平负、双重机会及完全由胜／平／负决定的让球线（如0、±0.25、±0.5）；不能唯一确定深盘、总球或比分。单独总球模型不能推出主客胜。完整比分矩阵能计算三市场，但“能算”不等于深让或总球尾部已验证。

固定表述：`历史攻防等已量化范围；人员／战术等仅定性范围；模型成熟度；本场实际调用状态；可量化市场；未知字段`。不得把模型λ称为已观测射门xG；不得把最可能单个比分当胜平负总概率，也不按列出的情景条数估计概率。

### 6.4 正负价值使用同一资格

在第一次查看本次模型输出之前，冻结其用途为“诊断参考”或“价值评价”，绑定模型设置与依据；事后才声明的用途不取得事前资格。已声明诊断用途的同版输出不能升级为强正／强负价值结论；新用途需另存版本并保留已经见过输出的事实，不能重置最早接触时间。正负强声明均需本场合约／价对应的已验任务范围、真实复算、验证及不确定性证据。

只有正／负点估计而误差或任务资格不足：保留数值，判“模型优势不清”。有合格不利结果不能隐藏、删除引用或临时改成定性来维持适合；同样不能凭很小正EV宣称确认优势。无模型、未知EV、市场同价去水负EV均不自动否决。

### 6.5 F5-C单场对照必须核查

每场分析均检查本场F5-C查询条件；调用生产模型时同步查询已保存的F5-C工程候选，生产原件或授权通道不可用时也记录读取受阻／未执行及原因，不省略此项。这项读取不等于重新训练或在两个GPT上下文独立判断。固定同一`model-state`提交，读取`runtime/integration/f5c-index.json`（旧状态缺索引时扫描真实候选原件）、本场receipt、payload、生产父预测、四类生产父来源、协议、共同输入、冻结选择池、适用赛程／场地来源及已有评分／独立结果原件。归档对象按同一完整压缩清单逐项定位并核哈希恢复，不能因没有inline文件而判未执行。

接入后分别验证唯一比赛身份、真实取得／写入顺序、同一生产run及完整原预测行、α=0与原生产预测逐值一致、其余四档复算、选择池及已有评分。只按队名、比赛ID或相近λ匹配不合格。当前生产父预测已变化时，旧候选只列历史原件，不套到本次基线；晚于截点的候选不得回填。

读取／配对状态与评分状态分别登记，保留程序实际字段、原因和查核范围；程序没有输出某状态时不替它造成功回执。

| 读取／配对情况 | 报告处理 |
|---|---|
| `verified_same_parent`：已核同父 | 展示生产基线与实际选中F5-C及差异；列五档、选中α、成熟唯一样本数、冷启动原因和原件引用 |
| `verified_saved_original_audit`：已核历史原件 | 只用于对应旧父预测的历史附录；不认证与当前基线配对或原聊天当时已读取 |
| `not_captured`：所查固定状态内没有对应已存记录 | 写“本次所查范围未找到对应原件”及状态提交、查询时间与范围；不推断后台从未执行 |
| 父预测失配、身份冲突或候选晚于截点 | 保留原件及具体拒绝原因，另列历史用途或排除；不能只凭比赛ID拼为同父配对 |
| `rejected`、原件缺失、读取或复算失败 | 记录真实报错、受影响原件及已完成范围；不能写成未捕获，也不能写对照通过 |
| 本次未运行读取入口／无法取得状态 | 写未执行或读取受阻及原因；不能填“无记录”“已通过” |

α=0另列为回退／选参结果，不是读取失败；按冻结规则核其为何取0及与父预测是否一致。顶层`verified_same_parent`／`verified_saved_original_audit`表示预测原件已按相应用途核验，不表示评分也已通过。评分保留独立`score.status`、`reason`、`score_id`和原件引用，按下表报告：

| `score.status` | 含义与处理 |
|---|---|
| `pending` | 待独立赛果／待评分／评分原件晚于允许截点等，必须按实际原因辨明；不能由pending单独推断缺赛果或填0收益 |
| `read_failed` | 评分原件读取失败；保留具体报错、已取得原字节和缺件范围，不使用该评分 |
| `rejected` | 已存评分尝试被拒绝，或评分身份、引用、算术／原件校验未通过；保留拒绝原因，不能当已核成功 |
| `scored` | 对应独立结果与已存评分原件核验、复算通过后，展示预定指标和真实评分版本 |
| `not_primary_evaluation_version` | 冻结首配对政策采用另一保存版本；不把本版本强行换入主要评价，不改原样本政策 |

最近capture／score尝试、最近已核成功记录和失败原因分别显示；评分失败不抹去已经核实的赛前预测，也不能用旧成功报告冒称最新任务成功。损坏或错配评分不参与比较。已取得但未通过评分验证的实际原字节以`diagnostic_evidence`留存，ZIP按真实导出路径列为diagnostics，与已核原件分开；逐件保存原长度和SHA-256，标明`raw_only_score_not_verified`。诊断字节可回读只证明保存一致，不证明评分有效；不得把它们写进已核通过证据集合。

报告固定列“180天生产基线／实际选中F5-C／差异”对照表，至少包括父run／model／预测原件ID、两侧生成与读取时间、λ及1X2；总球均值、相关事件概率、五态／EV仅在实际分布、同一合法合约／报价及各自用途资格齐备时计算。五档结果保存在附表，选择力度、成熟唯一样本数、回退原因、原件路径／hash及评分状态不可遗漏。F5-C仍为描述性影子候选，对照数值不暗中替代正式概率或改变正式推荐。缺少合法对照时，保留同一栏目并写原因；合格基线分析继续。五档是一场的候选网格，不能计为五场。

本地赛前receipt、远端持久保存、工程先导、正式确认、候选已改善分别登记。读取器不能单凭receipt内`pending_state_commit_verification`或本地写入时间认证远端赛前保存；另核首个成功云端保存与固定提交。α=0时明确候选沿用生产预测，固定非零档仅作预声明探索，不能据单场或网格择优宣称哪个好。

本轮影子记录工程资格，正式确认尚未激活；β、学习样本、成熟数量或验证成绩不继承F5-C的α、40场门槛或确认资格。没有未来结果时只能证明采集、执行及保存；第16.3的统计门禁另核。

## 7. 三市场公平判断

先在市场内部比较，再跨市场选主方向。七个方向可以用紧凑底稿，不要求七篇长文；每个入选代表必须有自身正面依据。

| 市场 | 固定问题与判断顺序 | 必须保留的反证／替代 |
|---|---|---|
| 胜平负 | 谁更能持续创造并限制机会？优势能否转为胜出？单独检查平局路径，再查客胜／弱侧取胜路径 | 强方攻坚失败、双方低机会、定位球／转换、领先后收缩；主胜概率高不等于该价有价值 |
| 亚洲让球 | 把具体线换成净胜门槛；区分赢球、赢一球、赢两球及反向失手；评弱侧破压／进球／守住差距的路径 | 浅胜能否兑现深盘、落后方追分、领先方降速；不追热门不能成为支持受让的唯一理由 |
| 大小球 | 分别审两队进球供给与限制；查单队多球、双方有球、领先／追分后的节奏；落到总球门槛和走水区间 | “弱方不进球”仍可能被强方多球打穿；“双方会进球”不必超过高线；人员、定位球、赛制、节奏、环境按证据处理 |

对每个代表保存：准确合约／报价、支付要求、支持事实及机制、最强反证与处理、最近替代、不选其余方向的主要理由、概率来源与价格价值。缺某市场可核条件时明确不作主选，不用其他市场的模型强行填它。

例如大2.75须分别判断总球≤2、=3、≥4的支付，不能用“预计2—3球”代替；总球均值本身不能唯一给盘口概率。显示比分时从完整分布排序并注明覆盖，只列支持方向须称条件情景，不隐藏概率靠前的不利比分。

变盘重新检查四件事：观察到的线／价变化；原因是否有新事实证实；临界比分支付如何改变；新线新价下结论是否仍成立。不能把多家公司同向变价自动解释为独立基本面证据。

## 8. 合约、五态、概率与EV

### 8.1 先核合约再计算

每票固定`比赛＋市场＋所选方向＋所选队线位／总球线＋结算范围＋滚球起点（适用时）＋报价ID／制式／价格＋规则与费用`。普通1X2选中对应范围的胜／平／负结果则全赢，否则全输；竞彩三项让球胜平负独立处理，不能套亚洲盘。半场／半全场需相应阶段分布；晋级、加时、角球、牌数和球员市场不得由常规全场进球模型替代。用户限定某市场时按限定范围，不冒称完成全三市场。

标准亚洲让球：令所选队对应范围净胜球为`d`，判断`d+h`的正、零、负。大小球：大球判断`g−L`，小球判断`L−g`，正为赢、零为走、负为输。四分之一盘拆为相邻两个半球步长线，各投入一半，例如−0.75拆−0.5和−1，2.75拆2.5和3。

| 五态 | 每1单位本金、标准十进制赔率O、未扣额外费用的净收益 |
|---|---|
| 全赢 FW | O−1 |
| 半赢 HW | (O−1)/2 |
| 走水 P | 0 |
| 半输 HL | −0.5 |
| 全输 FL | −1 |

四分之一线两半注分别核，再组合；同一四分之一合约两半使用该票相同价格，分别买两张不同价格的票则分别计算。标准无额外费用时，一半赢一半走为半赢，一半输一半走为半输。特殊返还、税、佣金、作废及延期规则按真实条款另算。

最低边界对照：所选队赢1球时，−0.75半赢、−1走水、−1.25半输；所选队输1球时，＋0.75半输、＋1走水、＋1.25半赢。总球为3时，小2.75半输、小3走水、小3.25半赢；大2.75半赢、大3走水、大3.25半输。这些是支付算术示例，不是本场预测或固定推荐。

### 8.2 概率与价格计算

实际比分矩阵逐比分映射同一合约，汇总五态并核和为1及截断／归一化处理。不能用展示时四舍五入的几个比分代替完整分布。

- 盈利概率：`P(R>0)`；不亏概率：`P(R≥0)`；亏损概率：`P(R<0)`。费用会改变净收益符号时按实际逐状态净收益判断。
- 一般净EV：`Σ p状态 × R状态`。
- 标准五态且每单位固定费用k：令`A=p_FW+p_HW/2`、`L=p_FL+p_HL/2`，则`EV=(O−1)A−L−k`。
- A>0时保本价`O_BE=1+(L+k)/A`；目标净收益g对应价`O_g=1+(L+k+g)/A`。A=0时不能除零，应逐状态判断是否存在有限达标价。
- 只有无走水／半结算的二元标准合约才可用`pO−1`；不能给亚洲盘通用套此简式。赔率抽水已体现在支付中，不重复扣除。

真实费用未知时，实际费用后净EV仍未知；可以另列“额外费用假设为0”的参考纸面**费用前单位净收益／费用前EV**（已扣本金），不能冒称实际费用为0。无适用概率不得生成数学最低买价。确需价格阈值时，绑定概率、费用、目标与情景，按平台合法价位向上取整并逐情景回代；没有默认＋2%或＋5%门槛。

### 8.3 计算复核

保存输入、实际运行代码与版本、输出、容差和人工临界比分对照。最低检查：主／客符号一致；四分之一拆注正确；总球阈值事件包含关系正确；同范围主胜与主队−0.5事件一致；矩阵合法；换线／换价重新计算。

市场1X2比例去水仅在同平台同状态完整三项上作`q_i=(1/O_i)/Σ(1/O_j)`，标市场参照；同价回代的负EV是构造结果，不能据此认定真实负价值。带走水／半结算的两项价格不能唯一还原五态。

## 9. 唯一主方向、正式适配与影子等级

### 9.1 主方向选择

比较顺序：机制与合约支付门槛匹配→关键假设依赖→盈利／亏损结构和失手路径→可比价格与有据EV。不是机械加权总分，不预设受让、小球或低赔率优先。

每场给一个相对主方向，并指出最接近替代及不选理由。依据弱可写“弱倾向”，不强造适合；身份未核或完全无可判断对象时不硬给方向。更高EV但更易失手的替代可以保留，不能同时给两个主推。

### 9.2 四态判定树

对每个候选的**单关和串关腿分别**按下列次序判定：

1. 身份、合约、必要实时状态或核心资料无法确认，且不能形成有依据的可操作分支：**暂无法判断**。
2. 已核事实足以判断，主要机制被推翻、支持薄弱／深盘无幅度依据，或符合第6.4节的模型证据显示当前价明确不利：**不建议**。未决事实不能先当已证实利空。
3. 主体依据成立，只有少数现实且可核的关键条件决定该具体票是否成立，且至少一个合理分支确有支持：**条件适合**。所有合理分支均不支持则回第2项。
4. 机制支持具体支付门槛、主要反证已处理、报价能对应本票，且无上述阻断或关键等待：**适合**，同时注明定性／量化依据和价值状态。

“适合＋EV未量化”必须写支持机制、赢走输要求、机制为何支持要求、最强反证为何未推翻和报价性质；不能以“没发现利空”代替。首发未出、没有xG、没有其他串关腿或没有订单不自动形成关键条件。

已被更新取代、已知状态不适用或纯假设的报价，只能作历史／条件分析，不支持当前票无条件适合；已核清最新公开参考不因缺账户开放或成交证明受此限制。

### 9.3 条件与重评提醒

条件记录：`condition_id、可观察事实／阈值、证据来源、适用票、检查期限／状态、满足动作、不满足动作、未知动作`。

| 条件状态 | 动作 |
|---|---|
| 已满足 | 保存事前证据与确认时间；重核当时合约／价及适配，生成新决定版本；不自动视为已买 |
| 已证实不满足 | 按预定分支撤回／换票／不建议，保留原条件票 |
| 未知／未取得 | 不纳入已确认条件策略；原方向观察可保留，不能记收益0或假定未触发 |

“出现红牌、改期或重大伤退需重评”是未来更新提醒；只有当前确实等待、会改变此票判断的未决事实才是入场条件。未知不是不利事实。没有可核条件的笼统不确定性，按证据弱或对象不明分别判，不用“条件适合”兜底。

### 9.4 主卡并列的五栏

`正式适配｜证据强度｜报价比较｜模型价格价值｜影子等级及用途`。

价格价值使用：模型支持正向价值／模型优势不清／模型显示不利／未量化。强正负须符合第6.4节；点估计正负如实显示，不伪装为确认。报价比较另记相对较好／相对较差／同状态差异不明／无可比价；相对较差不自动等于负EV。

### 9.5 影子分级的明确用途

先完成正式四态，再独立记录试行等级、证据和实际行动。等级用于检验区分度，不能反向制造概率、条件或适配。

| 等级／状态 | 可检查条件 | 当前用途 |
|---|---|---|
| A | 合约、支持链、边界支付、最强反证、最近替代均完整；主要现实普通分支仍支持所声明用途；脆弱假设已披露 | 强候选影子记录；可有据定性，仍不代表正EV或固定高命中 |
| B | 决定链完整且该用途有据，存在清楚、已处理但使优先级低于A的弱点 | 普通候选影子记录，不省略风险 |
| C | 当前以观察为主；必须区分`evidence_gap`证据链未完与`purpose_mismatch`不符合当前用途 | 前者未知，后者可为明确弃权；不能统一填0收益 |
| D | 已有依据支持不建议该用途 | 明确不建议；未选为主票本身不足以判D |
| U | 必要对象／证据无法确认 | 无法分级，保留缺口 |
| 等待关键条件 | 正式为条件适合，条件尚未确认 | `grade=null`，另记`awaiting_condition`，不硬塞C |

单关与串腿分别说明目标、普通失手风险和证据；不得一律把串腿降一级。A/B可以继续只观察；真正纳入哪类行动由试验预先规定。已有资格的明确不利价值不能通过高等级绕过。

价值目标下高价A的原始命中率可能低于低价B；评等级必须分别检查其声明目标、覆盖、价格和收益，不能仅按胜率排序认定好坏。完整串关另需实际各腿、联合支付、相关性、报价和投入，未知时不相乘单腿概率假称已验整串。

用户确需整串时，按平台条款核返还。标准拆注乘积且无额外费用时，单腿返还倍率为全赢O、半赢(O＋1)/2、走水1、半输0.5、全输0，整票单位净收益为各腿返还倍率乘积减1。例如半输腿配一腿1.80全赢，整票仍亏10%。这只是支付算法，预期收益仍需联合分布或有据依赖分析；特殊组合、作废与费用按条款另算。

|---|---|---|
| G1 对象与政策 | 身份、范围、模式、实际规则、试验登记及独立性 | 阻断对应对象／实验，不冒称登记完成 |
| G2 资料与模型 | 来源、真实截点、两队新鲜度、模型资格、失败范围、原件和实际复算 | 局部数值回退；实验资格按预定规则记失败 |
| G3 报价与合约 | 所用《赔率截图读取规范》的身份、执行结果与复核证据；下游合约／价格／状态、用途及准入隔离 | 按所用规范修错或停用受影响报价；不能绕过未解决缺口 |
| G4 判断与语义 | 自身支持、支付匹配、最强反证、最近替代、条件、正负模型对称、全部候选一致 | 修正有据错误；不能靠字段非空宣称足球逻辑正确 |
| G5 保存与完成度 | 原件和首输出保留、清单哈希、真实回读、保存事件、当前容量、历史追加 | 明示未存范围；不能把本地通过写成长期远端通过 |

这些是本版人工＋工程验收分组。现有`pretest`只覆盖其实际文档声明的检查，不因本版有五门就宣称全部已自动化。流程／对照模式需冻结、语义复核、统一输出与保存通过；普通分析可披露局部回退，但硬矛盾仍先修正。

### 10.2 日常报告固定顺序

1. **结论卡：**比赛与截点；唯一主票的准确合约／价／用途；单关和串腿四态；证据强度；报价比较；价格价值；概率与EV的实际能力；关键条件。
2. **三市场比较：**各代表、自身支持、最大反证与处理、最近替代／不选理由。主票和所有明确备选的适配不得漏掉。
3. **基本面与人员：**实力、变化、双方机会机制、关键替代；模型已量化与仅定性内容分开。
4. **模型与计算：**真实读取／复算或失败范围、来源提交、数据时点、矩阵及任务边界；按6.5展示本场F5-C对照或缺失／拒绝原因；已登记的特征研究按6.6展示候选卡、贡献与分歧，不隐去未运行或回退。五态、概率和EV仅有据才列。
5. **有效期与更新：**真正关键条件、满足／不满足／未知动作，以及另列的重评提醒。
6. **证据与交付：**纳入本次所用《赔率截图读取规范》要求的报价摘要、重要缺口与读取完成度，证据可定位。再列实际规范身份、来源、实际读到／未取得范围、输入／决定／保存时间、文件入口与完成度。

正文可简洁，底稿不可缺。采用统一决定对象生成主卡、正文关键结论、全部候选清单、适合集和评分视图；旧schema不能被无版本扩展拒绝。工具存在但本次未运行，写“未运行”；手工整理须逐字段与原文核对并保留范围，不能冒称正式入口验收。

完整原文保留原因、语气和限定词，不能只保存主卡。主票、市场代表、明确备选、比较报价和纯历史行各有角色；没有选为主票不能被机器统一成“不建议”。

## 11. 临场、滚球与版本追加

### 11.1 新版本的触发

新赔率、首发关键变化、重要伤停、改期／场地变化、红牌／比分状态变化或已确认错误，若影响具体票或判断则生成r2/r3。保存：父版本、真实新增事实及取得时间、受影响机制／支付、旧结论、新结论、重算、适配和条件。未重核的部分注明沿用范围。

普通提醒没有发生时不自动撤销原适合。条件满足须重新核价与生成决定，不自动表示执行；实际买入／未买／未知以独立事件保存。除非真实自动任务已建立并运行，不承诺无人发消息时自动更新。

### 11.2 滚球独立状态

先锁分钟／补时、比分、红牌、人数、在场关键人员与换人、VAR是否未决、近期机会、半场／剩余范围、参考起点及报价状态，并记观察时间，才作判断；实际成交另存真实接受起点，不能把截图时刻当成已接受。参考起点标`reference_only`，有真实接受证据才记`accepted`；接受时间／比分未知保持空。VAR／比分状态未决时限制相关实时合约，核定后追加版本。同比分不保证同状态，同分钟换人与截点顺序未知保持未知。赛前模型不冒充实时模型；缺适用实时分布时定性分析，数值概率／EV保持未知。赛前λ按余时比例缩放只能称假设基线。

滚球合约的读取口径、结算范围与起点承接本次冻结《赔率截图读取规范》及实际合约核定结果，再匹配对应范围的模型分布和支付计算；参考起点不冒充真实接受起点。原来已买票保留原起点，不随更新重置。真实平台条款与默认口径不同，须记录差异并按已核实际合约处理，不能以项目约定覆盖票据。

大小球另核全场总球还是剩余总球；全场线须计入已进球，不能照搬剩余让球规则。比分／红牌与报价不是同一状态时不得拼成一票。中场／全场统计不能替代原命题对应的分钟窗，赛中才出现的事实不能回填为原赛前依据。

## 12. 标准赛后复盘

用户要求“搜索赛果、反思、找优化空间”时，默认执行本节并合并实际取得的赛前、更新、滚球和复盘原文；只问比分或明确限制范围时从其要求。

### 12.1 先结算再归因

1. 核当前未赛／进行中／完赛／延期／中止，以及可核常规时间结果。官方原页优先，不可得时用可信交叉来源并注明级别；最终含加时比分没有90分钟拆分时不能猜。保存结果原件、取得与保存时间、版本和修订父链。
2. 锁实际原文、合约、报价性质、适配、条件、语气和时点。原文缺失只做可证范围，不能凭记忆恢复推荐。无原图仅能核文字转录，不能宣称回图正确。
3. 对原主票、市场代表／明确备选、实际参与原比较的票分别独立结算；赛后新增比较票另列探索。纯截图历史行不自动算推荐。四分之一拆注和滚球起点重新核算。
4. 参考价纸面、条件触发价、实际成交价分别计算。缺价可报五态，收益未知；确认已买可来自用户明确说明，缺金额不等于未买，但限制金额盈亏和总体实盘ROI。
5. 回到原条件核满足／不满足／未知及当时有效价；未取得不能当未触发或零收益。实际执行状态另存。
6. 逐条检验原机制：保留原句、限定词、作用时段；用匹配的过程证据判实现／未实现／未知。输赢、赛后总xG或单次失误不能独立证明因果与概率错误。
7. 按12.3先核已有规则的实际执行，再判问题类别，追加更正／候选和台账，生成累计包；原预测与失败不清洗。
8. 本场F5-C按6.5核已有独立赛果与评分原件，再报告基线／所选候选的预定指标。缺失或失败保留原因，不由本次用户比分补造“后台已完成”；本次另作的合法补算标为追加历史核算，不替换原评分或追认正式样本。

### 12.2 复盘固定栏目

`结果与完成度 → 原报告／版本与重要对话补充 → 原票逐项结算 → 条件／执行及分组 → 原机制过程核验 → 问题与纠错 → 改进候选／验证计划 → 材料与台账接续`。

结算完成、机制已证、实际执行已证和归档完成分别报告；可以出现结算完成而机制／实盘未知。重要用户纠正、盘口约定、条件变化和买入信息保留可见原文及消息定位，未知发表时间不补造。

### 12.3 问题分类及动作

审计默认先检查“当时适用规则是否已有要求、报告和真实日志是否实际执行”，再按下表判硬错误、规则遗漏／歧义、已定位模型／工程问题、待验证假设或证据不足。每项回到原文与当时规则，明确改动对象：已有要求却漏做，优先修执行与校验；正确执行仍无处理或要求含糊，再修规则；数据／代码／接口失败需可复现定位，预测方法增益另作第16节验证。用户明确指定的专项核查按实际范围先核，但仍保留已有规则是否执行这一诊断。

这一顺序不能用来推迟已证硬错误的更正，也不把所有问题归为执行者失误。同一步反复遗漏时，同时检查规则可执行性、字段／例子、工作量、工具接口与自动校验；同一问题可以关联执行与规则／工程根因，说明各自证据。资料不足时保留未知，不凭单场输赢认定模型有错，不因重复遗漏就重复堆叠同义条文。

| 类别 | 判定证据 | 动作 |
|---|---|---|
| 已有规则未执行 | 当时规则已经要求，原报告／日志显示漏做 | 修执行与校验，不重复发明同一规则 |
| 硬错误 | 身份、事实、时间、读图、符号、计算有直接反证 | 立即追加更正、复验受影响输出，原件保留 |
| 规则遗漏／歧义 | 正确执行现条文仍无明确处理 | 提出精确条文、适用条件与反例验收 |
| 已定位模型／工程问题 | 数据、代码、接口或计算链的可复现失败 | 登记独立修复任务；日常复盘不自动改生产 |
| 待验证假设 | 新方向、权重、选票／分级／筛选方法仅有开发线索 | 记录候选，未来同范围同截点验证 |
| 证据不足 | 原文、过程、交易或时点缺失，不能确定 | 保留未知和最小补件，不作强归因 |

每项都有：原文／文件精确定位、当时适用规则、本版条款、改动对象、证据状态、影响、动作、验收条件、状态。状态分别用“已写入／已实现／已部署／工程已验／真实流程已验／效果待验／效果已验／未采纳”；不能用一个“完成”覆盖全部层次。确无新改动可写“暂无新增”，不强凑优化。

### 13.3 保存验收

逐项检查文件存在、能打开、hash匹配、引用定位有效、HTML与机器决定一致、版本链完整、原件未改、ZIP可解压。首次失败和修复后回执均保留。外部保存后检查返回状态；有条件则从保存端回读校验，做不到时明确仅收到上传回执。

本地成功、一次上传成功、当前容量充足、整个长期周期可保存是四件不同的事。本修订读取的源码中，`storage_policy.py`设为1 GiB物理、4 GiB逻辑、800 MiB影子新增写入预算及256 KiB有界诊断预留，单件上限仍60 MiB；诊断也受完整状态硬上限约束，旧500 MiB／2 GiB清单继续验读。每次以实际固定源码及运行记录确认生效值、已用字节与剩余额度，源码数值不能代替真实部署／保存回读。阈值是项目代码的显式保护值，不是已核实的平台套餐额度。长期试验仍需部署归档与按需恢复、真实增速观察及完整周期预算；不能用离线压缩原型证明已上线长期保存。失去容量时追加延期／失败，不静默删旧预测。

## 14. 四类统计集合与指标口径

### 14.1 分组不改原判断

| 集合 | 收录依据 | 评价边界 |
|---|---|---|
| 原方向观察 | 事前固定的主版本原方向，含不建议／条件未知 | 判断与遗漏机会；不全叫推荐策略 |
| 无条件适合 | 原记录对应用途明确适合 | 该筛选政策表现，保留全请求覆盖率 |
| 条件已确认 | 有入场前／赛前满足证据、有效触发价及重评 | 条件策略；缺触发证据不纳入 |
| 实际执行 | 用户明确确认本场已买及可核字段 | 依据价、金额、费用完整程度分层计算 |

四组可以重叠，利润不能相加重复计算。同比赛多版本、多个盘口、多公司同支付报价不是多场独立样本。主观察版本预先固定：普通归档默认首次完整发布报告；发表证据未知时，仅按首份已保存的完整决定建立归档索引，发表及其资格继续未知。首输出实验连最早失败也保留，不能拿后来的完整报告替换首失败。

### 14.2 不混用的指标

- 方向正确、全赢、半赢、走水、净盈利、不亏分别报告。盈利命中率＝净盈利票数／全部有效已结算票数。标准无额外费用时半赢算盈利一次，半输算亏损一次；走水进入有效结算票分母并单列。另报去走水命中率须另命名。
- 概率质量用同事件的Brier／Log loss、校准等，必须是当时实际保存的概率。新旧选了不同票，不能拿不同事件的五态分数直接比较“谁更准”。共同模型的1X2相同也不能被宣传为框架增益。
- 参考纸面、开放模拟、真实成交各自计算。净收益合计／有效投入合计才是对应ROI；真实金额未知不能报告金额盈亏、真实回撤或总体实盘ROI。
- 单关和整串分别统计；没有联合预测／整票证据不得相乘概率或累加腿利润冒称整串收益。
- 覆盖率同时报分子、全请求分母、独立比赛数。多候选票数／场数可超过1，必须另命名“每场候选数”；若称比赛覆盖率，分子用至少一票符合条件的唯一比赛数。
- 未知、失败、条件未决、缺赛果不是零收益。仅在事前明确的纸面策略中，对有完整评分资格的机会真实主动弃权，才可按协议记零敞口；实盘未执行未知不得如此处理。
- CLV仅在同事件、同线、相同条款、预定收盘时点和可比费用下比较；变线不能直接比赔率比值，CLV也不独立证明盈利。
