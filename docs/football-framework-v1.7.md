## 一、对象、术语与不会混用的指标

### 1.1 本次到底分析什么

开始时确认球队、赛事、比赛日期与开球时间/时区、主客及中立场、赛前/滚球。默认常规时间为90分钟加补时；晋级、加时、点球大战、半场、竞彩三项让球和特殊合约单独核对。用户只给队名时，先自行查找对应赛程；仍存在多个无法区分的比赛时，才问一个必要问题，不自行选一场。

每项推荐对象是“比赛＋市场＋所选方向＋准确盘口＋结算范围＋报价/时点”，不能只写“支持强队”“看好大球”。资金管理由用户负责，本文件默认用1单位本金描述收益，不自动给仓位或拼3—5串。

### 1.2 常用词的白话定义

| 用语 | 本框架含义 |
|---|---|
| 1X2／胜平负 | 1主胜、X平局、2客胜；全场结算范围须核对 |
| 亚洲让球 | 所选队净胜球加所选让球数，再判赢、走、输；负号让出，正号受让 |
| 大小球 | 两队总进球相对指定门槛的结果；大2.5与大3.0不是同一张票 |
| xG／npxG | 射门机会的进球概率估计及按供应商口径排除点球的指标；历史指标不是下场赛果 |
| 联合比分分布 | 给每个主客比分分配概率，可汇总胜平负、净胜球和总球 |
| 预计首发 | 有来源与时间的人员推测，不是已发布名单 |
| 相对主方向 | 本场三市场比较后唯一较倾向的一项；可以是弱倾向，不自动等于推荐入串 |
| 串关适配 | 该具体方向作为候选腿的判断；不证明未知整张串单正EV |
| 证据充分 | 主要判断环节有事实支撑且重要反证已处理；不是某个胜率百分比 |
| 未量化 | 没有适用数值依据，既不是0，也不是正值或负值 |

### 1.3 命中与收益的固定口径

令R为对应合约每1单位本金、按实际条款及已知费用计算的净收益。

| 指标 | 固定定义 |
|---|---|
| 赛前盈利概率 | P(R>0)，有模型依据才报数值 |
| 赛前不亏概率 | P(R≥0)，包括零收益但不能称盈利 |
| 赛前亏损概率 | P(R<0)，包括半输，另列亏损幅度 |
| 历史盈利命中率 | 净盈利票数／全部有效已结算票数 |
| 净期望收益EV | E[R]，不是保证收益 |
| 实际ROI | 总净收益／总有效投入本金，不是各票ROI的简单平均 |

标准无额外费用下，半赢算一次盈利、半输算一次亏损，走水计入有效已结算票分母并单列；半赢收益较少由EV和ROI体现，不改成“半次命中”。作废、未结算、争议单列。若另报剔除走水后的条件命中率，必须另命名、显示分母，不替换默认指标。

球队获胜、比分猜中、亚洲盘全赢及净盈利是不同事件。未有用户明确本场已买确认时，实际执行保持未知，只能报告原合约的观察结算或明确假设的单位模拟。用户明确已买即可登记执行，订单凭证不是唯一确认方式；完整合约及必要起点支持核结算，真实赔率支持单位本金收益率，真实金额及费用支持金额盈亏和实盘总体ROI。缺哪项只限制哪层，不因缺金额或订单推定未买。单腿与整票分开统计，不重复计收益。概率校准和模型准确性另见第十九节，不能仅用命中率评价模型。

先形成基本面解释再对照市场；若用户截图已展示，记录“已接触赔率”，不要假称盲评。底稿可用简表，无需给七个方向各写长报告；必须足以说明每市场的内部选择、公平取舍与已知缺口。

### 2.2 定性和量化两条完成路径

**定性路径：**事实→对位机制→具体合约所需结果→最强反证及处理→最近替代→主方向和适配。概率、EV、数学最低买价写未量化；市场去水如需展示另标市场参照。无模型仍可有依据地“适合”，按§12说明理由。

**量化路径：**真实参数/预测/验证→核本场适用性与来源→实际复算分布→映射真实合约与价格→五态与EV→结合事实与合理分支判断。只有直接1X2时不造总球或深盘分布；只有总球模型时不造主胜概率。可量化与定性市场并列，说明覆盖。

每次均说明“哪些基本面已进入模型、哪些只作定性或未加权情景”。没有训练和合格系数时不手工增减λ、胜率或EV。单场分析无需临时训练；工程建设另走§20。

### 2.3 真实模型接入的固定动作

0. **发现授权读取通道。**先发现本会话已有的GitHub连接器，优先通过它读取仓库`docs/model-access.md`并执行其步骤；普通网页`DisabledError`或终端git错误只记录对应通道。成功后不必反复测试其他通道；全部适用授权路径不可用/失败后才归因为本会话读取受阻，不据此判定未训练或赛事未覆盖。详细错误分类与获取记录见§25.7。
1. **核当前对象。**模型比赛ID、联赛、主客、场地、开球时间与已核现实比赛一致。当前赛前、滚球、完赛分开；历史赛前产物不能作实时预测。市场队名与官方青年队名可能是别名，按真实队伍ID和赛事核对。
2. **固定代码与状态。**实际取得项目执行说明、配置、索引及真实源码提交、`model-state`提交。之后优先用连接器完整`fetch_file`响应按固定SHA取原件；所有参数、预测、验证、运行报告及预测引用的场地快照从同一固定状态版本读取，源码/配置从固定源码版本读取，不混用每日浮动分支文件。落地工具与依赖清单见`docs/model-access.md`；只取得文件不等于完成模型调用或复算。
3. **先查失败范围。**目标联赛最近失败、聚合索引失败、过期、参数与预测不对应等按实际接入门禁处理。仅其他联赛失败不自动封禁本联赛。索引写入前失败需另查对应运行记录；旧索引不能证明最新任务成功。
4. **绑定原字节。**模型/预测/验证/索引记录固定路径和原字节摘要；能核Git blob时一并核对。下载后转换或重序列化另存派生文件、父指纹与转换说明。哈希匹配只证明对象对应，不证明模型有效；不匹配先检查文件绑定，不猜原因。
5. **适用时运行并保留输出。**已确认当前任务不在模型覆盖内时，记录资格依据并转定性，不为形式完整运行已知不适用命令。适用时使用实际代码支持的`integration match`或经核实的当前入口，命令范式见§20.12。保存真实命令、分析截点、退出状态、错误或输出，以及本场数值复算。不手填“已调用”或伪造路径。
6. **明确采用范围。**记录F/MIX来源、成熟度、本场适用任务、预测矩阵真实维度、尾部和验证边界。采用资格与模型正负EV分开评价，不能看到正值称可信、负值才称模型弱；若改变采用判断，给独立于该正负号的证据，并保留旧结果。
7. **另算真实盘口。**接入命令不抓赔率、不自动计算所有三市场EV。实际取得分布后，使用本场已核价、线、范围和§22算术进行映射；缺价或缺分布限制对应数字。

显式复用只允许通过当次资格核验且仍有效的产物。记录“复用哪天哪份、为什么仍适用”；没有强制绕过失败门禁的默认路径。相关失败未修复时继续定性分析，不把旧成功包悄悄当当前成功。

遇到无法访问、代码缺失或模型不覆盖，分别记录实际尝试和返回原因；先依§20.12检查可用授权通道，不能把单一网页/git错误概括为全会话认证失败。不得要求用户每场重新上传模型，也不为消除一个数值缺口无限重试。发现属于新球队/赛事映射、场地资格或数据拒绝问题时，进入§24.2工程登记；本场按实际可得信息完成。

### 2.4 四种任务的结束条件

- **新分析：**对象已核或明确限制；适用市场完成判断；一个主方向及适配；条件可执行；引用和报价可追溯；§21已检查；原报告保存或留存范围说明完成。
- **更新：**记录新状态→新事实→受影响机制→新合约/价→新适配；原版本保留。更新未涉及的结论也不能假称重新核完。
- **复盘：**按§18核结果、原票及原命题，并完成§18.8固定栏目、§25审计增量与实际交付检查；未取得的机制/执行证据写未知，结算、机制、执行和归档完成状态分别报告。
- **异常：**只限制受影响的对象或数值范围；用户要求不可读即停的材料缺失按要求停止。结束时说明具体缺口及所需最小补件，不以“继续”代替缺失事实。

## 三、公开资料、最小数据包与缺口处理

### 3.1 默认公开检索次序

1. 赛事/俱乐部官方赛程、比赛页和规则：确认身份、日期、场地、赛制。
2. 官方伤停/停赛、发布会、名单及可信的球队记者报道：确定已知人员与预计变化。
3. 有比赛明细、口径说明的数据来源：取得成绩、主客场、对手、进失球与可得机会数据。
4. 用户指定平台或可核实报价来源：获取准确合约、线位、赔率、更新时间和开售情况。
5. 只对会影响本场判断的冲突再定向核查，不为了凑资料量重复搜同一新闻。

优先读原始内容而非搜索摘要；摘要只能提供线索。访问失败、收费数据或没有API时换可公开核实来源，不声称访问了实际未读内容。完成基本包且关键冲突已解决或已形成明确分支时即可分析；继续检索只用于具体缺口。无法取得重要信息则说明影响，不无限搜索，也不默认让用户提供全部资料。

### 3.2 每场最小资料包

| 项目 | 最小内容 | 缺失影响 |
|---|---|---|
| 比赛 | 赛事、主客、日期时间/时区、场地与赛制 | 身份不明不能作当前推荐 |
| 实力基础 | 适用赛季的整体表现、进失球、主要对手与主客差异 | 仅有名气/赔率不能称证据充分 |
| 近期变化 | 最近若干实际比赛及对手、比分、红牌/轮换等异常 | 不把无资料写成状态稳定 |
| 机会质量 | 可得同源xG/射门/禁区机会等 | 无xG可用其他事实，不伪称做了xG模型 |
| 阵容 | 已知缺阵、预计关键位置及替代者、消息时间 | 非关键未知保留；关键未知建条件分支 |
| 比赛背景 | 休息、明显轮换、两回合目标及与本场相关环境 | 没有明显证据就不强添“战意/天气分” |
| 报价 | 三市场各自的平台、方向、线位、制式、价格、时点 | 某市场缺价不否定其他可评价市场 |

只获取与本场有关的细节。模型训练需要的完整事件流、多年球员片段、跟踪数据等不属于每场定性分析的必填资料。

### 3.3 样本怎样展示

先看本赛季累计，再用近期比赛识别变化；新赛季样本少时参考上季但指出转会、升级、换帅差异。作为检索起点可先取近5场、必要时扩至10场，并保留主客场子样本；这只是可调整的资料窗口，不是统计最优窗口或固定权重。每个统计写实际场数、时间范围和口径。

对手修正分两种：有模型时使用明确估计的攻防/评级修正；无模型时逐场看对手水平与比赛状态，说明可比性，不能称已经完成数值对手修正。杯赛、加时、红牌后分钟、友谊赛和明显轮换须标记，不任意删除不喜欢的大比分。主客样本很少时不单凭一两场零封推断客场防守能力。近5场、近10场及主客子样本相互重叠，不计作彼此独立的多重证据。

**三种历史盘口统计必须分别命名**

| 统计 | 计算对象与所需资料 | 允许的说法与边界 |
|---|---|---|
| 固定线赛果回算 | 选定同一线位，应用于明确样本中每场常规时间比分；写所选队视角 | 例如“近10场按固定＋1.5回算8次全赢”；不要求历史真的开＋1.5，但不是本场80%概率 |
| 真实市场穿盘记录 | 每场真实盘口、方向、范围、固定取价时点及赛果 | 按当时实际线位列五态；不能用今天线位冒充历史市场 |
| 历史单位模拟收益／实盘ROI | 在前项基础上，增加逐场赔率、费用、取价/入样政策；实盘还需实际执行资料 | 固定单位回算标“模拟”；金额与执行有据才报相应实盘结果 |

三者都报告样本范围、场数和五态或已明确的胜负定义，不含糊使用“赢盘率”。对手、主客、人员和异常赛况的可比性另审；缺历史线位不妨碍固定线回算，但不能因此声称有真实穿盘记录。缺赔率可算结算状态，不能计算ROI。

### 3.4 来源与时间

最小记录“事实或报价是什么、谁发布、何时发布/抓取、指向哪场比赛”。一个事实被多个网站转载不算独立证据；官方资料也要核对日期，旧报道不优于新的可靠更正。遇到冲突，先分清是否指不同时间/不同角色，再查原始声明；仍冲突且影响具体票时用条件分支。

“同一分析截点”指使用截至该时点可得且未被新事实推翻的信息，**不要求所有来源在同一分钟更新**。昨天发布但仍有效的伤停可以与今天报价配合；新首发或重大事件之后的报价，不能与忽略该事件的旧模型假装处于同一状态。

报价时点不同要逐一注明。期间没有已知重要变化时可作有限比较，但不称精确同时价；若发生进球、红牌、正式首发引起的模型输入变化或合约变更，重新对齐。无法确认变化情况时说明查询覆盖，不虚构一律有效几分钟的期限。

### 3.5 截图与价格清洗

先定位比赛行、球队、市场标题、让球符号和行列绑定，再读取赔率。不凭公司排版记忆猜主客，不因低赔率把一边判为强队。截图平台顺序和北京时间等沿用用户当次明确说明；未说明而影响识别的字段先查证。

统一记录原赔率制式；本文O为含本金十进制赔率。已确认香港盘净赔率h时O=1+h；其他制式按对应已核实规则转换，不将负水直接当十进制数。不得把不同平台三项最高价拼成一家机构的去水概率，或把单关最佳价拼成真实串价。

报价角色与价格性质分开：角色为顶部最新状态、最近有价、其他历史及本次采用；性质为当前另有开放证据、最新公开参考、历史记录、已知不适用或假设。历史记录不必然过期，时间较早也不单独证明失效。页面链接不单独证明历史报价；尽可能保存截图、页面片段或响应内容及定位。哈希仅帮助识别记录，不能证明报价真实或账户可成交。

**有图时的可执行读取与证据记录**

1. 每图的AH、OU、1X2独立编号，内部读取所有完整可见行；三表同一高度不等于同一时间，裁切残行不拼接。
2. 每表分别确定“截图内最新状态”和“最近有价历史”。最新为封盘时保留封盘，不能用下一行旧数字覆盖；截图内有价也不等于现在仍可买。
3. 原字符、让受方向、赔率制式与标准值并存。已经转成1.88的十进制价不再加1；数值异常只触发回图/制式核查，不能用“合理价”猜回原字。
4. 实际用于候选比较、去水、拟合或EV的每条报价，都反向核对图号、市场、行号、本行时间、盘口、两侧/三项价格及状态。原图不可得时只能核文字内部一致性，不声称完成第二遍回图。
5. 把“看得清、盘口已识别、时间仍有效、页面可见开售、实际接受成交”分成独立字段；任何一项都不替代其余项。用户已说明公司顺序、时区等，无冲突时沿用，不重复询问。

合约、方向、制式和相关状态可识别的最新完整有价行，可作为公开参考用于候选比较和推荐；无需账户截图或接受订单。最新有价若就是顶部行，不降格为只能历史研究。当前开放与实际成交另按证据记录，已知封盘/新事件冲突/关键字段缺损时才限制对应对象。

紧凑表使用§16.1格式。完整观察所有可见历史；底稿最低完整转录每表最新状态、实际采用/比较/计算及支持重要变化或纠错的行，研究某段走势时保留支撑该结论的完整区间。无需把所有历史行都机械转录或结算，已形成的完整转录原样保留。未采用的普通历史行不强制新增候选ID；选择性转录不得省略与主方向相反的重要变化，实际取得的原图按§25保存供复核。正文至少展示**每个提供来源×每个可见市场**的最新状态及本行时间，另展示实际采用行和影响判断的变盘/封盘行；可以紧凑合并，但不得仅展示最终采用公司的报价。某表缺损或不可读时在对应来源和市场处标明，不补造数值，也不扩展成其他清楚市场的缺口。合约方向仍不清时仅对该合约作条件分析或暂无法判断，其他已清楚合约继续。

### 3.6 逐市场回退表

| 缺口 | 继续做什么 | 暂不做什么 |
|---|---|---|
| 无xG | 用历史结果、对手与可查机会机制定性分析 | 编造xG或其精确增减 |
| 无拟合模型 | 定性三市场和入串适配 | 独立概率、精确EV和模型买入价 |
| 只有直接1X2模型 | 对胜平负及可由其决定的合约量化，其余定性 | 由三项概率硬造总球/深让分布 |
| 只有大小球专用模型 | 量化其覆盖的总球线位，其余定性 | 声称已得到主客联合比分或整单相关性 |
| 缺某市场当前价 | 讨论该市场的明确参考线位，标条件；其他市场照常 | 编造现售盘口或将全场一律否决 |
| 所有报价都缺 | 给足球倾向及具体线位的条件分析 | 无条件评价当前票值得放入 |
| 预计首发存在普通位置竞争 | 检查替代后机制是否保持 | 全部默认等首发 |
| 身份/合约/滚球状态关键冲突 | 先查证；无法解决则暂无法判断该对象 | 用不确定对象给当前推荐 |

### 3.7 防止未来信息污染

记录是否看到截点后的首发、赛后xG、结果式搜索摘要或终场结果。日期过滤不保证无泄漏。已暴露未来信息的分析保留用于流程诊断，不能包装成干净赛前预测；按事先统一规则排除主要前瞻评价，不按输赢选择性删除。

### 3.8 过程统计与来源冲突的固定记录

过程统计保存：指标名、供应商/实际发布者、URL或原件位置、抓取时间、比赛ID、主客列序、全场/半场/指定分钟窗、人数/人员状态、指标定义、原显示值。供应商或定义不明就写未知，不能由网站名猜定。

发生冲突依次核查：是否同一场→主客是否换列→是否同阶段/人数→是否同供应商及口径→是否可能修订。仍不能解释时并列各值与时点，说明采用范围或停止该项精确定量；其他已独立核实事实继续。不能挑有利xG拼接、用当前页覆盖旧记录，也不能凭全场统计补造11对11或末段表现。官方优先是检索次序，官方局部模板/事件字段仍须核对；可用可信媒体与完赛数据交叉核实并标级别，不冒称官方。

比较机制时先锁原句及限定词和作用时间窗。结果支付正确、数据来源正确、原机制得到支持是三件独立事项；缺相应事件证据时只结算，机制记未知。

### 3.9 冻结输入、白名单复现与历史资格

发布新预测时，冻结本次**实际使用**的事实、原图、报价、模型及规则版本，保存原字节、相对路径、SHA-256、真实取得时间和分析截点；可靠的原发布时间/首次可知时间另存，未知不推定。清单只能列本任务已获准读取且实际取得的文件，不扫描其他任务资料；原件与派生件分开。`football_model.evidence`负责按明确清单复制、校验和记录时间/用途限制，具体输入见仓库`docs/evidence-contract.md`及实际`--help`。

复现模式只读取冻结清单允许的输入，不临时搜索补充；最终赛果、赛后统计和复盘意见留在独立结果层，由评分程序后续连接。新资料或修订另建新包/版本，不覆盖旧输入。缺原件、取得时间不明、截点后取得或已经暴露未来信息的项目明确排除或降为研究材料；可验证的内容哈希不替代公开时点、来源真实性或先前已读的证明。冻结程序记录这些边界，但不能隔绝LLM已有知识或保证调用者没有读取清单外信息。

赛后建立的冻结包仍是赛后建立，`as_of`填过去不会使它获得真实赛前资格。历史回放即使仅使用可证明当时公开的材料，也标为受限历史重演；已知结果不能靠“忽略结果”恢复盲测。真正前瞻记录必须有开赛前真实生成/保存的预测及其输入证据；是否曾向用户发布另存时间，不以模型文件生成时间冒充报告发布时间。相关资格、缺件与排除原因随包保留，不按后来输赢选择性删除。

F2决定包进一步区分外部输入和依赖这些输入的派生计算。输入的真实取得时间受分析截点约束；冻结输入后完成的复算另记父指纹和完成时间，不把计算时间倒填为输入取得时间。来源自报发布时间另存，与可靠发布时间冲突时保留冲突和待核状态。具体契约见 `docs/s2-decision-record.md`。

## 四、基本面怎样变成某张票的判断

### 4.1 固定区分实力、变化与本场对位

| 层次 | 要回答什么 | 常见错误 |
|---|---|---|
| 实力基础 | 在适用样本中，双方持续创造/限制机会的能力如何？ | 名气、积分或身价直接等于胜率 |
| 近期变化 | 哪些变化有人员、打法或机会质量支撑？ | 连胜等于变强，连败等于变弱 |
| 本场对位 | 本方优势面对本场对手能否发挥？ | 强攻弱守标签直接套到所有对手 |
| 合约要求 | 上述机制支持赢球、赢几球还是某总球区间？ | 看好球队直接推荐所有相关盘口 |

定性判断不要求每项都高分，也不以利好条数投票。信息可靠性、对本场的相关性和对合约的影响要分别看。

### 4.2 每个关键因素都写四件事

“可核查事实 → 对本场哪一环节有影响 → 影响哪种结算结果 → 实际怎样改变判断”。

例如仅作写法示范：“对方近期面对高压多次在后场丢球，预计本场使用同类出球人员 → 本队高压可能增加抢断后的机会 → 支持本队赢球，但不能单凭此证明赢两球 → 主胜保留，深让仍需额外的持续进攻证据。”不能把这个示例当成任何实际比赛事实。

最小影响表：

| 因素/来源 | 是否已在基础判断或模型中 | 对具体票的作用 | 本次处理 |
|---|---|---|---|
| 按本场填写 | 已包含／新增／不确定 | 支持／反对／仅增加不确定性 | 已改模型参数／阵容分支／仅定性／尚无法判断 |

有模型时给调整前后结果及参数来源；无模型写定性作用，不硬填百分点。涉及交互时逐项变化不等于顺序无关的因果贡献，最终看联合结果。

### 4.3 各类信息的使用边界

- xG、射门、绝佳机会、近期进球可能来自同一机会过程，不算四份独立利好。不同供应商口径不静默混用。
- 终结和门将表现小样本波动要与机会数量/质量分开；不能用两场超额进球或扑救率直接指定下场胜率。射门量、射正率、机会质量和终结是不同环节；仅凭“射门多但射正少”不能判定创造质量差或某球员缺阵的因果作用。结合可得的射门位置/方式、封堵、明确机会、门将与比分状态；资料不足就说明尚未分清，不强制要求xG。
- 伤停相对替代者与常用阵容评价；长期缺阵已经反映在近期表现中时，不重复扣减。
- 高压、控球、反击、定位球等要匹配对手和场上人员；控球多不自动等于机会多，低位防守也不自动小球。
- 休息、旅途与天气只有与本场相关且有可靠信息时参与；不设“少休一天减5%”“下雨固定小球”。
- 战意按赛制目标→预计用人/策略→具体机会或防守变化表达。“必须赢”不直接加分。
- 多年交锋只有当前人员、教练或机制仍可比时作辅助，不压过本场事实。

## 五、A01：预计首发与关键替代情景

### 5.1 人员表不必猜中全部11人

默认在最早提前10小时的实际截点评估。先列已确认缺阵/停赛、相对稳定的位置、预计首发、存在竞争的位置和未知信息；标来源与时间。预计可用不等于确定首发，首发也不等于踢满全场。没有消息不能写成“全主力健康”。

集中评价会影响本场合约的中锋、创造者、后腰、中卫组合、门将等角色，实际重要位置由本场决定，不以“明星”标签代替分析。替代者、预计分钟与角色变化同时说明。预计分钟有近期用人或模型依据才给范围；无依据时描述预计首发/替补及角色，不制造精确分钟。

### 5.2 何时是关键条件

把“关键”定义为：一个有现实证据的未决分支，可能改变**当前具体票的适配、首选市场/线位或重要赢走输区间**。不要求球队胜负方向完全反转才算关键。

例如主队即使轮换仍可能占优，但某中锋缺阵会削弱深让所需的第二个进球支持；这足以影响主队−1.25，即使主胜倾向未变。此时可改选支持更充分的真实盘口，或对原票给条件适合；不能说“主队仍强，所以阵容不重要”。

普通轮换、双方替代方案差异小且主要机制保持时，可以给当前适配。不必把“等首发”写成每场固定条件。

### 5.3 分支怎样落地

| 场景 | 依据 | 影响哪个环节与合约 | 当前处理 |
|---|---|---|---|
| 主要预计安排 | 按本场填写 | 按本场填写 | 形成基准判断 |
| 有现实依据的关键替代 | 按本场填写 | 支持减弱／换线／不适合等 | 保留／条件／改选，写原因 |

只列可能影响判断的分支，不穷举所有理论阵容。无可靠权重时分别说明，不手填50%/50%或“首发80%”。有训练的阵容模型及分支概率时，先各自生成完整分布，再混合；不能只取平均球员或平均λ代替完整预测不确定性。

正式首发之后复核是否影响原机制；复盘区分当时可查却遗漏和后来才出现的新信息，不因一名首发不同就判原分析错误。没有已启用监控就不假称会自动更新，已成交票按原合约处理。

## 六、胜平负：先判断谁占优，再单独检查平局

### 6.1 要回答的问题

在本场常规时间结束时，主胜、平局、客胜哪一项最有支持？支持获胜的依据是否强到足以承担“打平也全输”？主胜总概率较高，并不要求主胜比分是概率最高的单个比分。

### 6.2 所需输入

- 主客身份与90分钟规则、可核实的胜平负报价。做去水需要同平台同状态完整三项；部分报价缺失时仍可分析已有合约，不拼造完整市场。
- 双方攻防基础、近期机会质量或可靠的过程资料、主客场表现；有模型做数值对手修正，无模型按第三节说明对手可比性。
- 预计首发、关键替代方案、赛制目标与比赛节奏。
- 有模型则使用同对象比分分布；直接1X2模型只能提供胜平负及由其确定的相关事件，不扩展为大小球/深让盘模型。

### 6.3 推理步骤

1. **分别检查两端对位**：主队如何攻破客队，客队又如何攻破主队；说明优势来自持续机会、转换进攻、定位球还是其他具体机制。只解释热门队进攻不算完整分析。
2. **检查优势是否仍然存在**：当前预计人员相对历史基线有何变化？近期漂亮战绩是否主要来自弱对手、红牌或异常终结？替代者是否能保持原角色？
3. **单独分析平局路径**：优势方是否只是防守稳定而缺少破门能力？弱方能否通过低位防守、节奏控制或定位球抵消差距？双方对平局的赛制收益必须有事实依据。“平局风险”不能成为每场通用免责句。
4. **形成三项比较**：内部先公平检查主胜、平局、客胜各自的支持、反证和已有报价，再选一个有实质支持的市场代表；不能只查热门或为衬托另一市场而挑一个明显弱候选。有合格模型时按对应分布计算；无模型时给定性方向及证据强弱，不编三个加起来为100%的数。
5. **把判断放回价格**：分别评估“更可能获胜”与“当前赔率是否有价值”。市场去水概率另列为市场基准；不把其当独立能力预测。
6. **与让球候选比较**：如果胜负优势明确但平局是实质风险，比较确实存在的平手盘或受让/让球浅盘；不得声称降低赔率就必然更适合。若同结算口径下主胜与主队−0.5支付事件相同，比较已核清合约与性质的真实参考报价、费用和规则；若声称当前开放或实际成交，另需相应证据，不能当成两个独立观点。

有联合比分分布时：

$$
P(1)=\sum_{h>a}P(h,a),\quad P(X)=\sum_{h=a}P(h,a),\quad P(2)=\sum_{h<a}P(h,a).
$$

### 6.4 合约与支付

普通胜平负中，所选结果发生为全赢，否则全输；不因为“球队没输”而把主胜票的平局记为走水。每单位本金十进制赔率为\(O\)，全赢净收益\(O-1\)，全输\(-1\)。加时晋级市场、双重机会、竞彩让球胜平负是其他合约，另行标明。

### 6.5 主要反证与降级分支

- 对手有明确克制机制；有利数据依赖已不在预计阵容的关键球员；热门队近期机会创造弱于赛果；双方可能接受平局。
- 没有xG：可用对手、比赛结果、射门质量描述、阵容和战术评估，不能把射门次数机械换成胜率。
- 没有独立模型：仍可给适配，盈利概率和EV标未量化。
- 同时存在强度相近的主胜、平局依据，且无法判断主次：给弱倾向；不能靠强行上调“战意分”解决。
- 比赛身份/常规时间规则不清：暂停当前合约判断，指出具体待核项；不延伸成所有足球信息不可分析。

### 6.6 最小输出

“1X2相对倾向：[结果]；主要赢球机制：[具体机制]；平局/对手获胜的最强路径：[具体路径]；当前/参考报价：[平台、赔率、时点]；盈利概率与来源：[有据数值或未量化]；EV：[有据数值或未量化]；适配：[结论]；与让球相比：[选/不选理由]。”

## 七、亚洲让球：判断净胜幅度，不能只判断谁强

### 7.1 要回答的问题

当前让球要求所选队实现怎样的净胜差？球队优势足以支持这个幅度，还是更支持赢一球/保平/小负？半赢、走水、半输在串关中分别改变什么支付？

### 7.2 所需输入

- 所选队、明确正负号和线位、赔率、时间与让球结算起点。
- 胜平负流程形成的两端对位判断，以及领先后策略、落后方进攻能力、替补和体能对后段比分差的影响。
- 有模型使用净胜球分布；未建模时，只对有证据的比分差路径作定性分析，不把“看好主队”翻译成任意深度的让球。

### 7.3 推理步骤

1. **先把盘口翻译成比分差要求**：例如让−0.75需要至少赢1球才净盈利，赢1球半赢、赢2球以上全赢；−1赢1球仅走水。先说明要求再评价能力。
2. **区分领先能力与扩大优势能力**：优势队能否稳定破门？领先后是继续进攻还是控节奏？落后方压上会产生反击空间，还是有足够能力追平？这些是有条件的未来路径，不能当作已发生事实。
3. **检查对手反向进球**：零封能力、后场缺员、定位球和转换防守能否支持所需净胜幅度。总进球多不等于热门队能穿深盘。
4. **检验预计阵容分支**：普通轮换是否主要影响净胜幅度而不改变获胜倾向？若是，应降低对深让的支持，比较浅盘；不必把整场统一否决。
5. **映射五态**：量化时从同一比分分布汇总全赢、半赢、走水、半输、全输；定性时明确最相关的1—2个分界事件及其依据。
6. **先比较本线两侧，再看真实替代线与价格**：内部同时检查让球方与受让方，各自是否有支持当前支付门槛的事实，再选亚洲盘代表。不能从“不支持热门赢两球”直接推出“弱队受让最好”；受让方仍须解释如何限制失球或保持反向进球能力。同一队−0.5、−0.75、−1的差异是支付变化，不是换了球队判断。只在已核清合约及价格性质的真实报价（包括适用的最新公开参考）上比较，不凭空给“退一档就稳”的建议。

**变线例（只说明支付）：** 所选队由＋1.5变为＋1.25，净负一球从全赢变成半赢。即使变线被解释为市场提高对该队的评价，新买受让票的这一档保护仍减少；能否接受须同时看新价格、当前机制和有依据的概率，不能只说“走势支持，所以更值得买”。

令\(D\)为所选队进球减对手进球、\(a\)为该队让球，整数/半球盘按\(D+a\)正、零、负分别全赢、走水、全输；四分之一盘等额拆分相邻两条线。赛前用全场净胜球；用户限定的新滚球剩余让球仅用接受后新增净胜球。

| 所选队净胜差 | −0.25 | −0.75 | −1.0 | ＋0.25 | ＋0.75 |
|---|---|---|---|---|---|
| 至少赢2球 | 全赢 | 全赢 | 全赢 | 全赢 | 全赢 |

| 输1球 | 全输 | 全输 | 全输 | 全输 | 半输 |
| 至少输2球 | 全输 | 全输 | 全输 | 全输 | 全输 |

每单位本金的返还倍率依次为：全赢\(O\)、半赢\((O+1)/2\)、走水\(1\)、半输\(0.5\)、全输\(0\)。净收益须减去本金1及实际费用。半赢计入净盈利，走水不计盈利；“不全输概率”不是盈利概率。

### 7.4 主要反证与降级分支

- 可以赢球但缺少持续扩大优势的路径；对手虽弱但失球少、节奏慢；优势队领先后收缩；关键替补明显降低后段进攻；对手有稳定的反向进球机制。
- 仅有1X2概率：可评价由胜平负完全确定的盘，例如±0.5、0、±0.25；不能唯一确定−0.75、−1.5等依赖净胜幅度的概率。继续定性分析幅度，或明确需比分模型。
- 盘口符号、球队归属或滚球起点不明：先核清该项，不能靠通常习惯猜结算。
- 没有幅度优势但有胜负优势：优先比较浅盘/胜平负候选，不强求让球市场也给正向推荐。

### 7.6 假设示例：看好获胜，未必支持深让或大球

以下球队、事实与赔率均为演练假设，不代表已查到任何比赛：A主场对B，分析时距开赛8小时。假设核实资料支持A整体攻防优于B，但A一名主要创造者的替代方案会降低持续压制；B进攻有限但能收缩。假设可见报价为A胜1.70、A−1为2.05、大2.5为1.90。未训练独立模型。

- **胜平负**：A获胜的依据是攻防与对位优势；最强反证是创造者变化可能提高平局风险。合理预计替代方案仍保留获胜支持，可把A胜列相对主方向。
- **让球**：A−1需要至少赢2球才净盈利，赢1球只走水；现有证据支持赢球强于支持拉开差距，所以不把更高赔率视为更优候选。
- **大小球**：B进攻贡献有限，创造者变化又可能影响A连续破门，大2.5较依赖A单方多球；不因A更强就选大。
- **输出**：主方向A胜；若假设资料满足充分证据、当前真实报价可对应合约、没有第十一节所述有充分依据的绝对收益不利等要求，可评“适合入串｜盈利概率与EV未量化”。主要风险是破门效率不足导致平局。该例说明判断流程；仅凭这几句文字本身不能证明实际球队适合。

## 八、大小球：联合检查双方进球来源与具体分界

### 8.1 要回答的问题

本场双方各自的进球来源是什么？总体节奏及领先后的反应如何改变总进球？判断是否支持超过/低于当前这条线，而不仅是“比赛看起来开放/沉闷”？

### 8.2 所需输入

- 明确全场累计或剩余总球、准确线位、大/小两侧报价及时间。
- 双方创造与限制机会能力、历史xG/npxG及口径；不可得时使用历史进失球、对手和可核实比赛过程作替代，注明局限。
- 预计前场、后腰、中卫、门将与替代者；具体战术互动、赛程及已核实环境。
- 有模型使用总进球分布；仅有总进球均值或1X2概率都不足以唯一确定盘口概率。

### 8.3 推理步骤

1. **拆开双方的进球供给**：分别判断主队能从哪里得到机会、客队能从哪里得到机会。至少说明大球是否需要双方进球，还是主要依赖单队多球；小球是否能同时限制两端，而不仅是一方进攻弱。
2. **检查历史数据的适用性**：高xG是否来自弱对手、红牌后、点球或长时间落后压上？低失球是否主要依靠对手浪费机会？同一问题不能在“状态”“xG”“阵容”重复计入。
3. **把人员变化转成具体机制**：例如中锋缺阵影响禁区接应，后腰替换影响丢球后保护，门将更换影响射门转化。方向以证据和替代方案为准，不设缺前锋=小、缺后卫=大的固定规则。
4. **检查至少一个相关比分路径**：0—0时能否形成持续机会；任一方领先后是否降速；落后方能否逼迫开放比赛。只展开会影响本场的路径，不强制枚举所有红牌、点球和早球的坏情景。
5. **对准盘口分界**：例如大2.75最关键的是总球≤2、=3、≥4三段；小3.0则是≤2全赢、=3走水、≥4全输。说明证据支持哪一段与为何，不用“预计2—3球”代替支付判断。
6. **检查相反方向的最强证据**：推荐大球时检查一侧难进球与领先后降速；推荐小球时检查某一方独立打出多球、守转攻漏洞与追分压力。反证要落实为方向、适配或条件的变化。
7. **公平比较大、小两侧，再比较真实替代线**：双方都按自身支持、最强反证、支付边界和有效报价审查，再确定大小球代表。同样认为进球偏多，对大2.5、大3.0和大3.5可以有不同结论。线位变动后重算/重评，不沿用原结论；价格变化本身不能证明球队状态已改变。

**变线例（只说明支付）：** 小2.75遇到3球半输，小3遇到3球走水。总盘升高同时改变了市场预期和新小球合约的结算边界；不能只因多家公司升盘就规定“无模型不许选小”，也不能只因走水保护改善就选小。必须检查单队多球、双方进球、追分节奏等机制，并比较新线和新价。

有比分分布时：

$$
P(T=t)=\sum_{h+a=t}P(h,a).
$$

按各\(t\)的实际支付汇总五态和EV。总进球均值\(E[T]\)只是摘要；仅当选定且适用的分布假设成立时，才可由其确定完整分布。不能只因均值2.8就认定大2.5概率超过50%。

| 最终总球 | 大2.5 | 大2.75 | 大3.0 | 小2.75 | 小3.0 |
|---|---|---|---|---|---|
| ≤2 | 全输 | 全输 | 全输 | 全赢 | 全赢 |
| =3 | 全赢 | 半赢 | 走水 | 半输 | 走水 |
| ≥4 | 全赢 | 全赢 | 全赢 | 全输 | 全输 |

### 8.4 主要反证与降级分支

- 双方都“进攻好”但面对的是明显更强防守；一方进攻贡献非常弱；预计阵容破坏压迫/创造；战术目的降低节奏；盘口已要求远高于支持机制的进球数。
- 无xG：仍可依据其他可核实攻防、人员与战术信息分析；不以xG缺失自动否决，不把进球均值伪装成xG。
- 无模型：写定性总球倾向、具体盘口的盈利路径与反证，概率/EV未量化；有充分证据仍可适合。
- 只有1X2、无总球依据：1X2不足以支撑大小球数值；该市场证据薄弱可明确不作主选，继续比较另外两市场，不强行完成一个大/小推荐。
- 只有赛前均值而处于滚球：先核实际状态，再做定性更新；没有合格实时模型不按剩余时间比例冒充精确大小球概率。

### 8.6 假设示例：同一进球预测，不同盘口有不同收益

以下分布和报价完全是假设，仅用于说明支付与EV：假设某个合格模型给出\(P(T\le2)=45\%\)、\(P(T=3)=25\%\)、\(P(T\ge4)=30\%\)，无费用。比较大2.5@1.80、大2.75@2.00、大3.0@2.25。

| 合约 | 净盈利概率 | 走水概率 | 净亏损概率 | 每单位EV |
|---|---:|---:|---:|---:|
| 大2.5@1.80 | 55% | 0% | 45% | 55%×0.80−45%=−1.0% |
| 大2.75@2.00 | 55%（含25%半赢） | 0% | 45% | 30%×1.00＋25%×0.50−45%=−2.5% |
| 大3.0@2.25 | 30% | 25% | 45% | 30%×1.25−45%=−7.5% |

三条线使用同一个进球分布，却有不同的盈利概率和EV；大2.5与大2.75盈利概率相同也不代表收益相同。该例不能作为“真实比赛应统一选某条线”的规则，也不能按假设分布判断现实价格。量化结果若真实、可靠且适用，就不能仅因55%的盈利概率而忽略负EV；当概率根本未量化时，也不能把上述示例负EV套到现实候选上。

## 九、概率来源、模型资格与市场对照

### 9.0 决策数字、市场参照和研究算例分栏

- **实际预测栏**：只放本场适用、已运行且可复算的F/MIX预测；若验证有限，显著写“探索性模型估计”，按§9.2—§11.3限制其分量。无模型时写“盈利概率、净EV未量化”，首页仍完整给定性适配。
- **市场参照栏**：可单列同平台同状态去水1X2及假设，明确这描述市场。不能把市场基准或含抽水回代结果改名为独立基本面结论。
- **研究区**：市场拟合的λ、五态、参考EV以及手工假设只在确有诊断用途时展示，标MKT/SCN，不能为填满首页临时生成。记录拟合输入/排除的市场、时间与状态匹配、目标函数/权重、残差、输出敏感性和非唯一性。

每场固定一句：“本场基本面作用：[已由模型量化的范围／仅定性／未加权条件情景]；实际模型状态：[无模型／已拟合验证有限／相关任务已验证／本场不适用]。”可以有混合状态，例如历史攻防已量化、临时伤停仅定性；不能把后者伪装成已改变概率。

### 9.1 每个数字先说明从哪里来

| 来源标签 | 含义 | 可以怎样使用 |
|---|---|---|
| F：基本面 | 历史球队、球员或事件数据训练；赔率未作输入、先验或监督目标 | 在实际覆盖任务内做独立模型估计 |
| MKT：市场 | 去水、报价或市场拟合 | 市场基准，不能单凭同价回代证明真实价值 |
| MIX：市场参与 | 含赔率特征、市场先验、赔率评级或经验证融合 | 可用于预测，但不能称纯非赔率 |
| SCN：假设情景 | 明示的手工假设 | 解释敏感性或算术，不能当实际预测 |

定性分析直接写“定性，未给数值概率”，不强贴一个模型来源标签。事实证据用中文或E表示，不能再用F同时表示“事实充分”。模型成熟度M是另一维度，不是概率来源。正文优先中文名称，技术记录才使用缩写。

### 9.2 四级数值能力与本场适用性

| 当前状态 | 能报告什么 | 不能推断什么 |
|---|---|---|
| 无模型/仅有公式 | 定性判断、市场基准、假设演示 | 独立概率和模型EV |
| 已拟合可复算，验证有限（M中） | 探索性模型概率/点估计EV，明确范围和限制 | 精确点估计已经证明价格优势 |
| 相关任务样本外验收通过（M高） | 在覆盖任务内估计概率、误差及敏感性 | 对所有联赛、杯赛、滚球都有效 |
| 模型失配或数值失败（M低/不适用） | 标出失配，改用其他合格模型或定性 | 保留失败数字继续支持结论 |

“可复算”至少有数据/参数版本、训练截止、预测输入、代码或明确计算过程及合法输出。没有这些产物不因模型名字知名就评M中。M高必须提供相关联赛/市场/截点的验收材料；没有统一“满N场自动合格”。

本场运行前检查：球队与赛事是否覆盖；时间范围是否正确；输入是否过期；模型目标是否与所选合约一致；概率是否合法；参数/尾部/仿真误差是否已记录。成熟度高也不能掩盖本场错盘或新阵容未纳入。

没有误差评估时，可以说“模型点估计EV为正，优势尚未确认”，不能默认误差为0，不能凭＋0.1%就宣称有优势。价格及敏感性如何影响适配见第十一至十三节。

### 9.3 不同模型能覆盖哪些票

完整比分分布优先用于统一映射三市场。直接1X2模型可覆盖普通胜平负、双重机会及结算完全由胜/平/负决定的亚洲线，例如0、±0.25、±0.5；不能唯一确定需要净胜幅度的深盘或大小球。

单独总进球模型可覆盖相应大小球，不自动提供主胜概率。不同专项模型允许并列，但要标来源，不伪称有共同联合比分，也不能据此直接计算同场串关相关性。

**已读历史产物支持的能力（当次仍须核验）：** 基础泊松模型实际提供完整比分矩阵，可按标准支付映射胜平负、亚洲让球和大小球。但本轮所读历史验证材料主要为1X2的对数损失和Brier误差，深让球、总球尾部及盘口五态尚未专项验收。因此这些市场可以给可复算的“探索性模型估计”，不能因矩阵可计算就写成该市场已验证，更不能直接认定正EV已证明。

至少检查这些可核查一致性：常规时间主胜与主队−0.5为同一盈利事件；P(总球≥4)不能大于P(总球≥3)；对同一队，赢两球以上事件包含于获胜事件。不要把包含半赢/走水的不同支付概率误当同一事件。

### 9.4 市场1X2与去水

1X2只有主胜、平局、客胜三项。对同一平台、同状态的完整三项十进制报价，简单比例去水为：

$$
q_i=\frac{1/O_i}{\sum_j1/O_j}.
$$

它是明确假设下的市场基准，不是真实概率。正抽水时将同一组q代回原价：

$$
q_iO_i-1=\frac{1}{\sum_j1/O_j}-1<0.
$$

因此这种负EV是构造结果，不是独立证明本场真实EV为负；也不能一边据此否定主胜、一边随手上调大小球概率。不同去水方法与市场拟合须说明假设，跨平台先各自处理，不拼最高价造概率。

带走水/半结算的两项报价不能直接用倒数唯一恢复五态概率。跨市场拟合必须说明目标函数、额外假设、误差与非唯一性；市场信号分歧先排查合约、时点、费用和数据，不能直接编“诱盘”故事。

**拟合残差不等于球队新信息。** 以审计中显示数值作算术示例：47.91%×2.07−1≈−0.83%，48.70%×2.07−1≈＋0.81%。如果概率变化只是把同一批市场报价拟合成泊松分布，EV变号并没有新增基本面依据。报告残差及对结果的影响，不凭这类小正数认定价值，也不以小负数直接判实际EV为负。

可以预先留出亚洲盘等某市场做跨市场一致性检查，不强制把待评价报价加入拟合；但“没输入该市场”不等于独立基本面模型，也不能自动把价差当利润。多家公司均值、去水方法、来源权重或拟合政策须固定并披露，赛后更换只能进入§18.5探索方案。

### 9.5 A01：为什么1X2不能唯一决定总球和比分

以下仅为数学演示：

| 结果概率 | 比分分布A | 比分分布B |
|---|---|---|
| 主胜60% | 1—0占60% | 3—0占60% |
| 平局20% | 0—0占20% | 2—2占20% |
| 客胜20% | 0—1占20% | 0—3占20% |

两者1X2一样，但A全部小于2.5球，B全部大于2.5球，主队−1.5的盈利概率也不同。可以加泊松等假设拟合比分，但那是“报价＋假设”的推算，不是赔率唯一给出的答案。

同样，主胜总概率较高，不妨碍1—1是概率最高的单个比分。最可能比分按概率排序展示并注明覆盖；只列主胜比分时称“主胜条件情景”，不能选择性遮掉靠前的平局比分。无比分模型可谈假设路径，不把主观列举称概率排名。列出的三个比分中有两个走水，不代表走水概率为三分之二或“很高”；情景条数不是概率质量。合理的失败比分可用于展示反证，不因与主方向支付不利而删除。

### 9.6 融合是可选步骤

两侧都有同对象完整比分分布时，可以验证后采用：

$$
\pi_D=\alpha\pi_F+(1-\alpha)\pi_M,\qquad 0\le\alpha\le1.
$$

π_D表示本次采用的分布，不是第五种信息来源；融合来源标MIX。含义是逐比分按同一权重结合基本面与市场预测。权重在过去训练/验证段确定，用后续未见样本检验，不按本场想支持哪一方临时调节。

两分布必须覆盖同一比赛、同一结算范围、同一分析截点下的信息；全场与剩余比分不能直接平均。只有市场1X2时可做胜平负对照，不强行构造全比分融合。基本面只有定性判断时不执行这个公式，也不因此停止本场分析。

## 十、合约映射与五态结算

### 10.1 统一到真实支付事件

赛前同一常规时间比分P(H,A)：胜平负比较H与A；亚洲让球用所选队净胜球加让球；大小球用H+A。竞彩让平是独立选择，不能使用亚洲走水规则。半场/半全场需要阶段模型，角球、牌数与球员市场需要自己的数据和支付规则，不由全场进球分布代替。

对用户限定的新滚球剩余亚洲让球，统一记录 `settlement_basis=AH_REMAINING_REGULATION`。实际接受时比分(H_b,A_b)，终场(H_f,A_f)，令X=H_f−H_b，Y=A_f−A_b：

| 票的类型 | 用于结算的量 |
|---|---|
| 全场胜平负 | 比较H_b+X与A_b+Y |
| 新主队剩余让球a | X−Y+a |
| 新客队剩余让球a | Y−X+a |
| 全场累计大小球 | H_b+A_b+X+Y |
| 剩余进球大小球 | X+Y |

旧赛前票不重置。这个剩余让球规则不是所有平台所有票的通用规则；若平台合约不是用户限定的范围，先指出不匹配，不能擅自改票。分析、提交和实际接受时点区分；VAR改判或接受前事件导致起点冲突时先核对。

报价与候选分别保留结算范围、起点性质及起点证据。推荐参考阶段记录实际观察的分钟/比分及时间，标记 `settlement_start_status=reference_only`；实际接受时间、接受时比分未知就分别留空并说明原因，不能把报价行时间或分析时比分填成成交起点。有真实接受记录后才标记 `settlement_start_status=accepted`，填写 `accepted_at`、`accepted_score` 及证据引用，并按该接受起点计算票据支付；两个状态都不改变未知成交的处理原则。

### 10.2 四分之一线与五态

四分之一线等额拆成相邻整数/半球线：−0.25＝0与−0.5，−0.75＝−0.5与−1，大2.75＝大2.5与大3。同一张票两半用该票价格；独立买两张不同价票则分别算。

| 状态 | 缩写 | 含本金返还 | 无额外费用净收益 |
|---|---|---:|---:|
| 全赢 | FW | O | O−1 |
| 半赢 | HW | (O+1)/2 | (O−1)/2 |
| 走水 | P | 1 | 0 |
| 半输 | HL | 0.5 | −0.5 |
| 全输 | FL | 0 | −1 |

半输不能藏在“不全输”里。收费改变净收益时，按实际R的正负分类，扣费后走水可能亏损。平台特殊佣金、提前兑现和作废规则另算。

重点边界：−1.25赢1球半输；＋1.25输1球半赢；大2.25总球2半输；大2.75总球3半赢；小2.75总球3半输；小3.25总球3半赢。每场只展开对应盘口最相关的临界结果，不用用户自行推断。

### 10.3 有概率时怎样算五态

逐个比分先判该合约的结算状态，再把同状态的概率相加。不能把总进球均值直接当大球概率，也不能把获胜概率直接当深让盈利概率。五态非负且合计1；截断比分矩阵的遗漏质量及归一方式必须披露，不能把尾部全塞进有利状态。

从同一组五态得到盈利、走水、亏损和EV；无费用盈利=p_FW+p_HW，亏损=p_HL+p_FL。展示条件盈利/亏损幅度时，条件概率为0就写不适用，不除以0。有额外费用按实际支付重算。

## 十一、报价、净EV与价格条件

### 11.1 先分两种比较

| 比较 | 需要什么 | 能得到什么 |
|---|---|---|
| 同合约相对报价 | 相同支付事件、时点状态、规则、费用与可得性 | 无需预测概率，也能说1.85比1.80支付更好 |
| 绝对收益价值 | 适用概率分布＋实际支付 | 估计当前价的净EV及不确定性 |

A平台1.80、B平台1.85，不足以证明A是负EV。优先提示可用的较好价；更好价不可用也要说明。不同线位如−0.5@1.70与−1@2.10不是同一支付，不能只比数字大小。放进串关不会自然修复负EV，低赔率也不能独自证明适合。

代表报价写明采用理由：用户可用平台、同状态较优价、明确指定平台或固定研究基准。若同表已有更好且可比的有效价却不用，应说明可得性、规则、费用或研究口径差异；不能无说明地固定偏爱某家公司。对侧/替代缺价就写缺失，不虚构报价。正文单列“报价比较：相对较好／相对较差／同状态差异不明／没有可比报价”。这与下方模型价值栏分开，不把相对较差自动归为不建议入串。

### 11.2 净EV与最低价公式

标准结算、每单位固定费用k，令A=p_FW+p_HW/2，L=p_FL+p_HL/2：

$$
EV=(O-1)A-L-k,\qquad O_{BE}=1+\frac{L+k}{A},\qquad O_g=1+\frac{L+k+g}{A}.
$$

A>0才可用价格简式；A=0且要求正EV时无有限达标价。只有无走水、无半结算、无额外费用的二元合约用pO−1，有固定费用则pO−1−k。赢利佣金、税或特殊结算应逐状态算ΣpR，不能硬套固定k；抽水已经在赔率支付中，不重复扣一遍。

O_BE是给定分布的保本价，O_g是达到已选目标g的价格，都不是当前真实报价。没有可靠概率就不造这两个数。无费用二元1/O只是价格要求的保本概率，不是预测概率。

假设纯二元、无费用：75%概率配1.25，EV为−6.25%；55%配2.00，EV为＋10%。这只说明命中与收益不同，不是本场参数，也不要求一律选低命中高EV。

### 11.3 模型收益价值的判词

先判断数字来源与本场适用性，再分类：

| 判词 | 需要呈现的依据 |
|---|---|
| 模型支持正向价值 | 本场适用的F/MIX估计为正；相关验证、误差/敏感性支持该判断，说明局限 |
| 模型优势不清 | 可复算，但点估计近零、误差覆盖正负、验证有限或现实分支冲突；原点估计仍如实列出 |
| 模型显示不利 | 本场适用F/MIX支持当前价负EV，并说明敏感性及依据强弱 |
| 未量化 | 没有适用概率或报价/费用不足以计算；不填0，不推断正负 |

只有点估计而未评价误差时，写“点估计为正/负，优势尚未确认”，归模型优势不清；不能称已有优势证明。MKT同价去水负EV单列市场基准，不套“模型显示不利”。模型输出异常先查输入、时点、合约和拟合，不能为保留主推删除不利结果。

### 11.4 条件价与可选保守政策

默认单场适配不强制＋2%／＋5%门槛。有模型且任务需要时，可以显示中心模型价格及敏感性，但绑定分布、费用、截点和目标。按平台合法价位向上取整，再回代；不在没有模型时随口定“到1.85就买”。

若事先选择所有指定压力分支达标的保守政策：

$$
EV_{\min}(O)=\min_{s\in\Gamma}EV_s(O),\qquad
O_{\min}^{raw}=\max_{s\in\Gamma}\left[1+\frac{L_s+k_s+g}{A_s}\right].
$$

Γ及依据事先固定，不删坏分支；存在无有限达标价的分支就说明。各分支逐一回代。旧M高g=2%、M中g=5%只保留为待验证的可选项目政策，不是安全保证。附录代码的min_price专用于这种正目标、固定费用、等距格点情形；g=0保本用上面的公式或相应实现，不能把代码拒绝g=0误当无保本价。

无模型时可比较实际同合约价格、说明某种变线需要重评；报价条件只可来自已核实真实合约或用户指定线位，并说明它不是数学保本阈值。条件价格到了仍须重核新信息，不能自动沿用旧概率。

## 十二、从证据到主方向，再到串关适配

### 12.1 “充分、一般、薄弱”怎样判

逐一核对四个环节，不作网站计数或手工加权打分：

1. 实力基础是否覆盖本场双方与对手差异？
2. 当前阵容/打法能否支持所述机制？
3. 机制是否直接支持当前这张票所需的结果，而非只支持球队名气？
4. 最强反证是否查过，并实际影响或经过解释后未推翻判断？

**充分**：主要环节可核查，推断链清楚，重要反证已处理；允许普通信息缺口和无高级模型。  
**一般**：有实质依据，但存在已说明且不支配当前结论的缺口或机制不确定性。  
**薄弱**：核心只靠名气、盘口、未核传言，缺少合约所需的机制，或关键冲突仍悬空。

“充分”只说明依据组织与覆盖，不保证预测正确，也不对应70%等概率。单条官方重大事实可能胜过许多弱相关数据。

### 12.2 反证必须产生明确处理

每条主要反证写：针对哪个原判断→若成立会影响什么支付结果→证据状态→当前处理。处理只需落在以下之一：

- 普通失手路径：说明其存在，当前倾向不变。
- 支持减弱：降低证据强度或优先级，解释为什么尚未改票。
- 改变具体选择：换市场/线位，或关键条件未解决时等待。
- 推翻适配：此合约不再推荐。

“存在爆冷风险”没有对应机制与处理不算完成反证审查。更强的球队、较高主胜概率，均不能反驳“深盘幅度缺乏支持”。

### 12.3 适合、条件适合、不建议、暂无法判断

按以下顺序判断每个候选，不把所有未知都列成失败：

1. **对象能否确认？** 身份、合约、必要实时状态或关键资料无法确认且无法形成可用条件分支→暂无法判断该对象。
2. **依据是否支持这张票？** 已有信息能判断，但支持弱、主要机制被反证推翻、较深线位缺乏额外支持，或适用模型对该价格显示明确不利→不建议。
3. **是否仅剩具体关键条件？** 主体依据成立，少数现实、可核验的阵容/线位/报价条件会改变该票判断→条件适合；注明条件满足和不满足分别怎样处理。
4. **其余情况是否足以形成有依据的候选？** 机制与具体结算门槛相符，主要反证已权衡，报价可对应当前票→适合，另报证据与收益价值状态。

第2步针对已核实且不依赖未决关键条件的反对依据；若不足来自可核验的未决分支，转第3步，不把未知当不利事实。条件分支本身仍须有实质支持，不能把证据薄弱包装成“等一个条件就适合”；若各合理分支均不支持该票，则不建议。

“适合＋EV未量化”必须同时说清：支持机制、赢走输要求、机制为何支持该要求、最强反证为何未推翻、当前报价性质。这是定性候选判断，不是确认经济收益优势。不能凭一句“没有发现利空”评适合。

已被更新替代或已知不适用的历史价、假设价不支持当前票的无条件适合；可对明确合约作条件分析。按图规v1.2识别的最新清楚公开参考不因缺账户开放/接受证明或市场异步而自动归入此类。找不到一条可核验条件、只有笼统不确定性时，不用“条件适合”搪塞，应说明是证据弱而不建议，还是关键对象无法确认而暂无法判断。

已得到适用且有充分依据的负EV结果，不能切换成定性模式隐藏它；单纯缺模型或同价市场去水负EV也不能一票否决。

### 12.4 三市场怎样选唯一相对主方向

**先挑候选，再选主方向，避免预先偏向受让或小球。**

1. 胜平负先检查胜、平、负；亚洲盘先检查本线两侧；大小球先检查大、小。每项保留支持、主要反证和报价状态，再各选一个有实质依据的代表。无依据的市场明确不作主选，不强凑方向。
2. 对主方向问：“除不愿追另一侧之外，它自身的正面依据是什么？”让球/受让要解释净胜幅度，总球要解释双方进球机制。低赔率、损失较小、走水保护和多覆盖几个赛果只描述支付，不能代替事件发生依据。
3. 确认最接近的替代，包括同市场对侧或跨市场合约，写清主方向为何更受支持。缺报价时限定为足球机制比较，不声称完成价格/EV优劣排序。
4. 正文用三市场表和一两句取舍即可，不要求展示七份长分析，也不把内部检查的每个方向都列成推荐。


先比较合约所需结果与机制的匹配程度，再比较对关键假设的依赖、盈利/亏损结构和失手幅度，最后比较可比报价与有依据的EV。用户偏好较高盈利命中表现，但不能用高命中掩盖明确收益劣势。

主胜与主队−0.5若结算事件相同，视为同一方向的报价备选，不能当两份独立支持。相同信息的重复模型或不同平台也不增加独立证据。

有同源适用概率才精确排序；不同模型覆盖和不确定性明显不同，不凭0.2个百分点强分。没有模型仍可定性比较机制，但必须说明比较依据。

仍无法辨识优劣时，可以给“唯一相对倾向，优势弱”，解释选择依据，并给相应适配；不要为满足唯一方向硬造概率或称适合。比赛身份未确认时不硬选。某市场无法分析不影响另两市场完成任务，原样标出缺口即可。

同一报告只给一个主方向；更高EV但更易失手的替代可以解释取舍，不同时给两个“主推”。改主方向必须产生新报告版本，不能复盘时换成打出的备选。

### 12.5 主方向发布前的五个追问

1. 去掉赔率高低与球队名气，仍有什么本场事实支持这一票？
2. 这些事实支持的是获胜、净胜几球，还是哪个总球区间？与所选线一致吗？
3. 最强反证具体影响哪一种赢/走/输结果？本次是普通失手路径、支持减弱、换票、条件还是不建议？为什么？
4. 最近替代的支付、机制和实际价格有什么差异？同一盈利事件是否被错误计作独立支持？
5. 模型对主方向有利和不利时，是否使用同一套来源、成熟度、适用性和误差标准？条件、报价性质和最终适配是否前后一致？

五问必须能从本场底稿回答；不要求五问都给正面结果。发现缺口回到对应步骤，不为维持原倾向新增无依据解释。此检查落实既有比较纪律，不建立新的固定权重或一票否决门槛。

### 12.6 结构化决策审计与固定证据重复检查

主卡必须并列显示**合约适配**（适合／条件适合／不建议／暂无法判断）和**价格价值**（§11.3四种判词）；例如“适合（定性候选）｜价格价值：未量化”。它们是不同判断，不把未量化填0，也不让“适合”暗示已证明正EV。原证据强度、报价比较和数值点估计继续各自保留。

沿用`record.json`的候选、条件、报价和模型记录，并按`decision-audit-1.0`建立可检查的视图：具体合约→支持事实→机制与支付门槛→最强反证及处理→最近替代→适配与价格价值。`football_model.decision_audit validate`检查字段、引用、条件三态、结构化合约/摘要一致性、模型适用性与数值披露等确定矛盾。缺陷须修正或局部回退，再生成真实审计结果；未运行则写未运行，不能复制`passed`。具体格式与命令见仓库`docs/decision-audit.md`；HTML自由文字仍须人工回核，不能仅凭结构化视图通过就宣称全文无矛盾。

审计程序不判断战术解释必然正确，也不自动证明证据“充分”；支持链非空只是可检查的必要信息。无模型的有据定性候选仍可适合，普通首发未知不自动变成条件，A01和无统一EV门槛保持原样。有适用不利模型结果时保留其来源、数值与采用理由，不因改成定性表达而隐藏。

使用F2接口时，正式决定正文、主卡、membership及评分导出从同一对象生成，单关/串关腿各保存四态；不手工维护多份主方向副本。影子等级旁列并独立标政策版本，不替代本节正式判断，亦不由一致性或表格完整性自动证明分级有效。

稳定性检查须保存多次**真实、独立运行**的输出，绑定同一冻结证据包、规则、模型版本及可得采样设置，再用`decision_audit repeat`比较主方向、适配、价格判词和确定规则违规。证据或规则不同不能当相同输入；复制同一份JSON不能充当重复实验。没有独立运行记录就只报告工具已实现、实验未完成。重复一致不等于正确，不以多数票强制选边，也不以赛果挑选最有利的一次输出。语义理由是否前后合理仍需回查原文。

## 十三、不确定性与适度的敏感性检查

### 13.1 分清三种不同问题

参数误差反映模型估计不稳；阵容分支反映当时未知事实；未来先丢球、红牌等是比赛路径。它们不能都当作同一个“最坏概率”相加扣减。模型已经整合的正常波动和尾部，不重复追加同名风险。

定性分析优先检查与本场最相关的1—2个替代情景；这不是最多只允许两个重要风险，若确有更多实质冲突应如实披露。情景由事实决定，不为每场机械列红牌、点球、爆冷大全。

### 13.2 什么叫“合理敏感性”

范围来源可以是已估计的参数误差、历史同类条件分布或具体人员分支；方法和范围须说明。任意λ±10%只能称假设演练，不能称95%区间或经验证压力。

无模型时问：“换成这个有现实依据的人员/节奏条件，哪条支撑仍在？当前票还要求什么？结论会怎样？” 不生成假的数值区间。未知情景权重既不默认各半，也不默认最坏分支必然发生。

### 13.3 中心与分支怎样影响决定

普通波动不自动否决。若一项具体现实变化会使主队仍强却不再支持−1.25，那是该票的关键条件；若所有合理安排下主要支持保持，可评当前适配。若优势只存在于未确认的最乐观安排，不能给无条件适合。

量化时先固定情景集合与分布，再计算中心及敏感性。未来极端路径的条件EV不要求普遍为正；常见、依据充分的温和变化反复消除优势，则价值应标不清，必要时改变适配。有限情景最小EV不是收益下界保证。

后验/重采样参数不确定性要对完整比分分布积分，不只是先平均λ。阵容分支权重未知时，条件中心、价格和适配绑定该条件，不能当当前无条件预测。保守全分支达标政策仅按第十一节事先选择。

## 十四、滚球单场按独立状态流程处理

### 14.1 先锁定快照再分析

按顺序取得：当前比分、分钟/补时、人数、VAR未决情况、仍在场人员与换人、近期机会信息、当前合约与报价时点。报道或画面可能有延迟，记录实际观察时间。这里的状态对齐要求报价适用于已核快照，不要求三市场同一分钟更新。仅变化时间不同不自动失效；已发生进球/红牌等重大状态变化而采用价适用性无法确认时，给历史快照或条件分析，不能说仍适合当前新增票。

当前比分影响后续打法与概率，但在用户限定的剩余亚洲让球里不算已经获得的净胜球。先按第十节确认这张票是剩余让球、累计总球还是剩余总球，再讨论方向。

### 14.2 场面怎样进入判断

先看双方还能怎样创造和限制机会，人员/比分状态是否改变赛前机制；再看近期xG、射门和禁区威胁。控球、进攻次数、近5分钟射门不能独自线性外推。两次险情不自动证明整场趋势已反转；重大人员与状态变化也不能被赛前名气压过。

有适用实时模型时计算剩余比分分布；没有时仍可在状态对应且资料充分的前提下（不强求报价时间相同）作定性方向与适配，数字未量化。状态不清是当前票判断缺口，无实时模型只是数值能力缺口，二者不混同。

**证据窗口与所选票必须匹配。** 80分钟时的判断需使用当时已发生且可同步取得的状态；事后检验其末段机制时，用80分钟后至实际终场的事件。全场射门、控球或xG可作背景，不能替代这段窗口，也不能把80分钟前已离场球员写成末段正在发挥作用。“未首发”不等于截点仍未上场；截点与换人在同一分钟时核事件顺序，不编秒数或猜在场名单。窗口资料缺失就保留未知。

例如新客队剩余＋0.25，在剩余比分0—0时半赢，并不要求客队形成压制或追平原全场比分。应检查“不再比对手多丢球”的支持与反证，再看价格；缺少进攻占优证据不单独否定此票，最后没再进球也不证明事前概率已经估准。

### 14.3 实时模型的边界

可估计状态依赖进球强度r_H(u,S_u)、r_A(u,S_u)，剩余主队进球均值形式为：

$$
E[X\mid I_t]=E\left[\int_t^T r_H(u,S_u)\,du\mid I_t\right].
$$

完整分布还需状态转移递推或模拟；进球、人数和未来换人会改变后续强度，补时终点T也不必固定。赛前λ×剩余分钟比例只是强假设基线，不能包装为完成了状态模型。[R10]

相关文献中Titman等使用赛前赔率代理实力；沿用该输入应标MIX，只借状态结构并不自动得到已训练的纯非赔率模型。[R11] 赛前模型通过验证不等于滚球已通过。

### 14.4 发布后如何更新

进球、VAR、红牌、关键换人、盘口范围或接受起点变化后重核。新票与旧票分别记录；若没有用户确认接受价和比分，只能评价公开快照，不能推定成交。未安排自动服务时仅按请求更新，不声称一直监控。

必测例：接受时主队1—0，新主队−0.5，终场1—0或2—1均全输；终场2—0时新−0.75半赢、−1.25半输。实际合约若不是剩余让球，不套这些例子。

## 十五、串关适配的边界与按需整单分析

默认单场任务只给第十二节适配，不要求整单价格、其他腿或资金方案。解释该腿是否依赖大胜、高节奏等单一机制，说明半赢、走水、半输如何改变支付。其他腿未知时不编相关系数。

只有用户提供或明确要求完整组合时，再核对平台真实组合价、每腿合约和状态、共同因素及整票规则。不能把各平台单关最佳价拼成实际串单。各腿适合不自动证明整票价值；条件适合的腿不默认已满足条件。

若平台允许标准拆分乘积，各腿返还B_i∈{O_i,(O_i+1)/2,1,0.5,0}：

$$
R_{\rm ticket}=\prod_iB_i-1.
$$

一腿半输、另一腿1.80全赢，整票净亏10%。单腿走水可能减少有效串数，半赢降低倍率，半输并非只少赚一半。特殊同场组合、促销、作废、费用和重定价按实际支付函数处理。

整票概率要有联合分布。独立、无走水或半结算且无额外费用的纯二元例子，可以将各腿获胜概率相乘得到整票盈利概率。五态合约即使独立，各腿全赢概率的乘积也只表示全腿全赢事件；整票盈利概率须按完整支付枚举或模拟。同场处理共同比分，跨场核查共享因素与模型误差；不足时只给有明确独立性假设的参考或定性组合审查，不造整票EV。

组合任务才列最弱腿、依赖与去掉一腿后的变化。对冲、提前兑现和反向补单重算全部支付及成本，不自动创造优势；金额管理仍由用户决定。

### 16.3 输出长度与底稿完整性

正文必须足够说明结论、三市场、关键事实/阵容、反证与条件。哈希、已记录的赔率历史、完整模型矩阵和长计算日志放可追溯底稿；主方向和关键缺口不能藏在附件。用户要求详细分析时展开机制，用户要求简短时压缩文字但不省略会改变推荐的条件。

内部底稿至少含§25的适用字段。模型未取得、没有截图或未声明执行时，相关块标不适用或未知并附理由，不能为了填满模板制造日志、图号、模型或订单。

### 16.4 条件写法示范

以下仅说明表达方式：如果某主要创造角色的不确定性只影响赢两球而不改变基本获胜支持，应分别评价主胜和深让。主胜可以维持当前定性适配；深让列明“该角色被可靠信息支持可承担所需任务→重新核该线和价格后评估；不满足→深让不建议；未知→保持条件，不视为已触发”。不能泛写“等全部首发”，也不能预设有主力缺席仍应推荐。

条件价格没有独立概率依据时，可以绑定真实参考合约与价格并写“变化后重评”，不得把参考价改名为数学最低买价，也不得将原文“0.99可取得”概括成没有定义的“0.99附近”。

### 16.5 日常交付：HTML阅读报告＋ZIP累计归档

**适用默认：**用户请求比赛分析、临场/滚球更新或赛后复盘，且环境支持文件生成时，交付一份可直接阅读的HTML及一份本场ZIP。聊天先给结论、原方向的结果/适配、最重要缺口与文件入口；不在回复中倾倒全部机器记录。用户明确指定MD、PDF等时服从指定格式，并保留同样的证据职责；无HTML或打包能力时可用MD/正文回退，说明实际完成范围。

| 交付对象 | 内容及职责 | 完成标准 |
|---|---|---|
| 阅读报告（默认`report.html`） | 当前分析/复盘、原版本时间线及可跳转原文；原判断与事后评论清楚分区 | 正文结论、条件、报价性质、模型状态、结果及重要缺口独立可读；无脚本/CDN依赖也能阅读主要文字 |
| 累计ZIP | 报告、结构底稿、清单、实际可得原件和真实执行材料 | 下载一份ZIP即可取得本次已归档内容；原始赛前、r2、滚球、复盘分别保留，不用摘要替代全文 |
| MD（按需） | 文字编辑、差异比较、用户要求的合并稿 | 不强制每场再做一份与HTML重复的主报告；原本已有的MD作为原件保留 |

ZIP中的阅读报告应与单独交付HTML逐字节一致。HTML主文本可单独阅读；原图与大型记录可用包内相对路径，注明“查看附件请解压ZIP”。如生成内嵌图片的另一预览版，必须明确标为派生预览并在清单记录，不能声称两版相同。报告无须塞入全部原图和矩阵；包中通过稳定标识定位即可。

赛前首次建立包；每次更新递增报告版本及包版本，累计纳入本场已取得版本。赛后短指令同时授权完成本场归档整理，不再问用户是否合并。只使用本会话已取得或本任务可合法读取的资料；不能假称能调取其他对话或缺失附件。缺少旧版就标“部分归档”，保留可得部分与最小补件清单。没有实际命令运行就没有运行日志，不为凑目录制造空成功文件。

阅读报告和JSON应引用同一组已核记录，先核事实再生成两种表达；发现差异先修派生文本/结构映射并留更正记录，不覆盖冻结原件。底稿是索引和核验辅助，不因写有`passed`就成为独立执行证据。真实命令、输出、退出状态、输入文件与指纹链按§2.3及§25留存，确未取得则写明。

## 十七、有效期、条件和报告版本

### 17.1 一次发布锁定什么

最少保留：比赛与报告标识、框架修订批次、发布及分析截点、主方向完整合约、报价来源和时点、适配、证据强度、收益价值、主要支持/反证、生效条件、缺项、实际使用的数据/模型记录、原报告位置。有模型时追加固定状态提交、真实比赛ID、模型/预测/验证路径、本次复核及盘口计算输入/输出；不能仅留下随每日更新变化的分支链接。

这是分析者的底稿要求，不让用户先补多年历史日志才能获得单场分析。可以持久保存时保存原文；无法保存时说明记录范围，不承诺下次能自动调取。用户未提供金额、票据、其他腿时记“未提供”，不填0、不假设成交。

### 17.2 何时需要重新评估

| 新变化 | 当前处理 |
|---|---|
| 普通预计轮换已在主要/替代情景覆盖内 | 检查是否仍符合原条件；不因正式名单出现就必然推翻 |
| 关键角色或组合超出原预计 | 回到人员→机制→具体合约；可只改变深盘/总球，不必整场同向变化 |
| 只有同一合约赔率变化 | 重新比较价格并更新可计算EV；原足球方向可保留，原收益判断不能照搬 |
| 盘口线位、结算范围或平台规则变化 | 作为新合约重新映射支付，不能只改报告里的一个数字 |
| 球滚动中的进球、红牌、时间、换人或有效报价变化 | 更新整个实时快照及相关推断；旧截图不称现价 |
| 出现原资料重大错误或更可靠冲突事实 | 明确纠错，说明受影响结论，保存原版本与更正版本 |

不统一规定所有赛前分析几分钟后失效。有效性取决于引用事实是否仍成立、合约/价格是否还对应当前场景；盘口移动也不等于已有某种“内幕”。

变盘解释按固定顺序写：“观察到[哪家公司、哪一行、何时变线/变价] → 原因[已核实新信息／原因未明] → 新合约在[临界赛果]下的支付变化 → 新线、新价与当前基本面下的判断”。只有同一合约价格改变时，不虚构线位保护变化。

低水不能定位“庄家防刚好2球”等精确比分概率；浅盘/未升盘不单独证明强队不强；多家同步也不证明资金意图、内幕或必须跟随。它们可触发定向核查，不能独自产生永久方向规则。变线的两个支付例见§7.3、§8.3。

### 17.3 更新和执行须分开

每次用户请求更新或实际获得新资料时，追加r2、r3，写明“新增事实→影响机制→方向/适配/价格变化”。不得覆盖原预测，也不能事后选打中的一个版本作为当初唯一推荐。

分析报告不是已买票据。用户明确确认本场已买后即可登记“已执行”，合约、价格、金额等字段不全则保留缺口。完整合约及必要比分起点支持核结算，真实赔率支持单位本金收益率，真实金额支持金额收益及总体实盘ROI；缺金额不推定未买，也不拿单位模拟代替实盘金额。用户只说“我买串关”本身不证明本场已买。没有明确设置并运行的监控任务，不承诺自动追踪首发、到价提醒或实时撤回。

包版本（`package_revision`）与报告版本（`version_id`）分开：同一旧报告被装进新包不会变成新预测；仅重排版、补来源或赛后纠错也不回写原发布时间。通过父版本和原字节指纹保留链路，见§25.4—25.5。

### 17.4 条件三态与报价、执行分别管理

每个关键条件填写：原文、影响的合约、可观察事实、来源、当前满足/不满足/未知、核实时间、满足动作、不满足动作、未知动作、确认时有效的线位/赔率与适配复核。只记录会改变当前具体票的关键条件；普通风险保留在失手路径，不机械转成等待。

- **满足：**实际证据已取得，另检查当时合约/报价和其他关键事实，生成确认记录或新版本；不等于用户已经买入。
- **不满足：**执行预先写明的换票/不建议/重评动作；原报告和此前是否曾满足分开保存。
- **未知：**不推定满足或不满足，也不在复盘填0收益；保持相应条件状态。若条件本身无法观察或没有明确动作，返回§12重新判断，不能用空泛条件掩盖依据不足。

原报价、条件确认时有效价、实际成交价分别保存。参考价没有独立概率依据时不改称数学买入阈值；“0.99可取得”不能转述为无定义的“附近”。若没有依据设数值容差，直接说明哪种变线/变价需要重新评价，不硬凑百分比。

首发赛后被证实、最终比分命中、用户曾说喜欢串关，都不能证明当时条件已确认或本场已执行。用户明确确认已买可登记执行，缺金额只限制金额收益；具体字段不全分别留缺口。

### 17.5 时间、纠错与摘要保真

首次完整报告是主观察版本；收到时间、分析截点、发布时刻、报价变化时刻、模型复算、条件确认、实际接受分别记录。拿不到精确时刻写未知，不拿07:02:20这样的复算时间代替首次发布，不凭“早于每日任务时间”认定赛前。

F2包内的冻结开始、冻结提交完成和阅读制品生成时刻由实际操作记录；真实发表、用户收到和实际执行另存追加事件。只有制品生成证据时，不据此填写后面三项；追加事件不改原决定，条件变化须重新评估并另建实质更新版本。

摘要和台账必须回对原句的方向、线位、价格、范围、适配及条件强度。发现二级摘要扩宽原条件时，保存原摘要并追加更正，而非回改原报告。读图或数字错误留原值→正确值→依据→时间/版本→影响范围；即使本场终局下两张票同赢，也检查临界比分差异。只有文字错误时不扩大为模型算法错误。

## 十八、复盘：先结算原票，再检查原判断

### 18.1 固定复盘顺序

0. **核比赛状态与复盘范围**：先确认请求时比赛是未赛、进行中、完赛、延期或中止。未赛只能审赛前流程，进行中只能阶段复盘；已完赛且结果可取得，必须结算原票后再审方法。结果暂不可得时写“部分流程审计，赛果未核”，指出待完成项，不称完整赛后复盘。延期/中止按实际合约规则，不凭比分擅自结算。
1. **锁原文**：先找到赛前/当时报告、完整合约、原价性质、条件和适配。同步记录原图可看、仅有文字转录或原件不可得。缺原文时只能做事后比赛分析，不重建一个“当时本该如此”的推荐；找不到被批评原句，就不能说原作者作过该判断。
2. **核结果并独立验算**：优先读取对应范围的官方结果，核比赛身份/字段；官方正文不可得时可用可信媒体或完赛数据交叉核实并明确非官方级别和缺口。记录来源及核查时间；滚球按原接受时点映射。按原合约算全赢/半赢/走水/半输/全输。原主方向、原明确备选、原已列比较报价及赛后新增比较盘口分别按各自线位重新算，不因原票算对就默认比较票也算对。无原图只审转录一致性，不宣称读图已正确。
3. **分执行性质**：有有效原价可算原方向单位模拟净收益；条件策略使用触发时经核实价；明确确认买入即可登记执行，实际价格支持单位收益；金额有据且完整才汇总金额收益和总体实盘ROI。无有效价格可评结算状态，不编ROI。
4. **核命题及证据窗口**：逐项摘录原支持机制、最强反证和阵容假设，保留当时语气、条件及作用时段；用匹配窗口的证据记录实现、未实现或未知。命题是否实现与是否支持某票分开，不能把非必要条件的缺失误当合约失败依据。
5. **归因**：事实/时点/合约/算术错误属于可直接修复的流程问题；正确概率仍可能失手。仅凭一场赛果不能断言概率错误或某因子无效。
6. **登记改进**：新解释先列待检验假设，进入以后时间样本验证；不因一次爆冷立刻改权重或新增永久否决规则。
7. **追加记录**：保留失败和未建议案例，不回改原方向、条件、模型、收益判词或实际执行。

### 18.2 四类集合分别统计

| 集合 | 收录对象 | 可以评价什么 | 不能混作什么 |
|---|---|---|---|
| 原相对方向观察集 | 每场事前固定主报告中的原主方向，包含不建议/条件未确认 | 方向判断、遗漏机会、是否过度谨慎；有价可作统一单位模拟 | 不全部叫实际推荐或已买策略 |
| 无条件适合候选集 | 原报告明确适合的票 | 适合筛选后的命中与单位模拟表现 | 不与全体观察集偷换分母 |
| 条件已确认候选集 | 原报告条件明确，且有进入前/赛前按政策核实的满足证据 | 条件政策触发后的表现 | 不能因赛果有利就推定条件满足 |
| 用户实际执行集 | 用户明确确认已买的票；逐项记录实际合约、价格、时间、金额及缺口 | 资料足够时核结算、单位收益率；金额完整时算金额收益与总体ROI | 缺金额不等于未执行；不把单位模拟混入真实总体ROI |

条件触发记录必须同时保存条件确认时点，以及该时点仍有效或重新核实的合约和报价、适配复核结论；取价方法事先固定，不能事后挑高价。滚球条件须在对应状态与入场之前满足，不能把赛中才出现的事实补成此前已满足。条件确认晚于原报价时，不沿用无法确认当时仍可取得的旧价计算触发策略ROI。缺少触发时可用报价，只能保留原方向结算或明确标记的原价假设模拟，不计入可执行条件策略ROI。

这四组不是互斥的四个结果类别：实际执行票可能来自前几组，报告各组时注明关系，但总利润不能重复相加。条件不满足、未核实、无法追溯是不同状态；未核实不能当作“未触发”或收益0。可将其原方向结算留在观察集，不能纳入已确认触发策略成绩。

默认主观察版本为每场首次完整发布的单场报告；后续更新另列。若要改为固定提前时点，必须在后续样本开始前登记。相同比赛多个版本按比赛聚类，不能当多场独立成功。

### 18.3 固定指标与分母

- **推荐覆盖率**：符合对应入样政策的适合票数／全部已纳入比赛数；条件票的确认状态另列，不能删除资料困难场次后声称覆盖高。
- **盈利命中率、走水率、半输率、全输率**：对应票数／同一组全部有效已结算票数。净费用改变收益符号时按真实净收益，同时保留原五态。
- **单位模拟ROI**：固定每票1单位和对应组别的既定合约、有效记录价、已知费用，净收益合计／有效投入合计。原方向观察用原价；条件触发策略用触发时经核实价；用户实盘用真实成交价，三者不互换。没有有效价格的票不填0，显示可计算覆盖率。
- **实际ROI**：真实净收益合计／真实有效投入合计。实际串单按整票投入与结算计算，不把每腿各算一次投入后与整票利润相加。
- **平均赔率、收益集中度、亏损幅度与连续亏损**：按相同策略/组别说明；实际金额未知只能作单位模拟，不能报告用户真实回撤。
- **CLV／收盘价比较**：仅在同事件、同合约、可比费用和固定截止政策下比较；变线不可直接比赔率比值。它是价格诊断，不能单独证明真实盈利优势。
- **概率评分**：仅使用当时真实给出的数值预测。没概率不填0，也不事后从结果补造概率。

一个“不建议”方向最后赢了，不足以证明过度保守；一个适合方向输了，也不足以证明框架无效。观察连续样本中被排除原因、机制质量、报价和分组表现，才能评价取舍。

### 18.4 可直接填写的复盘模板

**比赛状态与完成度**：[未赛/进行中/完赛/延期/中止；状态来源与核查时间]；[完整赛后复盘／阶段复盘／部分流程审计]；[尚缺什么、影响哪项结论]。  
**原件可用范围**：[原分析全文/摘录/缺失；原图可看/仅有转录/不可得；本次实际回图范围]。  
**原报告**：[版本/截点；原主方向、线位、范围、价格及性质；适配；证据；原条件原文]。  
**条件与执行**：[事前条件有无满足证据及时间；触发时有效报价；实际买入是否确认及字段缺口]。

**先完成逐票结算**

| 对象及性质 | 准确合约／报价性质 | 对应结果及来源／滚球起点和增量 | 结算拆分与五态 | 单位净收益及口径 |
|---|---|---|---|---|
| 原主方向 | [原票，不改选] | [范围匹配结果] | [每半注独立计算] | [有效价可算；否则仅报结算] |
| 原明确备选（确有才列） | [当时明确作为替代的原句位置] | [对应结果] | [重新验算] | [不替换原主推成绩] |
| 原已列比较报价（确有才列） | [原报告实际比较/计算过而未推荐；纯图中可见历史不自动列票] | [对应结果] | [重新验算] | [仅比较；不升级为备选或推荐] |
| 赛后新增比较票（确有才列） | [明确事后假设；报价可得性] | [对应结果] | [重新验算] | [探索性，不能记成原推荐收益] |

例：总球3时，小3走水、小2.75半输；这句话只比较支付，不证明小3事前更有价值。原价、触发价、实际成交价分别计算，不用最有利价回填。所选队直接获胜时，不能由＋0.75获利就说受让保护优于主胜；本场结果未落在保护差异区间。即使落在该区间，也只确认本场支付差异，不证明长期策略优劣。

**再检验原命题与机制**

| 原句或精确位置／当时语气和条件 | 作用事件、所需结果与时段 | 当时依据 | 匹配的事后证据及来源 | 实现／未实现／未知 | 对流程/模型的启示及不能推出什么 |
|---|---|---|---|---|---|
| [保留“可能”“若”等限定] | [如余时不多丢球，而非必须扳平] | [原资料] | [时段、人员、比分/人数状态匹配] | [无过程资料则未知] | [是否必要条件；一场不能证实概率] |

不能把“可能影响后段体能”改成“预计必然崩盘”，把“压迫破坏出球”改成“必须转化进球”，把“优势尚未确认”改成“曾宣称有正EV”。原报告已有时间戳或制式转换时，应先核原字段，不能为批评流程而虚构缺项、早期版本或并未给过的价格阈值。

机制检验对应原句声称的环节：压迫是否破坏出球，观察出球困难、危险区丢球或相关压迫表现，不能只看有没有进球；休息差可能影响后段，不能仅以某个后段进球证明体能影响不存在。缺匹配证据就记未知或仅与结果相容，不强行验证因果。

统计范围与命题对应：末段用原截点后的事件；全场统计只作全场描述。赛后xG反映已形成机会，不等于赛前净胜幅度分布。人员变化、红牌、伤退、领先后策略分别标在时间线上，不混成常态实力证据。过程证据不足记未知，终场输赢不能代替机制是否发生的证据。

**错误与改进**：[已确认的事实/时点/合约/算术错误直接修复；原版保留，并记录受影响结论]。  
**探索性替代**：[有无赛后新增方向、方法、假设；与原方案差异；按18.5登记]。  
**入样**：[可追加哪些观察/候选/执行组；概率来源资格和缺失字段；未确认条件不计已触发]。

### 18.5 赛后新方案单列，原记录不清洗

赛后换方向、换报价来源聚合、换去水/拟合方法、加新因子或重排候选，必须登记：提出时间、原政策、新政策、所需资料、新增假设、哪些资料当时可得、是否已接触结果。这可以是同资料下的探索性反事实，不能称为恢复了干净赛前预测。

保留全部原报告与错误数字，旁注更正、原因及可评价范围；失配数字不再支持当前判断，但原发布记录不能删除。按事先固定且对输赢对称的来源/验证资格分组，披露排除原因、数量与覆盖，不依据输赢清洗样本。合法但来源标错的概率可另列原始表现与来源错误；概率非法或无法复算的记录标不可评分，不填0，也不从全部请求和流程审计中消失。赛后才提出的新资格规则另作探索，不冒称原验收政策。符合旧1.4不代表旧政策最优；新1.5允许定性适配，也不追溯把旧三级改成推荐。

结算硬错误立即修复。涉及一般方向、权重或筛选政策的新主张按§19.5后续检验，不把单场失败变成“无模型必须顺盘”“德比固定受让”“必须删失败比分”等永久规则。只有事先明确启用的自动监控才有对应自动更新承诺；没有任务时，不因首发出现后未自动发r2就判违约。

### 18.6 GPT复盘结束前必须给出的状态

按顺序确认并分别报告：①原文/版本读取范围；②比赛完成状态与常规时间结果证据级别；③原方向、原明确备选、原已列比较报价、赛后新增比较的独立结算；④相关价是原参考、触发还是实际成交；⑤原条件确认状态与用户执行状态；⑥原命题对应时窗的证据；⑦问题分类、修正及候选登记。

结算复核可以完成而机制因果仍未知。没有本场有效价时仅报告支付状态；旧0–0价不能移给1–0新状态。仅有原参考价时明确标准合约/费用假设，不把假设单位收益写成实盘成绩。条件适合、不建议、暂无法判断组不得因终局命中而升级；一个比赛多个版本不增加独立场数。

分类使用：已有规则未执行、已确认事实/读图/算术硬错误、规则遗漏或文字歧义、已定位模型/工程问题、待验证方向/权重/筛选假设、证据不足。一个问题可有多类，但说明哪层已证实。失败赛果本身不证明流程错，复算通过本身不证明模型好。

### 18.7 报价角色不能升级成原推荐

| 角色 | 识别依据 |
|---|---|
| 原主方向 | 首份完整报告明确选定，并保留其原适配；只有滚球报告不造赛前主票 |
| 原明确备选 | 当时文字明确作为替代、次选或备选的具体合约 |
| 原已列比较报价 | 原报告实际引用并用于比较/计算、但未推荐的合约；不能统称推荐备选 |
| 赛后新增比较票 | 当时决策未列、赛后才提出的合约，用于诊断或研究 |

原主方向、各市场原代表、原明确备选和实际参与原判断/计算的比较票逐项结算；不因图上可见135行就把135行都升格为原候选。纯历史变化行保留原图/底稿，只在影响判断、纠错或研究某段走势时核算。赛后从原图另选出的票记“赛后新增比较”，不能补进原推荐成绩。

同合约多公司报价可以分别复算，不能计为多场或多次推荐。本轮新增计算与原复盘已有结算分别标记，只对真正重合的原项报告对照结果。无价合约可判支付状态，净收益留缺口；参考价计算注明费用假设，不当实际利润。原始分析的原方向、适配和执行集合不随这些比较项目增加而改变。

### 18.8 短指令触发的标准赛后复盘

用户说“**搜索一下赛果，反思一下，分析框架有什么可以优化提升的地方**”，或同义表达时，默认执行本节全部适用步骤。用户无需再说“套模板、合并原分析、保存证据、登记审计”。用户仅查询比分或明确限定不归档/只做某项时，遵从本次限定，不擅自扩成完整复盘。若本对话无法唯一识别比赛，先自行核现有材料，仍有歧义才询问比赛；不默选同名的另一场。

## 十九、怎样验证框架是否真正改善预测

### 19.1 分别验证流程、预测和收益

流程清楚不等于概率更准，概率评分更好不等于当前买价正EV，单腿正EV也不自动证明未知串单的联合收益。分别记录：

1. **流程质量**：对象、合约、资料时点、反证和条件是否清楚，是否出现事实/计算错误。
2. **预测质量**：同目标概率评分、校准、分辨能力及覆盖；没有数值时审查可证伪机制和连续分组表现。
3. **策略结果**：按预设入样、条件和价格政策计算单位模拟/实际收益，展示风险与误差。

不把某次回复写得更长、更像数学论文或多引用一个模型，当成准确性提高的证据。

### 19.2 同场同截点的配对比较

预先保留下列候选；它们输出对象不同，只比较共同任务：

| 对照 | 用途 |
|---|---|
| B0 简单联赛基线、赛果Elo等 | 判断复杂模型是否超过低成本基准 |
| B1 历史比分＋主场＋对手的攻防模型 | 判断基本建模是否可用 |
| B2 在B1上逐项加入xG、阵容、赛程等 | 判断每项信息是否有增量；同时做去掉该模块的对照 |
| MKT 同截点固定来源/去水方法的市场基准 | 判断模型是否提供市场之外的信息 |
| B3 经过验证才启用的融合 | 判断融合是否改善对应任务，明确它包含市场 |

样本、时间、目标和数据可得性一致。不能用提前10小时的基本面模型与临场收盘市场比较后，将差异全部归因于模型；收盘可另作价格诊断。也不能让一个方案看到官方首发，另一个只看到10小时前预计名单，再声称只比较算法。

### 19.3 时间验证与概率评分

按时间训练→验证/调参→未见测试，或使用事先确定的滚动起点。特征窗口、标准化、球员评级、缺失处理、参数选择、校准和融合权重全部只用当时以前的数据。测试集上看完结果后改规则，需要新的后续检验区间。

多分类Brier采用不除以类别数的固定版本，对数损失用自然对数：

$$
BS=\frac1N\sum_i\sum_{c\in\{H,D,A\}}(p_{ic}-y_{ic})^2,
\qquad LL=-\frac1N\sum_i\log p_{i,y_i}.
$$

两者越低越好。原预测某结果概率为0而实际发生，对数损失为无穷；数值处理事先固定并保存原概率，不在赛后平滑美化。[R12]

检查总体和联赛、市场、深盘、杯赛、预测时点等相关分组，显示样本与不确定性。样本不足以比较则如实说不足。相同比赛多时点不是独立样本；误差评估需保留比赛内及必要时间依赖。不同盘口五态只在同合约/同目标上作可比评分，不能把不同难度混合排名。

如计算差异区间，说明采用的重采样/时间分块方案与前提；没有实际计算就不宣称“统计显著”。模型校准好也不能证明未验证的比分尾部准确或投注盈利。

### 19.4 初期如何验收，怎样识别过度保守

首批连续30场可用于流程验收：身份、合约、算术重大错误目标为0，概率溯源、基本面作用、条件和版本完整。这个数量是项目操作约定，不是有效性样本门槛。入样政策在结果前固定；出错保留并修复，不删掉重凑完美批次。通过不自动评为M高。

检查以下两端，不设“必须推荐多少场”的配额：

- 如果经常仅因没有模型、缺xG、普通首发未公布或未提供其他腿而等待，违反本版的默认单场任务边界，应修复流程。
- 如果经常只靠球队名气、低赔率、重复利好就给适合，或无视具体盘口门槛与反证，应修复依据。
- 如果很多票已支持赢家但不支持净胜幅度，优先检验是否选错合约，而非把所有球队判断判为错误。
- 比较旧保守门槛与本版平衡政策时，用事前固定的同一后续比赛和可用价格；分别展示覆盖率、命中、收益与风险，不能只挑某一项宣布胜出。

v1.5修订批次5曾使用的12个分享对话、此前已接触案例及本次32场审计材料，只用于探索和发现流程问题，不作为据此改版后的独立成功证据。收益优势需要与样本覆盖、误差和执行条件相称的证据，不规定达到某笔数就能获利。

### 19.5 新政策怎样进入后续验证

1. 结果出现前固定版本、适用联赛/市场/预测时点、所有纳入比赛的规则、报价选择、条件触发和原主方向记录方式。

5. 不把缺值填0、不删除失败/不建议场次；汇总显示适用分母、未知、未查和排除原因。同一问题的频次是诊断线索，效果改善仍按§19.2—19.5验证，标准化文件本身不构成验证。

### 19.8 真实预测账本、生产回放与三市场评分

第4项工程验收分三个对象，互不替代：

| 对象 | 输入与执行 | 允许得出的结论 |
|---|---|---|
| 生产策略开发回放 | 冻结历史输入/原API响应、数据观察时点与时钟轨迹，复用实际生产更新入口及其训练、沿用、过期和拒绝逻辑；与每日重拟合研究另列 | 策略行为能否重现、历史开发比较；补抓或事后取得的数据不能冒充当时快照，不称前瞻 |
| 真实保存预测评分 | `football_model.prospective --runtime runtime --config config.json`读取真实本次运行并追加独立账本；原预测冻结，赛后只追加核准常规时间结果与评分 | 对合格赛前已保存预测的概率表现；报告发布与用户执行另有记录，不能由后台预测推定 |
| 报价与收益验证 | 预先固定合约、截点、报价来源、选票与1单位规则；有真实合格报价才登记模拟，真实成交另留证据 | 对该记录规则下的单位模拟或实盘表现；缺赔率不能声称已检验收益优势 |

账本按协议及其指纹分区；同一比赛的首个合格赛前快照作为该协议主评分版本，后续更新另留，不挑赢家版本。所有实际生成行、`unsupported`、失败和无预测原因保留；任务在产物生成前中断等未被账本捕获的范围，由运行记录和Actions核查补明，不能把账本存在当作全体请求完整覆盖。正式评分须核比赛/主客身份、真实保存/预测时间、赛程与最终常规时间比分；缺证据、延期、结果冲突或不可评分项单列，不填0。结果修订追加记录，不能改写原概率。

胜平负使用原三项概率；让球、大小球使用同一原比分矩阵映射到**事先登记的具体线位、方向和结算范围**，按同合约五态评分及分组校准。固定研究线与实际采用线分开：未登记或无真实报价的线不能称已验证当时实际市场。结构上不可能出现的五态不计作“预测正确”或校准优势，例如大2.25不存在半赢及走水；报告真实可行状态、每组/每箱样本与未评分数。不得因评分程序支持任意线位，就声称所有线位质量已验收。

与简单基准比较时，只比较同比赛、同目标、同截点资格且均有有效预测的共同覆盖；新增/缺失覆盖另列。无法将基准绑定原训练数据指纹时保留缺口，不拿今天的训练样本回算过去的“当时基准”。1X2市场去水须同源同截点完整三项；亚洲盘两项赔率不能唯一恢复五态市场概率。没有市场报价时只报告模型与可用简单基准比较。

程序的报价登记只建立明确的固定单位**模拟记录**，不代表用户已买、自动抓价或已运行自动选票策略；报价准入中的实际登记时间、开放证据和其他限制以相应协议为准，不把它们提升为日常定性推荐的新门槛。缺报价不阻断概率评分，缺概率不补造EV。真实本金/成交不足时不报告实盘ROI。

仓库`docs/prospective-validation.md`及`docs/production-replay.md`记录实现范围、文件位置和命令；运行前核实际版本。真实生产运行可用`football_model.cli --record-replay`记录重演包，离线入口为`python -m football_model.production_replay --bundle PATH --output-dir NEW_DIR`，只重演实际已录制输入，不联网补齐旧快照；原失败重演匹配也不等于业务成功。回放产物标为研究并不得进入前瞻账本。

评分采用数值地板时，应披露其值、保存未裁剪原概率，并分开报告原零概率对应实际结果的事件；该情形的数学对数损失仍按§19.3为无穷，有限的稳定计算值不能掩盖它。工程测试、开发回放、未来概率表现、GPT决策稳定性、收益验证分别报告。校准器、模型权重及新筛选规则仍须先在过去数据拟合、再在后续样本验证；本批不凭一次评分修改原模型，也不承诺在固定场数或期限内证明增益。

### 20.1 方法选择与实施优先级

“有研究基础”表示可以作为合理方法候选，不等于本项目已经实现该候选。下表保留技术路线和优先级，不是文献证明的唯一最优组合。已读历史基础模型为独立泊松；Dixon–Coles、动态分层、xG、球员和滚球扩展不能凭设计自动计入能力。当次若另有真实实现与产物，按其模型卡和相应验证核验，不由旧登记排除或自动认可。

| 模块 | 量化什么 | 最低资料 | 本版定位与限制 |
|---|---|---|---|
| 带正则化与时间权重的攻防泊松/Dixon–Coles | 球队攻击、防守、主场、对手强弱及低比分相关 | 连续历史比分、主客及日期 | 首选比分基线；参数须拟合，不能从本场赔率反推后称基本面模型 [R1] |

| 历史xG/npxG增强 | 机会创造与防守过程，而非只看终结结果 | 口径稳定的过去比赛机会数据 | 优先增强候选；xG不是下一场进球，也不保证优于市场 [R4,R5] |
| 赛果Elo＋结果概率模型 | 对手修正的相对实力 | 日期、赛果、主场 | 廉价对照；原始Elo预期得分不是主胜概率，不能单独推出大小球 [R6] |

先做一个能完整复现的基础模型及简单对照，再逐个增加特征。多模型共享数据并不等于多份独立证据；不靠投票数量或模型名字提高可靠度。

### 20.2 从历史比赛拟合攻防强度

对比赛m，主队i、客队j，模型规格可写为：

$$
\log\lambda_{H,m}=\mu+\eta I_{home,m}+a_i-d_j+\boldsymbol\beta_H^\top z_m,
$$
$$
\log\lambda_{A,m}=\mu+a_j-d_i+\boldsymbol\beta_A^\top z_m.
$$

其中a为攻击、d为防守（越大防守越强）；中立场的主场指示为0。联赛/赛季基线、不同主客效应或时变参数属于可检验扩展。设定如Σa=Σd=0等识别约束。所有z只包含截点前已知特征，标准化参数仅由训练段取得。

训练赛程须有足够的球队间连接，才能区分自身与对手实力；互不相连的联赛或组别不能仅靠上述约束获得有数据支持的相对强弱。跨组比较需要连接比赛或另行估计并披露的层级转换。

基础版本先令z为空，直接估计球队攻防及主场参数。采用加权对数似然加正则项，例如：

$$
\hat\theta=\arg\min_\theta\left[-\sum_m w_m\log P_\theta(H_m,A_m)+\kappa\|\theta_{pen}\|_2^2\right],
\qquad w_m=\exp(-\xi\Delta t_m).
$$

正则化通常作用于需收缩的攻防和特征系数，不应不加说明地惩罚所有截距。时间单位、权重是否归一、惩罚尺度、窗口、\(\xi\)、\(\kappa\)及估计约束必须固定并记录；超参数在训练/验证段选择，不根据目标比赛的赛果调整。不规定通用“近6场占60%”。

上述是本版建议的实现规格，综合已有方法形成，不声称全部细节来自某一篇论文。没有历史数据和拟合输出时，只能称模型规格，不能手填λ并评为M中（见9.2）。

### 20.3 联合比分分布与Dixon–Coles修正

独立泊松基线：

$$
\pi_F(h,a)=\operatorname{Pois}(h;\lambda_H)\operatorname{Pois}(a;\lambda_A).
$$

Dixon–Coles在低比分处使用乘法修正：

$$
\pi_F(h,a)=\tau(h,a;\lambda_H,\lambda_A,\rho)
\operatorname{Pois}(h;\lambda_H)\operatorname{Pois}(a;\lambda_A),
$$

$$
\tau=\begin{cases}
1-\lambda_H\lambda_A\rho,&(h,a)=(0,0),\\
1+\lambda_H\rho,&(h,a)=(0,1),\\
1+\lambda_A\rho,&(h,a)=(1,0),\\
1-\rho,&(h,a)=(1,1),\\
1,&\text{其他比分}.
\end{cases}
$$

ρ必须估计，并保证训练和预测状态的概率合法；不得出现负概率后静默截成0。ρ=0回到独立泊松。低比分修正不自动解决红牌、深盘尾部和阶段变化；是否使用双变量、混合或状态模型由相关样本验证决定。[Dixon–Coles原研究](https://research.lancaster-university.uk/en/publications/modelling-association-football-scores-and-inefficiencies-in-the-f/)

当\(\lambda_H,\lambda_A>0\)时，每一个训练或预测状态均须满足：

$$
\max(-1/\lambda_H,-1/\lambda_A)\le\rho\le\min(1,1/(\lambda_H\lambda_A)).
$$

若共用一个ρ，应满足所涉及状态的合法区间交集；观测比分的似然不能为0。实际实现需记录约束与数值容差。新状态超出合法范围时，采用预先规定的重新拟合、收缩或回退模型方案并披露，不能在发布时随意裁剪概率来凑结果。

截断比分矩阵必须保存上限、遗漏质量与误差；不能把漏掉尾部归给有利状态，或不披露地归一化。仿真记录种子、规模与数值误差。算得更精确不等于模型更准确。

### 20.4 收缩与动态能力

正则化或分层先验使低样本球队向合理群组中心回归，减少几轮成绩造成的极端估计。群组、方差与升班转换需要数据支持；过度收缩也可能压低强弱差异。动态模型允许攻防随时间变化，但状态噪声同样需要估计，不能每次换帅直接把旧数据清零。[R2,R3]

时间衰减、随机游走、近期窗口高度重叠，不能把它们各自产生的变化再人工重复加一次“状态分”。先比较简化模型，再决定复杂扩展。

### 20.5 Elo作为对照

赛果Elo可使用比赛结果更新评级，再通过训练得到的有序或多项概率模型输出胜平负。原始预期得分相当于胜的权重加半个平局，不直接等于获胜概率；还需单独处理平局与主场参数。Elo本身没有总进球维度，不能凭两队评级推出大球概率。[R6]

若Elo使用历史赔率而非赛果更新，必须标为市场参与模型，不归入纯非赔率对照。保留这种模型的研究价值，但不能混淆来源。

### 20.6 历史xG、终结与防守过程的建模

xG估计已发生射门在给定条件下的进球概率。历史xG可帮助描述机会创造过程，但下一场还需要预测会产生多少次、什么质量的机会。不能把上一场xG或最近均值直接当作下一场λ。[Hudl说明](https://www.hudl.com/blog/expected-goals-xg-explained)

一项原始研究比较了xG和传统统计对未来表现的预测，支持将xG列为候选信息；其样本、交叉验证与胜平负分类局限不等于本项目的时间验证。不能直接照搬其窗口或宣称xG一定击败市场。[Mead等，2023](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0282295)

**首选实现步骤**

1. 使用过去比赛、同供应商的npxG创造/被创造、射门质量等，构造滞后特征；确保没有用到本场赛后数据。
2. 根据对手、场地、人数与比分状态进行可复算修正。先拟合的修正模型只能使用当时历史段；滚动特征也必须按时间重算。
3. 将这些历史特征作为20.2的z的候选输入，预测未来实际进球分布；系数与正则强度由训练数据估计。
4. 与不含xG的基础模型做同场、同截点配对测试；没有增量改进则保留基线。

连续xG/npxG不能直接当作整数进球塞进标准泊松概率质量函数。若选择连续目标回归或准似然等替代实现，须明确目标、损失和分布假设，并另验证它怎样转成未来实际进球概率。不能只因两者都叫“预期进球”就省略映射。

**终结、门将与定位球**

- 将创造机会与终结表现分开。进球减xG、扑救表现等残差在小样本下需强收缩，不因两场超额进球就推定稳定终结能力。
- 门将可研究赛后射门质量相关指标，但须对应射门面对条件、样本与供应商定义；扑救次数或扑救率不能直接变成球队胜率。
- 定位球机会与运动战机会可以分层建模；点球和红牌路径的未来发生概率须来自模型或情景，不用已发生的偶然事件直接外推。
- 同一底层射门同时产生xG、射正、绝佳机会等多个指标，不是多个独立利好。增量价值由正则化、特征删减对照与未来测试判断。

### 20.7 阵容、RAPM与相对基线的增量

“缺阵人数”不是影响量。先记录球员角色、预计分钟、替代者、阵容制度和关键位置衔接。

数据充分时，可用带正则化的片段模型或RAPM控制同场队友、对手、主客和人数状态，估计球员贡献。它需要完整换人时点与曝光时间；经常一起出场的球员难以分离，小样本必须报告不确定性。[RAPM原论文](https://arxiv.org/abs/1706.04943)

阵容特征可采用下列结构，作为需要再估计映射关系的候选，而非固定伤停扣分：

$$
z_{lineup}=\sum_j\frac{E[m_j\mid\text{当前信息}]-m^{ref}_j}{90}\,r_j.
$$

其中r为有历史依据的球员指标，参考分钟来自球队基线所代表的阵容。替代球员分钟须同步增加，总分钟和位置安排必须合理。该指标到进球强度的系数需要训练；RAPM净贡献或VAEP值不能直接当成进攻λ变化。

球队历史攻防已经包含常用阵容，不能将首发全部能力再加一次。只处理相对基线的变化；长期缺阵若已反映在球队估计中，不重复扣减。伤停与模型差异并不自动构成因果效应，球员出场选择可能受到对手和赛况影响。

### 20.8 战术、事件价值、赛程与环境

可研究压迫与出球、反击、禁区进入、定位球、边路与制空等可观察指标及对手交互。需要统一统计口径、控制比分与人数状态，并在历史数据中学习系数。不能把控球、射门、PPDA或某个阵型直接等同于胜率优势。

VAEP估计动作对短期得失球概率的贡献，可为推进与创造能力提供特征；它的预测视野与整场赛果不同，不是“某球员VAEP高，因此缺阵减几个百分点”。[作者文档](https://socceraction.readthedocs.io/en/latest/documentation/valuing_actions/vaep.html)

少量战术对位观察保留为可证伪机制：写明预计出现的信号、观察时段、反证和无法判断条件。未知样本不强行造一个“战术分”。球队高压与对手出球弱等交互项应预先提出、限制数量、正则化并验证，防止从众多故事中挑事后赢家。

**赛程、战意与环境**

休息间隔、旅行、近期分钟负荷、场地和天气可作为协变量；方向、非线性与交互需估计。拥挤赛程对伤病风险的研究不能直接推出固定跑动下降或胜率损失；单队小样本结果不普遍外推。[R9]

战意按“赛制目标→预计阵容/策略→机会分布”表达。“必须赢”“德比更拼”不直接加胜率。两回合总比分、中立场、加时安排核对官方规则。多年交锋只有当前教练、阵容或机制仍相关时才作为辅助，不压过当前实力。

### 20.9 数据清洗、目标边界与不确定性

- 统一球队/球员ID、男足女足和青年队、赛制与常规时间；中止、判罚比分、加时和点球大战单独处理。
- 小样本近期数据向较稳定的长期/群组水平收缩，不能只凭两次客场零封或四轮连胜定义能力。
- 用模型联合估计对手攻防，不能仅把近几轮进失球平均数当成本场强度。
- 有事件数据时，可建11对11片段模型并以有效时间为暴露量，另处理红牌与比分状态。不能删除红牌后的失球，却仍用完整90分钟作分母。只有全场数据时标明未充分分离状态，不能凭印象“修正掉”坏比分。
- 11对11片段得到的是相应状态下的条件强度。预测真实全场时，须有依据地整合未来红牌、点球等事件及状态转换，或在真实全场结果上拟合并验证相应比分分布修正；未完成此步骤，只能标为条件基线/敏感性分析，不能据此声称已量化真实全场的概率或收益价值。
- npxG只排除点球相关部分，仍须看供应商定义；未来总进球包含可能发生的点球。不能因为使用npxG就把点球概率设为0。
- 升班、换帅、大转会和新球员记录结构变化。跨联赛能力转换或升班先验用历史同类数据估计；无依据时加大不确定性，不直接照搬低级别数据。
- 不同供应商的xG、压迫、绝佳机会不能静默混合。缺失不当作0，样本覆盖及缺失机制需要披露。

**训练目标与条件分布不能混淆。** 使用历史npxG作输入、以未来真实全场进球作目标，与“只预测未来非点球进球”不同。若模型已用含红牌、点球的真实全场结果拟合并通过对应验证，可以由整体分布吸收这些事件的影响，不强制逐项显式模拟。若只拟合11对11或非点球片段，则必须处理从条件分布到目标全场分布的转换，不能悄悄把事件发生概率设为0。

**参数与阵容不确定性在预测分布层面整合。** 若参数后验/重采样结果为\(\theta_s\)，完整阵容情景为\(L_k\)，且相应权重有依据，先产生各自完整比分分布，再按有效权重混合：

$$
\bar\pi(h,a)=\sum_{s,k}w_{s,k}\,\pi(h,a\mid\theta_s,L_k),
\qquad w_{s,k}\ge0,\quad\sum_{s,k}w_{s,k}=1.
$$

权重应反映参数与阵容的联合关系，不能未经依据假定独立。一般而言，混合泊松分布不等于把λ先平均再代入一次泊松；两者尾部和盘口概率可能不同。将后验均值代入模型属于明确的点估计近似，不能声称已经整合参数不确定性。没有可靠阵容权重时，分别报告有依据的条件情景和敏感性，不编造等权或首发百分比。

### 20.11 从规格到可调用模型：训练、预测与交付验收

**参数是训练结果，不是要求用户先填的球队评分。** 基础版读取历史日期、主客队、常规时间进球和场地信息，用§20.2—20.3的似然/约束估计攻防、联赛基准和主场效应；低比分修正仅在实际实现并估计对应参数的扩展模型中存在，当前独立泊松不包含Dixon–Coles修正。只给所有队相同的初值不算训练完成；必须实际执行优化，保存收敛和概率合法性检查。

以下保留完整建设与扩展的实施顺序；它不表示当前系统已经逐项完成，也不是本轮更改现有训练或验证方式的授权：

1. **定范围和截止**：先选一个有连续历史资料的联赛及明确预测截点。使用赔率共存的数据文件时，对基本面输入设字段白名单；赔率留给后续市场比较，不能悄悄进入F模型。新球队、中立场及跨级别转换有预先规定的回退。
2. **清洗和分时段**：统一ID、比分范围、缺失与异常规则，按时间划训练、验证和未见测试。窗口、衰减和正则化只在训练/验证段选；同一测试段被用于改规则后，不再称未见测试。
3. **执行拟合**：由程序联合估计球队与对手参数，普通泊松作可复现基线，Dixon–Coles等作候选；优化初值、约束、目标、随机种子（如用）、收敛状态和参数完整保存。
4. **冻结并预测**：预测程序读取已保存参数、球队ID、主客/场地及截至预测时点可得输入，先生成比分分布，再按§10映射1X2、亚洲盘、大小球。模型进球均值标“预测λ”，不冒称射门事件xG。未知球队或非法概率明确回退，不静默补数。
5. **滚动验证（原扩展规格，当前工程状态另核）**：只能用每个预测时点之前的数据重训；对照简单基线和同截点市场，保存概率评分、校准、分组样本与局限。最早提前10小时使用时，价格验证对应当时可得报价；收盘价只能另作诊断。批次4形成时生产验证仍使用固定时间留出；后续研究滚动、真实生产策略回放与保存预测评分按§19.8及真实代码分别核验，自动每日更新本身不证明历史验证已经改为滚动。
6. **保存并接入**：模型通过什么范围的检验，就在什么范围按§9.2使用。仅训练成功而验证有限时可报探索性估计，不直接宣称有收益优势。增强xG/阵容前先保存基础版，逐项做增量比较。

**模型交付必须能指向实际文件和运行结果**

下列文件名保留为实现职责的示例约定，不是本项目现有文件的逐一真实名称。当前产物及运行入口见§20.12；不能为填这张表而虚构文件，也不能因实际命名不同而判定没有模型。

| 产物职责（示例命名） | 必需内容 | 验收动作 |
|---|---|---|

| `model_parameters.json`或模型文件 | 球队参数、基线/主场/ρ、训练截止、版本、球队映射 | 参数实际来自本次拟合，不是手工演示 |

独立基本面模型生成预测不需要本场赔率；计算对应价格EV才需要有效赔率。采用外部开源库也要完成上述数据、版本、拟合、合法性和验证工作；导入库成功不算模型建成。四分之一盘库接口如只返回拆注加权的win/push/lose，不能直接当作整票盈利概率，应从比分分布按本框架汇总五态。

**二、日程与索引怎样衔接**

现有训练/审计CLI在每次运行末尾更新接入索引，原来的保存流程将索引随运行产物提交到`model-state`。仅在已取得完整本地运行历史且确有重建索引任务时，使用：

```bash
python -m football_model.integration index --runtime runtime --config config.json
```

这条命令会整理已有产物并写入本地索引，不启动训练，也不证明GitHub当天已执行成功。单场任务的最小下载包应读取固定提交的原索引，不对不完整历史运行index后宣称已核最新全局状态。日程仍遵守既有“更新数据→按需训练→生成预测→保存报告”的流程。前次产物沿用、某联赛失败、没有未来7天比赛均要保留真实状态；0场预测可能是正常赛程空窗，应核实际赛程，不能强行填一场。

v1.6历史记载用户已确认开启UTC 01:17（北京时间09:17）日程；v1.7没有重设日程，也未据历史记载独立确认当前变量、排程或当日成功运行。每日是否按时触发、是否成功保存，要读相应Actions运行和状态提交。若最新任务在写入状态之前失败，旧索引尚不包含该失败，执行者必须结合Actions状态单列缺口，不能用旧索引冒充本次更新成功。

## 二十二、附录：标准结算与算术内核

以下原样保留修订批次4的标准库参考内核，计算逻辑未改；其中Binary EV是算术测试标签，与预计首发A01不同。它验证标准亚洲盘、固定费用、等距赔率格点和允许乘积的普通串关；不训练球队模型、不获取数据、不估计真实阵容效应，也不验证预测准确率。

使用时将下面完整Python代码保存成.py文件，以Python 3运行，执行324项结算与算术自检。对真实比赛，还须输入本场有效概率与报价、核对该场临界结果，不能仅凭示例通过宣称本场计算正确。没有模型时仍可调用结算函数核对支付，但不填写虚构概率。

- settle：输入所选队整数净胜球及带符号的让球；大小球输入整数总球、非负线位及OVER/UNDER。
- payout：输入五态和含本金十进制赔率，返回含本金倍率；净收益再减1及实际费用。
- probs/net_ev：五态固定顺序FW、HW、P、HL、FL；概率总和必须为1，固定费用按每单位本金计。其他费用结构另按逐状态支付实现。
- min_price：只计算事先选定情景全部达到正目标g的价位，统一固定费用和等距格点；不是默认入串门槛。g=0保本用11.2公式；分支费用不同、非等距价位、平台特殊规则需另实现并回代。
- live_ah：只用于第十节明确的新剩余让球，必须有真实接受起点；不能拿赛前票或全场累计盘调用。
- standard_parlay：只在平台允许标准返还乘积时使用，输入各腿实际五态；不估计相关性或整票概率。

```python
from decimal import Decimal, ROUND_CEILING, getcontext
from math import exp, factorial, isclose

getcontext().prec = 40
STATES = ("FW", "HW", "P", "HL", "FL")
TOL = Decimal("1e-12")


def d(value):
    result = Decimal(str(value))
    if not result.is_finite():
        raise ValueError("Non-finite input")
    return result


def parts(line):
    q = d(line) * 4
    if q != q.to_integral_value():
        raise ValueError("Line must be a multiple of 0.25")
    q = int(q)
    return ((d(q - 1) / 4, d(q + 1) / 4)
            if q % 2 else (d(q) / 4,))


def settle(value, line, market="AH"):
    # value: selected team's integer goal difference, or integer total goals.
    value = d(value)
    if value != value.to_integral_value():
        raise ValueError("Score/goal difference must be an integer")
    if market not in ("AH", "OVER", "UNDER"):
        raise ValueError("Unknown market")
    if market != "AH" and (value < 0 or d(line) < 0):
        raise ValueError("Totals must be non-negative")
    outcomes = []
    for subline in parts(line):
        margin = (value + subline if market == "AH" else
                  value - subline if market == "OVER" else subline - value)
        outcomes.append(1 if margin > 0 else -1 if margin < 0 else 0)
    if 1 in outcomes and -1 in outcomes:
        raise ValueError("Unexpected split: not a standard quarter line")
    state_value = sum(outcomes) / len(outcomes)
    return {1: "FW", 0.5: "HW", 0: "P", -0.5: "HL", -1: "FL"}[state_value]


def payout(state, odds):
    odds = d(odds)
    if odds <= 1:
        raise ValueError("Decimal odds must exceed 1")
    return {"FW": odds, "HW": (odds + 1) / 2, "P": d(1),
            "HL": d("0.5"), "FL": d(0)}[state]


def probs(values):
    values = tuple(d(x) for x in values)
    if len(values) != 5 or any(x < 0 or x > 1 for x in values):
        raise ValueError("Need five probabilities within [0, 1]")
    if abs(sum(values) - 1) > TOL:
        raise ValueError("Probabilities must sum to 1; no silent normalizing")
    return values


def weights(values):
    fw, hw, push, hl, fl = probs(values)
    return fw + hw / 2, fl + hl / 2


def net_ev(values, odds, fixed_cost=0):
    values = probs(values)
    odds, cost = d(odds), d(fixed_cost)
    if odds <= 1 or cost < 0:
        raise ValueError("Invalid odds or cost")
    A, L = weights(values)
    fast = (odds - 1) * A - L - cost
    direct = sum(p * (payout(s, odds) - 1 - cost)
                 for s, p in zip(STATES, values))
    if abs(fast - direct) > TOL * max(d(1), odds, cost):
        raise AssertionError("EV cross-check failed")
    return fast


def min_price(scenarios, target, fixed_cost=0, tick="0.01"):
    scenarios = [probs(p) for p in scenarios]
    target, cost, tick = d(target), d(fixed_cost), d(tick)
    if not scenarios or target <= 0 or cost < 0 or tick <= 0:
        raise ValueError("Need scenarios, positive target/tick, non-negative cost")
    thresholds = []
    for p in scenarios:
        A, L = weights(p)
        if A == 0:
            return Decimal("Infinity")
        thresholds.append(1 + (L + cost + target) / A)
    raw = max(thresholds)
    price = (raw / tick).to_integral_value(rounding=ROUND_CEILING) * tick
    if any(net_ev(p, price, cost) < target - TOL for p in scenarios):
        raise AssertionError("Minimum-price back-substitution failed")
    return price


def remaining(final_score, accepted_score):
    if len(final_score) != 2 or len(accepted_score) != 2:
        raise ValueError("Need home/away scores")
    all_scores = [d(v) for v in (*final_score, *accepted_score)]
    if any(v < 0 or v != v.to_integral_value() for v in all_scores):
        raise ValueError("Scores must be non-negative integers")
    x = all_scores[0] - all_scores[2]
    y = all_scores[1] - all_scores[3]
    if x < 0 or y < 0:
        raise ValueError("Score correction/VAR dispute: check the actual contract")
    return int(x), int(y)


def live_ah(final_score, accepted_score, line, side="HOME"):
    if side not in ("HOME", "AWAY"):
        raise ValueError("Selected side must be HOME or AWAY")
    x, y = remaining(final_score, accepted_score)
    return settle(x - y if side == "HOME" else y - x, line, "AH")


def standard_parlay(legs):
    # Only for platform rules explicitly allowing the standard product.
    if not legs:
        raise ValueError("Need at least one leg")
    result = d(1)
    for state, odds in legs:
        result *= payout(state, odds)
    return result - 1


def self_test():
    checks = 0

    def check(condition, name):
        nonlocal checks
        if not condition:
            raise AssertionError(name)
        checks += 1

    cases = [
        (0, 0, "AH", "P"), (0, "-0.25", "AH", "HL"),
        (0, "0.25", "AH", "HW"), (1, "-0.75", "AH", "HW"),
        (-1, "0.75", "AH", "HL"), (1, -1, "AH", "P"),
        (1, "-1.25", "AH", "HL"), (-1, "1.25", "AH", "HW"),
        (-2, 2, "AH", "P"), (2, "2.25", "OVER", "HL"),
        (3, "2.75", "OVER", "HW"), (3, "2.75", "UNDER", "HL"),
        (3, "3.25", "UNDER", "HW"), (3, 3, "OVER", "P"),
    ]
    for value, line, market, expected in cases:
        check(settle(value, line, market) == expected, str((value, line, market)))

    for final, line, expected in [
        ((1, 0), "-0.5", "FL"), ((2, 1), "-0.5", "FL"),
        ((1, 0), 0, "P"), ((1, 0), "0.25", "HW"),
        ((2, 0), "-0.75", "HW"), ((2, 0), "-1.25", "HL"),
        ((1, 1), "0.75", "HL"),
    ]:
        check(live_ah(final, (1, 0), line) == expected, "Live starting score")
    check(live_ah((1, 1), (1, 0), "-0.5", "AWAY") == "FW", "Away perspective")

    opposite = {"FW": "FL", "HW": "HL", "P": "P", "HL": "HW", "FL": "FW"}
    for margin in range(-4, 5):
        for q in range(-8, 9):
            line = d(q) / 4
            check(settle(margin, line) == opposite[settle(-margin, -line)],
                  "Handicap symmetry")
    for goals in range(7):
        for q in range(17):
            line = d(q) / 4
            check(settle(goals, line, "OVER") == opposite[settle(goals, line, "UNDER")],
                  "Totals symmetry")

    p45 = ("0.45", 0, 0, 0, "0.55")
    p65 = ("0.65", 0, 0, 0, "0.35")
    check(net_ev(p45, "1.85") == d("-0.1675"), "Binary EV 45 percent")
    check(net_ev(p65, "1.55") == d("0.0075"), "Binary EV 65 percent")
    scenarios = [p45, ("0.5", 0, 0, 0, "0.5")]
    price = min_price(scenarios, "0.05")
    check(price == d("2.34"), "Price ceiling")
    check(net_ev(p45, price) == d("0.053"), "Threshold back-substitution")
    check(net_ev(p45, price - d("0.01")) < d("0.05"), "Previous tick fails")
    check(min_price([(0, 0, 1, 0, 0)], "0.05").is_infinite(), "A equals zero")
    check(min_price([p45], "0.05", "0.01") == d("2.36"), "Fixed cost threshold")
    check(net_ev(p45, "2.36", "0.01") == d("0.052"), "Fixed cost EV")
    risk_p = probs(("0.48", 0, 0, "0.28", "0.24"))
    check(risk_p[3] + risk_p[4] == d("0.52"), "Any loss includes half loss")
    check(net_ev(risk_p, "1.85") == d("0.028"), "Half-loss weighted EV")
    check(net_ev(("0.4", "0.2", 0, 0, "0.4"), "1.9") == d("0.05"),
          "Half-win weighted EV")
    check(standard_parlay([("HL", "1.9"), ("FW", "1.8")]) == d("-0.10"),
          "Half loss plus win is a losing parlay")
    check(d("0.7") ** 4 == d("0.2401"), "Four-leg non-total-loss example")

    # One supplied residual distribution; different settlement maps.
    pi = {(0, 0): d("0.4"), (1, 0): d("0.3"),
          (0, 1): d("0.2"), (1, 1): d("0.1")}
    p_ah = {s: d(0) for s in STATES}
    p_home_win = d(0)
    for (x, y), mass in pi.items():
        state = live_ah((1 + x, y), (1, 0), "-0.5")
        p_ah[state] += mass
        if 1 + x > y:
            p_home_win += mass
        check(state == live_ah((3 + x, 2 + y), (3, 2), "-0.5"),
              "AH settlement invariant to past-score offset for fixed residual input")
    check(sum(p_ah.values()) == 1, "Derived five-state probability sum")
    check(p_ah["FW"] == d("0.3") and p_home_win == d("0.8"),
          "Live AH is not full-time moneyline")
    check(settle(1, "0.5", "OVER") == "FW"
          and settle(0, "0.5", "OVER") == "FL", "Full totals vs remaining totals")

    pmf = [exp(-3.4) * 3.4 ** k / factorial(k) for k in range(4)]
    win, push, loss = 1 - sum(pmf), pmf[3], sum(pmf[:3])
    check(isclose(win, 0.4416429447171045, abs_tol=1e-12), "Poisson win")
    check(isclose(push, 0.21861716708677603, abs_tol=1e-12), "Poisson push")
    check(isclose(loss, 0.33973988819611944, abs_tol=1e-12), "Poisson loss")
    check(isclose(win + push + loss, 1, abs_tol=1e-12), "Poisson sum")

    invalid_calls = [
        lambda: settle(0, "0.3"),
        lambda: probs(("0.6", 0, 0, 0, "0.6")),
        lambda: probs(("-0.1", 0, 0, 0, "1.1")),
        lambda: live_ah((0, 0), (1, 0), 0),
        lambda: net_ev(p45, 1),
        lambda: net_ev(p45, "NaN"),
    ]
    for operation in invalid_calls:
        try:
            operation()
        except ValueError:
            check(True, "Invalid input rejected")
        else:
            check(False, "Invalid input was accepted")
    print(f"PASS: {checks} settlement/arithmetic checks")
    print(f"Example minimum odds: {price}; EV at that price: {net_ev(p45, price):.3%}")
    print("Scope: settlement and arithmetic only; no forecast-quality claim.")


if __name__ == "__main__":
    self_test()
```

- **R4** Mead, O’Hare & McMenemy (2023), *Expected goals in football: Improving model performance and demonstrating value*：[原文](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0282295)。支持研究xG的增量预测用途；仍须本项目时间验证，不能照搬窗口或盈利结论。
- **R5** Hudl/StatsBomb：[xG定义](https://www.hudl.com/blog/expected-goals-xg-explained)、[开放数据](https://github.com/hudl/open-data)。供应商定义与可用数据边界，不是独立收益验证。
- **R6** Hvattum & Arntzen (2010), *Using ELO ratings for match result prediction in association football*：[期刊原文](https://www.sciencedirect.com/science/article/pii/S0169207009001708)。用于赛果评级与结果概率的简单对照。
- **R7** Kharrat, López Peña & McHale (2017预印本), *Plus-Minus Player Ratings for Soccer*：[原文](https://arxiv.org/abs/1706.04943)。正则化球员贡献研究；不能将单个评分直接当缺阵造成的因果胜率损失。
- **R8** Decroos等，VAEP：[论文](https://arxiv.org/abs/1802.07127)、[作者项目文档](https://socceraction.readthedocs.io/en/latest/documentation/valuing_actions/vaep.html)。动作短期价值不等于整场胜率。
- **R9** Dupont等 (2010), *Effect of 2 soccer matches in a week on physical performance and injury rate*：[原文](https://journals.sagepub.com/doi/10.1177/0363546510361236)。特定队列的伤病/体能研究，不提供可通用的胜率扣减。
- **R10** Dixon & Robinson (1998), *A birth process model for association football matches*：[原文](https://rss.onlinelibrary.wiley.com/doi/10.1111/1467-9884.00152)。支持时间和比分状态下的进球过程建模。
- **R11** Titman等 (2015), *Joint modelling of goals and bookings in association football matches*：[原文](https://academic.oup.com/jrsssa/article/178/3/659/7058647)。研究含赛前赔率实力输入；引用其事件结构不等于采用纯非赔率模型。
- **R12** Gneiting & Raftery (2007), *Strictly Proper Scoring Rules, Prediction, and Estimation*：[原文](https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jasa.pdf)。用于概率分布评价，评分好不自动意味着投注盈利。

流程字段、正确结算和语义澄清可以直接执行；新足球筛选政策进入比较前先作为独立研究输出，保留正式基线决定。预测与收益分别报告，不由文档完整性或30场流程通过推出优势。

### 25.3 GPT完成任务时的最后核对

先检查用户本次要求是否都已完成，再检查主方向、适配、报价性质、条件和数字是否一致。向用户交付正文及实际可用附件；没有保存成功就如实说明，不给虚构下载地址。需要下一输入时只说最小缺件或新的比赛资料，不把能在当前任务继续完成的核验留成“要不要继续”。

### 25.4 ZIP的最小结构与累计原则

本节是执行者的交付约定，不要求用户建数据库或运行程序。包名可用“日期_赛事_主队vs客队_完整归档_pkg003.zip”；包版本顺序递增，比赛日期与复盘生成日期分开记，不因赛后跨日改比赛身份。

| 相对路径 | 必需程度 | 内容 |
|---|---|---|
| `report.html` | 默认必需；工具受限可用`report.md`并标原因 | 最新可读报告，赛后按§18.8栏目；连到所有实际纳入的原版本 |
| `record.json` | 默认必需；字段表回退须显式说明 | §25.5结构化索引、事实/合约/结算记录及本场审计增量 |
| `manifest.json` | 成功生成ZIP时必需 | 实际文件相对路径、角色、字节数、SHA-256、来源标识及缺件列表；自文件不自算哈希，外层ZIP摘要如需另附 |
| `originals/` | 有可取得原件时 | 原报告、旧复盘、图片原字节、原底稿、可见对话保存件；报告/图片原件不因转格式被替换 |
| `evidence/` | 实际取得或运行时 | 赛果页关键摘录/响应、真实模型/计算输入输出与日志、必要规则/代码来源凭证；大文件可固定引用并如实标未打包 |

这些是约定路径，不强制空目录、空日志或每类拆成多个文件。没有截图/模型运行时，在`record.json`记适用性与原因即可。保存网页证据只需支撑核验的结果字段、关键片段、来源和获取时点，不为凑文件复制无关整站。

累计包包含实际可得的各版原文与必要证据，旧包无需层层嵌套：保留去重后的原文件及旧清单/包指纹引用即可。既有文件名可保留，通过清单映射角色，不为统一命名重写内容。ZIP不可作唯一的比赛键，文件哈希也不能代替比赛身份。

实际可读、已经检查、已装入包是三个独立状态。只有附件名/链接时不得生成一个同名空文件装作原件；能在对话看图但无法取得原字节时保留可见性和读图范围、记录归档缺口，不称已保存原图。裁切/放大/OCR/转码均为派生件，单独记录父`source_id`及转换，不能覆盖原图。用户纠正、买入说明等补充原文附消息来源和实际时间或未知，不凭记忆补写。

### 25.5 跨场最小机器字段：match-archive-1.0

`schema_version = "match-archive-1.0"`只表示本批定义的归档字段接口，不表示框架版本或自动程序已实现。原底稿已有更多字段时保留，允许转换成兼容索引但不得覆盖原始记录。以下必需块以数组/对象组织在一个`record.json`内；不适用块注明理由，无需制造记录。

**稳定标识和缺失规则**

- `match_key`：优先“供应商命名空间＋真实比赛ID”；无外部ID时生成本地稳定键并记录赛事、队伍身份、赛季/轮次、日期的核对依据。后补官方ID加入别名映射，不改掉旧关联；无法唯一识别时`identity_status=unresolved`，不自动合并。
- `version_id`：本场报告唯一ID，含阶段（赛前/临场/滚球/赛后）及顺序；另存原始r1/r2标签、父版本与真实时间。`package_revision`是包次序，不是新增比赛/预测。
- `source_id`定位原文、图片、网页证据或命令产物；图规的网站/页面来源配置另用`source_config_id`，旧底稿中同名source_id先保留原义并建立映射，不混作图片证据ID；`quote_id`定位某来源某市场某一整行状态；`contract_id`定位市场、所选方、线、结算范围和必要起点组成的支付对象。报价变化建新报价ID；合约线/范围/起点变化建新合约ID。ID不是文件哈希。
- F2新版对象显式使用 `quote_row_id` 标整行、`quote_offer_id` 标单票。导出到 `decision-audit-1.0` 时其 `quote_id` 是单票别名，必须附转换版本和整行→单票映射；不能直接把该别名当作本节历史整行 `quote_id`，也不重写旧档。报价、合约、预测及决定ID分别绑定。
- `candidate_id`沿用§25.1，表示投注候选；`condition_id`表示原条件；`issue_id`表示一个可追溯问题事件；`improvement_id`专指规则/模型改进候选，避免与投注候选混淆。历史P/C编号放`legacy_ids`，不重编号或仅凭同名合并。
- 未知用JSON `null`并在`missing`内记录字段路径、原因与影响。`[]`仅表示已检查确无记录；未检查的集合用`null`并说明，不能空数组伪装已检查无问题。0只表示真实数值0。时间用带偏移的ISO 8601，展示优先`+08:00`；只有日期/不完整时间时保留原文和精度，不补00:00。
- 指向不可得原件的引用必须仍有`source_id`占位及缺失状态；`path=null`、`sha256=null`，不冒称本地存在。原文、派生文本、执行输出和执行者结论分别标来源角色。

| 顶层块 | 最小字段/要求 |
|---|---|
| 包与比赛 | `schema_version`、`package_revision`、`generated_at`、`framework_used`、`image_rules_used`、`match_key`、`identity_status`、`external_ids`、赛事/队伍/赛季/开球时间及核对依据；历史各报告版本仍保留自己的规则版本 |
| `versions[]` | `version_id`、原版本标签、父版本、任务阶段、`as_of`、`published_at`、时间证据、是否已见赛果/未来资料、原框架/图规、原件`source_id`、原主方向/适配/条件引用、前瞻资格及原因 |
| `sources[]` | `source_id`、类型、原文件名/URL/消息定位、读取状态、读取范围、原文/转录/派生角色、`read_at`、`acquired_at`、归档状态、相对`path`、`sha256`或缺失原因；派生件加父来源与转换 |

### 25.6 保存前的最低核验与旧材料兼容

执行者实际检查并保留结果，而非仅复制勾选表：

1. 打开生成的阅读报告，赛后确认§18.8 A—H适用栏目，赛前/更新确认§16适用栏目，关键表可读、无截断；主方向/线/报价/条件/结算与结构记录逐项一致。独立HTML与包内报告字节相同（派生预览例外明确标记）。
2. JSON实际可解析；版本、稳定ID无冲突，引用可解析，未知与0不混用，四集合和各阶段不串组；对照原文抽取不是凭摘要填值。
3. ZIP实际可解压，清单所列路径/字节数/哈希与实际文件一致；HTML包内相对路径可达，必要附件缺失写明。清单不含本机临时绝对路径作可移植引用；本机路径可另留在真实运行日志中。
4. 原件复制前后指纹相同；保留旧版本全文，派生格式不冒原件；只有链接、图片展示或模型说明时不伪称已保存原文件/已实际运行。缺证据可部分交付，但不标完整核验通过。
5. 实际命令与输出支持相应“已运行/已复算”结论；未运行、资格不适用、运行失败分别记。必要的输入/输出缺失会限制复算资格，不能靠JSON自述弥补。
6. 旧MD/HTML/TXT/ZIP可直接审计：先建立保留原件的映射，不为了迁移格式改旧预测；没法还原的字段保留缺失。只有单一报告时可完成适用审查，不能标成原图/日志齐全。

到此即交付本次已完成结果；不因非关键缺件反复索要无关材料，也不承诺其他对话自动取得包或后台自动更新。后续审计所需原文、真实图像与模型日志的获取能力仍以届时实际可读范围为准。


### 25.7 模型访问尝试与原件落地记录

在本场`model_access.json`或`record.json.model_records[]`附属记录保存以下内容，并由§25.4的证据目录/清单引用；无需为无模型任务制造空日志。本节增补批次3原有字段，不改`match-archive-1.0`的既有状态含义。

日志不含认证头、密码、令牌或带凭据URL；错误摘要脱敏仍保留足以区分原因的工具/错误码。单一通道失败不升级为“全会话认证失败”；所有当前适用授权路径均未取得必要文件后才记本次读取受阻，继续可支持定性分析。不得推导成模型未训练、赛事未覆盖、概率为0，也不能仅因有GitHub链接、原件落地或JSON自述而标实际复算通过。

### 25.8 批次5的可执行核验记录

`match-archive-1.0`的原字段及历史状态不改写。新增模块产物作为独立证据对象，由`record.json`或本轮工程报告引用，并保存实际命令、代码版本、输入/输出指纹与退出状态。具体JSON以对应实现文档及真实`--help`为准，不把示例命令当实际执行凭证。

| 程序及入口 | 保存职责 | 不能替代什么 |
|---|---|---|
| `python -m football_model.evidence freeze --source-root DIR --output NEW_DIR --spec SPEC.json`；`verify --bundle DIR` | 实际白名单原件、真实创建时间、`analysis_cutoff`、每项`observed_at`及已知`published_at`、信息暴露声明、完整性和用途限制；外部保存清单摘要可加强后续篡改检测 | 文件哈希不能证明历史公开时间、盲测资格或来源内容真实；自述未见结果也非独立证明 |

**S2统一决定接口（2026-10-07追加能力说明）：** `football_model.decision_record` 使用一份正式对象生成决定正文、主卡、兼容审计视图、membership及评分导出；报价保留原整行，通过 `decision_quotes` 明确转换所选方、主队盘口符号及制式。完整接口与执行命令见 `docs/s2-decision-record.md`。这一决定正文不代替§16完整足球分析及§25累计原件包；实际自由文字仍须回核。输入与晚算派生资料分层，真实冻结开始/完成、报告生成、实际发表和用户收到不互相代填。发布、条件变化及执行记录另存追加事件，新条件只触发重评，不改变旧决定。
