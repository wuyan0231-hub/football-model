## 恢复原研究的具体入口

恢复前先结束本次维护、确认共享写入队列没有维护任务、保留当前固定状态提交，并核下面的条件。暂停期间不自动执行本节命令。

1. 核原 Actions 运行的 `head_sha` 为上表旧源码、原 `head_branch` 为 `main`、输入仍为原 `research_only` 和原联赛范围，且原运行已终止。保存原失败、取消和跳过状态。
2. 使用**原运行的 Re-run failed jobs**，不要从最新 main 重新派发 `research_only`。例如原运行号为 `38928003279` 时，恢复命令为 `gh run rerun 38928003279 --failed --repo wuyan0231-hub/football-model`。这是供审阅的入口，本文件不会执行或调度它。
3. 重跑后核实际运行仍使用原源码、原 main ref 和旧 50 文件指纹。原 checked-save 入口要求源码 HEAD、`GITHUB_SHA`、main ref 和加载标记一致；本次不放宽此要求，也不伪造这些字段。
4. 从当时最新状态恢复后，逐联赛让原生检查点核输入、协议、实现、成熟目标、新鲜度和固定持久闭包。已完成的结果核通过则复用，不重复拟合。资料变化导致失配时如实保留，先报告范围；不得直接升级成全部联赛重跑。
5. 原运行已有通过的联赛作业不重跑；取消或跳过的剩余作业继续按旧队列串行写入。全 19 联赛核验和原最终短轮仍由原实现完成，原研究产物不改写成新实现产物。

如果平台不支持原运行按失败项恢复，停止在该边界，另审查固定旧源码入口；不能以新 main 重算全部联赛代替恢复，也不能改守卫绕过来源验证。

4. **候选范围**：旧卡不合格时保存明确拒绝与 M0 结果。若本次要验新候选 live，先选定一个有资料的联赛在隔离状态进行本实现真实开发、原门槛判断、保存和独立回读，再在真正新赛前窗口验证；不自动对全部联赛重训，不因工程改进激活确认或晋级生产。
5. **结束后调度**：维护期间暂停的工作保持暂停，直到明确恢复；恢复时先原研究、后原交接，新研究和未来积累的身份各自独立。仅移除已过期的 2026-10-17 单次 cron，其他周期日程原文保留。

## 2026-10-18 固定冷读失败与最小缓存准入修补

原新实现 `b49e96b3…` 的无预热固定诊断运行 `39082219909` 实际到达 1500 秒截止；清理及最终核验后记录 1511.532 秒，状态为 `diagnostic_deadline`。完整冻结未证明通过，原失败保留，不用以前带预热的 17 分 45 秒结果替代这条生产冷读路径。

后续纯观测前段已区分具体原因：单个读取进程正常复用、没有缺件返回；3 个固定来源 manifest 原字节共 135,342,008 B，最大 58,189,975 B，与压缩传输原件竞争同一 64 MiB 字节 LRU。在约 2539 次观察调用时，manifest 已读取 10 次、返回约 484 MB；2528 次完成的 transport 读取只对应 1723 个不同对象、合计 4,239,092 B，但实际命中仅 1 次。多次读取的传输对象虽可容纳，仍被大型 manifest 挤出。这些是有界前段证据，不能替代完整闭包耗时验收。

第一步修补仅让精确路径 `state_storage.json` 不进入字节 LRU；64 MiB 上限、其他传输对象缓存、原 manifest 解析与校验缓存上限均不变。不增加负缓存、磁盘缓存、预热或新资源上限；每条冷引用仍执行固定 manifest 比对、compressed SHA、解压、raw SHA 及原 JSON／秘密信息检查。原始返回字节和缺失／损坏错误保持；真实 Git 回归另外核验重复冷引用仍逐次完成 manifest 检查和解压。

诊断中 `original` 明确表示之前的“全部 blob 准入”基线，`skip_manifest` 表示本修补策略。新 native 的重放一致性核 `actual_vs_skip_manifest_hit_mismatches`，不把 `actual_vs_original_hit_mismatches` 为零作为新实现门禁。两种重放仅比较同一有界请求前段的缓存行为；追踪达到上限即标不完整，不能由命中差直接推算耗时提升。

分钟日志拆为短行：全局摘要少于 400 字符、每类少于 350、每读取器少于 800；完整结构仍保存在原诊断 checkpoint 和最终 artifact。最终新指纹、窗口守卫与工作流执行参数同步为上表 `b443defa…`；固定输入、1500 秒、无预热及全部原验收门保持。须等新的完整固定闭包及保存回读真实通过，才能报告相应工程验收完成。


## 同一总预算内的已核成员关系证明

字节缓存准入修补以后，三份来源清单在原两份完整解析缓存中交错，仍会反复全量解析。单条懒缓存的真实 Git 反例显示，三来源、600 个首次唯一路径仍需 600 次完整解析。最终修补不扩大原两份完整清单缓存，也不改变其完整返回接口；仅在完整固定目录的读取会话内复用已成功核验的成员关系。

默认读取器的原 64 MiB 总额划为 56 MiB 字节缓存与 8 MiB 成员证明预算；先实际逐出超额字节，再建立元数据。自定义小缓存、离线材料、非固定会话和不匹配的路由均使用原路径。元数据按构建峰及容器／键字节预扣，另有 250000 路径、128 来源的界；超界逐出证明或退出优化，不能放宽正确性检查。

路径序号表只借用已固定目录中的原字符串引用，排序构建峰按每路径 20 字节加固定余量计入 8 MiB；每份来源的 bytearray 与不可变 bytes 双份峰及键／容器余量也计入。来源清单仍先完整核 SHA、schema 和重复路径；只在同源、同 manifest SHA、固定九字段路由及完整五字段成员记录严格相等时置位。位图是确定性关系证明，不是概率过滤器；零位仅表示尚未证明，当前读取仍走原完整验证和原错误。未访问的错误记录不被提前扩展为整份业务失败。

每条引用仍核来源绑定、精确九字段路由及五字段等值，并逐次执行 compressed SHA、解压、raw SHA、JSON、秘密信息、时间与容量门。证明不表示原件正文已核；当前正文任何失败都不会建立新证明。scope 退出清空证明和路径表、恢复原总预算；进程 close 清记录但不提前释放活动会话预算，不跨会话复用。

独立真实 Git 回归中，三来源各 200 个首次唯一路径交错读取共 600 条边，完整来源解析为 3 次，解压仍为 600 次。该反例证明重复工作减少，不替代云端完整 5401 原件、原 1500 秒、无预热验收。观测日志分别记录当前总额、实际字节预算、元数据预算及构建峰收费；预算转换同步到两种有界重放，截断前重放容量与当前容量单独标记。原 512 KiB 输出上限保留。


## 诊断截止不被底层错误处理吞掉

运行 `39086371200` 超过原 1500 秒后仍在原生冻结，已停止并保留取消终态及本运行 artifact，不计性能通过。独立 CPython 3.12 的真实 SIGALRM 实验确认，`Path.resolve(strict=False)` 会将继承 `OSError` 的诊断截止异常视为可恢复文件错误；逐条冻结会调用该路径。旧脚本还可能在信号迟到或清理超限时错误保留成功状态。

截止异常改为专用 `BaseException`，外层显式捕获并保存失败；成功声明前以及清理完成后都核未取整的 monotonic 耗时和原 expired 标记。只有原生冻结、退出检查和清理均完成且未过原限，最终状态才置成功。即使下层显式吞掉异常，expired 标记或时间门仍拒绝通过。日志另记原时限、expired、未取整是否超限和清理是否计入，避免取整后的 1500.000 掩盖边界。原 1500 秒、512 KiB 及所有原件／容量门均未提高。


## 路径检查保留全部系统调用，减少对象构造

运行 `39088348849` 的最终原件记录实际失败：`diagnostic_deadline`，1511.358 秒，expired 与未取整超限均为 true，清理计入；完整 5401 原件与目标库存尚未完成。三份来源清单各只读取一次，成员证明峰值 2,259,914 字节，原资源与 512 KiB 输出门均满足。实际 profile 的 `_safe_path` 为 5,545,696 次、累计 411.560 秒；累计时间与子调用重叠，不能相加或直接推算整体提速。该失败原样保留，以下修补须重新完成同门验收。

`_safe_path` 继续每次按原叶到根顺序检查原路径及全部祖先，完全不缓存或跳过检查。它直接调用原底层 `os.stat(path, follow_symlinks=False)`，减少为每个祖先构造 Path 对象及中间包装函数的开销；返回值仍为原绝对 Path。

目标 Python 3.12 的错误规则保持：仅忽略 errno 2／20／9／40 或 winerror 21／123／1921，以及同一 stat 范围内的 ValueError；其余错误原对象向外抛，专用 BaseException 截止异常不被捕获。本地命名常量和谓词避免依赖私有标准库符号。

差分检查覆盖实际路径、缺叶、非目录、根与双斜杠、点及上级路径、符号链接、控制编码、全部错误位置与优先序，逐次 nofollow stat 的顺序和次数均相同。原文件身份六字段及修改后恢复的拒绝机制不变。局部计时只证明包装层开销减少；完整云端仍必须使用同一输入、无预热、原 1500 秒和最终库存门。
