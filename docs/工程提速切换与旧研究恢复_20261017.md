## 诊断截止不被底层错误处理吞掉

运行 `39086371200` 超过原 1500 秒后仍在原生冻结，已停止并保留取消终态及本运行 artifact，不计性能通过。独立 CPython 3.12 的真实 SIGALRM 实验确认，`Path.resolve(strict=False)` 会将继承 `OSError` 的诊断截止异常视为可恢复文件错误；逐条冻结会调用该路径。旧脚本还可能在信号迟到或清理超限时错误保留成功状态。

## 路径检查保留全部系统调用，减少对象构造

运行 `39088348849` 的最终原件记录实际失败：`diagnostic_deadline`，1511.358 秒，expired 与未取整超限均为 true，清理计入；完整 5401 原件与目标库存尚未完成。三份来源清单各只读取一次，成员证明峰值 2,259,914 字节，原资源与 512 KiB 输出门均满足。实际 profile 的 `_safe_path` 为 5,545,696 次、累计 411.560 秒；累计时间与子调用重叠，不能相加或直接推算整体提速。该失败原样保留，以下修补须重新完成同门验收。

`_safe_path` 继续每次按原叶到根顺序检查原路径及全部祖先，完全不缓存或跳过检查。它直接调用原底层 `os.stat(path, follow_symlinks=False)`，减少为每个祖先构造 Path 对象及中间包装函数的开销；返回值仍为原绝对 Path。

目标 Python 3.12 的错误规则保持：仅忽略 errno 2／20／9／40 或 winerror 21／123／1921，以及同一 stat 范围内的 ValueError；其余错误原对象向外抛，专用 BaseException 截止异常不被捕获。本地命名常量和谓词避免依赖私有标准库符号。

差分检查覆盖实际路径、缺叶、非目录、根与双斜杠、点及上级路径、符号链接、控制编码、全部错误位置与优先序，逐次 nofollow stat 的顺序和次数均相同。原文件身份六字段及修改后恢复的拒绝机制不变。局部计时只证明包装层开销减少；完整云端仍必须使用同一输入、无预热、原 1500 秒和最终库存门。
