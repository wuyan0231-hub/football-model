## 0. 适用范围与优先关系

本规范用于读取用户提供的足球赔率截图，包括赛前、滚球、三表并列截图、单市场裁图和同场多张截图。它规定图片识别、整行绑定、标准化、异步报价处理、市场变化观察、推荐采用价记录、输出摘要和读图检查。概率模型、EV、推荐等级、串关适配与复盘评价由当前采用的足球分析框架负责。

日常比赛分析有截图时必须执行本规范。其他比赛的历史资料及规范中的示例不能混入当前比赛输入；本场早期截图按实际时间与用途使用，保留其市场变化证据。报告写明实际读取的框架版本、修订批次和截图规范版本；原图不可得时说明只能检查文字记录，不能声称完成回图核验。

用户在当前任务中明确说明的公司顺序、网站、时区、赔率格式及合约约定优先；已确认的同一来源配置可以沿用，出现冲突时再核对。合约约定与实际平台条款不匹配时说明具体差异，不能擅自改变票据结算。

推荐、执行与复盘政策服从当前框架；不因旧截图规范曾引用 v1.4 而恢复旧 Q/T/K、旧等级或旧默认 EV 门槛。

核心原则：**每条采用数据必须绑定“图片—来源—市场及合约范围—本表行号—本行时间—本行比赛状态—本行盘口及整组赔率—本行报价状态”。**

### 0.1 本版确认的截图使用方式

1. **历史变化用于观察市场反应。**内部读取完整可见记录，识别变线、同线变价、反复切换、封盘与恢复，比较不同市场和公司的支持或分歧，并说明对具体候选合约的影响。
2. **推荐采用所选合约的最新可见报价。**可以使用用户提供的任一来源，不要求其他市场或公司在同一分钟更新，也不要求选择整组截图中时间数字最大的那个市场。
3. **本类页面按用户已确认的机制解释时间。**赔率发生变化时才产生相应变化时间；某市场最新时间较早，不单独构成其报价过期的证据。这个机制是本类来源的配置，不自动推广到所有网站。
4. **推荐依据与实际成交分开。**完整、可识别且没有已知状态冲突的最新有价记录，可以作为推荐参考；无需先提供账户截图或已接受订单。实际开放、投注提交和接受成交只按各自证据记录，缺少成交记录写“未确认”，不假定已下注。
5. **缺口只限制受影响部分。**其他市场缺失、封盘或无法辨认，不自动阻断已清楚市场的分析；缺少完整历史不自动阻断清楚最新价的使用。
6. **各市场表最上方就是最新记录。**用户已确认本类截图为上新下旧，日常直接沿用，无须每次重新确认排序。这里的“每列”按每个独立市场表理解，采用其最上方整条记录；若该行显示“封”，最新状态就是封盘，不能跳过它把下方旧数字当作最新报价。
7. **“封”代表封盘，原因另行判断。**滚球时可能与危险球、点球或其他异常情况有关，但仅凭“封”不能确认具体事件。历史封盘不等于顶部最新状态仍封盘，某一市场封盘也不等于所有市场都封盘。

## 1. 来源配置与图片身份

### 1.1 每张图片先记录

- 图片编号与收到时间；
- 赛事标签、主队、客队及标题显示的开球时间；
- 赛前或滚球阶段，以及判断依据；
- 实际赔率公司与截图网站，两者分别记录；
- 页面记录时间的时区；
- 亚洲让球、大小球和胜平负各自的赔率格式；
- 亚洲让球的让受显示方式；
- 各市场的结算范围；
- 裁切、模糊、遮挡、缺列及残行的位置，以及分别影响什么。

主客顺序按截图标题和列名保存，不按球队强弱或赔率高低交换。截图中的赛事和开球时间属于原始转录；外部核验结果另设字段，不覆盖图片原文。

图片未显示的公司、网站、时区等，可采用用户明确说明或已确认且仍适用的来源配置，并记录依据；没有依据才写“未知”。用户上传时间只能作为收到时间，不能冒充截图时间或页面变化时间。

一张图片可以同时包含三个市场，多张图片可以来自不同公司、不同市场或不同页面窗口。不得固定假设“图一是让球、图二是大小球、图三是胜平负”，也不得在没有用户说明时固定公司顺序。

网站和公司不是同一概念。同一公司经不同网站展示，证据层保留各自来源，分析或模型层不能把它们当作两家独立公司重复计权。

### 1.2 来源配置表

同一来源首次确认后建立配置；后续图片无冲突时沿用，不重复要求用户说明。页面改版、字段冲突或用户更改设置时重新核验。

| 配置项 | 允许值或说明 |
|---|---|
| source_config_id / bookmaker / website | 网站及页面类型的配置标识、实际赔率公司、截图网站；证据对象另用source_id，见§1.3 |
| config_evidence | 用户说明、页面标识或其他可核实依据 |
| timezone | 页面记录时间的时区及依据 |
| ah_odds_format / ou_odds_format | 香港盘／十进制／其他／未知，分别确认 |
| 1x2_odds_format | 十进制／其他／未知 |
| handicap_display | 主让、主受的显示规则及依据 |
| market_period | 全场、半场、剩余时间或未知，逐市场记录 |
| row_order | 本用户已确认的本类截图固定采用上新下旧，顶部记录最新；其他未确认的新来源另行识别 |
| suspension_marker | “封”=该来源该市场本行记录时封盘；具体原因需其他证据 |
| timestamp_semantics | 赔率变化记录时间／其他页面时间／未知 |
| quote_stream | 页面主盘变化序列、独立备选线或其他明确的报价序列 |

排版、中文界面、颜色和赔率高低都不能单独证明来源配置。已知来源配置不能被一条异常数值临时改写。

### 1.3 原图可用性、原件和证据定位

先核实际可读材料，再执行读图；读取状态沿用框架§0.3的四类，不用“看见文件名”冒充“看见图片”。状态针对具体对象记录：

| 读取状态 | 图片或相关文件的实际情况 | 可做与不可声称的事项 |
|---|---|---|
| 已读取原文 | 已实际查看原图的可见范围、已读取报告/底稿全文，或已读取可见对话原文；分别写明对象类型和范围 | 原图可支持回图；读完文字文件不能代替回图。可见对话只证明所见原话，不证明原附件全文；完整文件字节可取得与否另记 |
| 只见转录或摘录 | 只有旧报告转录、OCR、摘要或局部摘录 | 可检查文字内部一致性；不能声称已核对原图或取得原文件全文 |
| 仅有文件名或链接 | 只见附件名、失效路径或未成功读取的引用 | 保存定位与待补事项，不补造图片内容或哈希 |
| 未取得 | 必要图片/文字尚未提供或无法取得 | 记录缺失原因及影响，继续不受影响的分析；不凭记忆复原 |

“读取状态”“已完成哪些检查”“是否实际归档原字节”分别记录。能在对话中看图但不能取得原文件时，记录已查看的范围、消息定位及原字节归档缺口；不能标为已保存原图。只有派生裁图时仅标该裁图已查看，不能扩大为已看完整原图。未检查的字段保留未知及原因。

每个实际取得或明确缺失的证据对象分配`source_id`；图片另设`image_id`并指向该证据对象，两者可同值。记录原文件名/消息或附件定位、来源角色、收到/取得/读取时间及已知精度、读取范围、包内相对路径、实际字节数与SHA-256。未知路径/哈希用`null`并说明原因；SHA-256只能证明所存字节一致，不证明图片真实、转录正确、报价开放或已成交。

原图按取得的原字节留存；裁切、放大、增强、转码、OCR和重新截图均另记派生件，保存父`source_id`、转换说明和各自指纹，不覆盖原图，也不把派生件的哈希写成原图哈希。只有名称/链接时不得建立同名空图充数。

本批将网站/页面配置标识明确命名为`source_config_id`，将`source_id`统一留给框架§25.5的证据对象。旧底稿若以`source_id`表示网站配置，保留原字段于原件，迁移时用`legacy_source_id`记录旧值并映射到`source_config_id`；不得静默改变旧ID含义或丢失关联。

## 2. 各张市场表独立读取

常见版式为左侧亚洲让球、中间大小球、右侧胜平负，每张图片仍先核对表头。只出现一个或两个市场时读取实际可见部分，不补造其余表。

各表独立更新。横向处于同一高度的记录，不一定拥有相同变化时间、比赛分钟或比分。一个市场新增记录，不代表其他市场也在该时点变动。

本类截图各表均为上新下旧，分别以本表顶部整条记录确定最新状态，不在三张表之间寻找统一的最大时间。顶部有价时读取该行完整报价；顶部为“封”时按封盘记录。

### 2.1 亚洲让球表

常见表头为“时／比分／主／盘／客／变化／状”。

- “时”是本行对应的比赛分钟，不是墙上时间；
- “比分”是本行对应的主队—客队比分；
- “主”和“客”是本行盘口两侧的赔率或水位，不是胜平负赔率；
- “盘”保存完整盘口原文及让受标记；
- “变化”保存该条记录的日期与时分；在用户已确认的变化记录页中，它是该市场该条变化的时间，不是整张图刷新时间或报价到期时间；
- “状”是早盘、即时、滚球等阶段标记，与有价、封盘等报价状态分开。

最新行的时间较早，只说明该市场最新可见变化记在较早时点，不能仅凭这一点写成“旧价已失效”。“即”也不能单独证明比赛已开球。

### 2.2 大小球表

常见表头为“时／比分／大／盘／小／变化／状”。“大”和“小”必须与本行总进球盘口成组读取，不能沿用让球表的主客含义。

同线变价与总进球线位变化分别记录。大小球从 2/2.5 换到 2.5 时，不能忽略合约变化，仅比较水位高低。

### 2.3 胜平负表

常见表头为“时／比分／主／平局／客／变化／状”。同一行的主胜、平局和客胜必须成组读取。去水只能使用同一公司、同一完整记录行、同一结算范围的三项价格。

### 2.4 每表独立编号

每张图片实际出现的市场分别从 1 编号，例如 `IMG01-AH-01`、`IMG01-OU-01`、`IMG01-1X2-01`。定位采用“图片编号＋市场＋本表行号”，不使用含糊的“图片第5行”。

## 3. 行绑定、排序与状态

### 3.1 固定行读取顺序

逐行按以下顺序读取并绑定：

1. 图片编号、来源、市场、结算范围及报价序列；
2. 本表行号；
3. 本行“变化”日期与时间；
4. 本行阶段标记；
5. 本行比赛分钟和比分；
6. 本行盘口与两侧／三项赔率，或者封盘；
7. 本行可读性、缺失项和推定项。

先锁定整行，再读取数值。时间单元格分两行显示日期和时分时，在同一单元格内合并；不得从相邻行或另一市场借用日期、时间、比分或赔率。跨行换行的盘口文字在同一单元格内还原，不拼接其他行。

### 3.2 排序、同分钟记录与裁切

本用户已确认：本类截图每个市场表最上方记录最新，向下依次为历史。日常直接按这一排序读取，不再把“排序尚未独立确认”当作使用顶部记录的前置障碍，也不反复向用户询问。回图核对的是行列对应、字段和实际矛盾，不是重复要求用户证明排序。

其他未确认的新页面另行识别排序。若本类截图出现明确的时间矛盾、页面改版或最新报价记录确实被裁掉，只核对受影响部分：时间字符有疑点时保留“页面顶部最新”的身份并标记该时间疑点，不凭下方较大的时间数字擅自换用旧行；确实缺少最新记录时，才限制最新状态的确认。未截入标题不等于最新报价行被裁掉。

同一分钟可能有多条记录。全部保留原始行号和页面顺序，不去重、不平均、不编造秒数；本类截图中同分钟较上方的行仍比下方更新。报价相同也可能对应不同状态，不只凭相同数字合并记录。

比分或比赛分钟回退可能来自 VAR、订正或页面问题，先标记冲突，不自行改写。页面时间与已确认排序局部矛盾时记录原样，核对具体受影响行，不用“合理时间”修补。

裁切按实际影响处理：

| 裁切或缺失 | 处理 |
|---|---|
| 仅底部历史或较旧端被裁切；最新端和相关字段完整 | 可确认截图内最新完整记录；只限制历史覆盖，不能声称完整历史或真正初盘 |
| 最新报价记录确实被裁掉，或本行关键字段被裁掉 | 前者只能称最上方可见历史，最新状态未显示；后者保留顶部最新记录的身份，缺失字段待核，不用下方旧行补成最新报价 |
| 侧边、关键列或采用行缺失 | 限制受影响字段、行或市场；不连带否定其他清楚市场 |
| 比赛标题、公司等身份区域未包含 | 用用户说明或已确认配置绑定；无依据时保留未知，只在影响结论时请求补充 |
| 底部残行 | 标记残行，不拼补为完整报价，不用于数值计算 |

“截图内最新”不等于现实实时；“最早可见完整记录”不等于真正初盘。仅在其他页面已确认采用相反排序时，才按该页面的最新端处理裁切，不把这种例外套回本用户已确认上新下旧的截图。

### 3.3 三种“最新”与推荐采用行

1. **截图内最新状态**：本类截图中，本市场、对应报价序列的最上方记录，可能是有价或封盘；顶部字段缺失时分别标记，不以下方较旧完整行替代其最新身份；
2. **截图内最近有价记录**：从最新状态向历史方向找到的第一条完整数字报价；
3. **分析时当前可成交价**：有证据支持在所记录的分析、提交或接受时点仍开放的报价；实际接受成交另需接受记录。

三者不得互相替代。推荐另记“采用行”，通常从各来源的最新完整有价记录中选择，按 §5.2 使用；推荐参考不以证明实际成交为前提。

封盘与恢复按各市场自己的页面顺序处理：

| 图中情况 | 最新状态与报价使用 |
|---|---|
| 顶部是“封”，下方有数字报价 | 最新状态是封盘；向下找到的第一条完整数字记录只作最近有价历史，不能冒充当前开放价 |
| 顶部是完整数字报价，下方历史中有“封” | 顶部数字是最新报价；可记录为该历史封盘后已有较新有价记录，不因下方曾封盘而继续判定当前封盘 |
| 同一分钟内同时出现“封”和数字行 | 按上新下旧判断先后，最上方决定最新状态；不编造秒数 |
| 某公司或某市场顶部封盘，另一来源或市场顶部有价 | 分别记录，不扩大封盘范围；另一报价在合约清楚、相关比赛状态适用时可作为推荐依据 |
| 封盘之后未提供更新记录 | 只确认截图记录时封盘；不保证现在仍封，也不保证已经恢复；旧价不升级为最新开放价 |

封盘市场仍可继续足球方向分析与历史比较；需要给出该市场的新采用价时，使用其他适用来源，或待出现清楚的恢复报价再更新。不因单个市场封盘停止整场分析。恢复后的数字行按新报价处理；是否发生进球、点球判罚、VAR 改判等，仍按事件证据核对，不能由恢复报价反推事件结果。

### 3.4 缺失、封盘与颜色

- 空白、破折号、封盘、不清楚和未显示分别保存，不能填成 0；
- **“封”明确表示该来源、该市场在本行记录时封盘，即暂停接受该市场的新投注。**它不是盘口名称、赔率 0，也不证明比赛暂停或结束；
- 滚球封盘可能与危险球、点球或其他异常情况有关。仅凭“封”不能认定已经判罚点球、发生进球、出示红牌或有其他具体事件；原因未核实时记“未明”，不推造事件方向和发生时间；
- 赛前比分空白或“—”不能改写为 0—0；
- 红绿文字原样保留；网站图例未确认时，不把颜色解释为升降、资金流向、让受或推荐方向；数值变化可用同合约的实际数值比较确认；
- 红底比分只记录为视觉高亮，不能当作红牌；
- 奇偶行底色和网格线只用于定位。

## 4. 盘口、赔率与时间标准化

### 4.1 原文与标准值并存

先保存原始字符，再另列标准化字段。标准值不能覆盖原文。无法确认的字符或方向标为“待核实”，不根据其他市场赔率倒推。

常见盘口可标准化为：平手=0，平手/半球=0.25，半球=0.5，半球/一球=0.75；2/2.5=2.25，2.5/3=2.75。让球的非零幅度不等于方向，主让或主受按原文与已确认的来源配置确定。

香港盘确认后，十进制赔率 `O=1+h`；已经是十进制赔率时不再加 1。香港盘水位可以大于 1，不能因单个数值较大而临时改变制式。其他制式按已确认规则转换，不将负水直接当十进制数。格式未确认时可以条件式换算，但不能把换算结果写成已确认报价。

同线比较才直接比较价格高低。不同线位、不同结算范围或不同让受方向是不同合约，需要比较支付结构；不能只因某一侧赔率更高就判断更优。

### 4.2 时间字段分开

以下时间分别保存：

- 标题显示的开球时间；
- 页面每行显示的变化时间；
- 截图时间，如可知；
- 用户提供或系统收到时间；
- 分析截止时间；
- 报告发布时间；
- 投注提交与接受时间，如有。

在用户已确认的本类页面中，变化时间随赔率变化记录，不代表其他市场刷新，也不表示该条报价在若干分钟后自动到期。没有新变化记录，不自动证明报价过期；同样不能据此保证网站此刻仍开放或用户已经成交。

页面“变化”时间不自动等同于博彩公司系统的原始发布时间。时区未知时保留原文，不能直接认定为北京时间；用户已明确北京时间且配置无冲突时沿用。年份只在标题与行日期关系明确时补足，并记录推定依据。不能用开球时间加比赛分钟反算记录时间。

## 5. 多张异步截图与报价使用

用户通常提供同场 2—3 张截图，可以来自不同公司、网站、市场或截图时点。无需要求完全同刻，也不固定必须提供三张、三家公司或三个完整市场。

### 5.1 每个来源、市场与报价序列分别提取

本类截图直接以各市场顶部记录确定最新状态，再分别保存最近有价记录、本行时间与比赛状态、完整盘口和整组赔率、价格性质、用途及缺口。顶部为“封”时先记录封盘，不跳过它取下方旧数字作为最新。

“使用最新数据”指分别使用各来源、各市场对应序列的最新可见完整记录：不把整张图片的最大时间复制给各表，不回挑更有利的历史行，也不把不同公司的最高价格拼成一家公司的去水赔率或真实串关报价。

同一来源同一序列有多张截图时，按可核实的记录顺序、截图时间及状态判断是否已有更新，保留旧图与采用依据。收到较晚不单独证明截图较新；相同分钟报价冲突且无法确定先后时保留冲突，不平均、不任选一个假装最新。

页面主盘变化序列与同时开放的独立备选线要区分。主盘序列已有新行时，旧行保留作历史；独立备选线不能仅因另一线位更新而自动判成历史或过期。

### 5.2 推荐采用最新报价的规则

**推荐可以采用用户提供的任一来源中，所推荐合约的最新可见完整有价记录，无须等待其他市场同一时间更新。**例如让球最新变化记在 19:00、大小球在 20:00、胜平负在 21:00，三者各自都可以是最新；最终选择让球合约时，可以引用其 19:00 记录，不必改选 21:00 的胜平负。

具体执行：

1. 先确认候选的比赛、方向、线位、结算范围及赔率格式，读取相关来源的最新完整行；分析需要的其他市场与历史变化仍照常读取。
2. 将各来源最新价作为报价参考，可在同一合约、可比较状态下比较价格。异步比较注明各自时间，不称精确同时价；线位不同则按不同合约比较。
3. 选定推荐后注明公司／来源、市场、方向、线位、原始赔率及确认后的制式、本行时间、行号和合约范围。公司未知则如实标记，不因缺公司名而猜造来源。
4. 仅有截图证据时，价格性质通常记“公开参考”，报价角色记“该来源该市场最新”；可以据此给推荐，不必每次加上“因时间不齐暂不推荐”。已另行核实当前开放的，再追加对应证据。
5. 不以报价时间早于其他市场、缺少账户截图、没有实际订单或其他市场缺失，单独取消清楚合约的推荐资格。是否推荐以及是否适合串关，仍按当前框架的比赛与合约分析决定。
6. 若已有更新替代、顶部最新封盘、明确状态冲突、合约变化、采用行缺损或最新记录确实未显示，说明具体限制。历史行出现“封”不单独限制顶部已恢复的清楚报价；本类已确认排序也不反复标为未知。优先使用其他清楚且状态适用的来源，或继续不受影响部分；没有可支持当前采用价的记录时，才将相关报价限于历史研究或条件测算。

“最新参考价”“历史记录”“已知不再适用”“假设价”含义不同。历史记录仍可用于市场反应研究；不能仅因时间较早，把最新参考价写成已知过期价。不得把参考报价、据此推荐、提交投注和实际成交合并为一个状态。

### 5.3 时点、滚球状态与合约标签

比较不同来源前，核对日期、时区、赛前／滚球、比赛分钟及补时进度、比分、人数、VAR 未决情况、关键换人及其他影响本场判断的事件。无法统一时区时不计算精确时间差。

赛前不存在适用于所有报价的统一分钟有效期。若出现超出原情景的关键阵容或其他新事实，更新对应判断，不能把原因归结为单纯时间不同。

滚球报价位于进球、红牌、关键事件或合约变化两侧时分别记录，不能直接视为同一截面。即使比分相同，剩余时间、人数、换人或结算起点也可能不同。异步记录可以用于观察反应；要判断当前新增票，应取得足以支持该时点的比赛状态并更新相关分析。无法支持当前状态时，明确分析对应截图中的历史状态，不把旧截图称作现实实时价。

封盘可以提示核查相关时点是否有危险球、点球相关情况或其他异常，但“看到封盘”不是“事件已经确认”。先结合可得比赛信息判断是否存在影响所选合约的新事件、未决事件或状态冲突；没有相关证据时原因写未明，不自动判定全场报价失效。另一公司仍有价或随后恢复报价，也不单独证明异常已解除；只在已知事件或实际状态缺口影响当前新增票时，针对相关合约更新或限定分析。

“同一分析截点”是截至该时点可得且未被新事实推翻的信息集合，不要求所有来源在同一分钟更新。异步的 1X2、让球和大小球不能机械拟合成一个精确同时点分布；确需联合拟合时，另行记录可复核的时点匹配或状态转换方法。

读取时记录结算范围和起点。本用户的新滚球亚洲让球统一标记为 `AH_REMAINING_REGULATION`：当前比分用于描述状态和更新概率，结算按投注接受后的剩余比分从 0—0 起算。此为本用户约定的合约范围，不是所有平台通用规则；旧赛前票不重置。大小球独立确认是全场累计还是剩余时间。默认常规时间为 90 分钟加伤停补时，不含加时和点球大战；具体计算、接受前事件及旧票处理按当前框架与已核实条款执行。

### 5.4 市场反应观察

历史读取与最终取价分别完成。不能只抄最新三行而忽略变化，也不能为解释走势而用旧价替换推荐采用的最新价。

按以下顺序组织关键变化：

1. **可观察事实**：哪家公司、哪个市场、哪几行、什么时间，发生同线变价、变线、反复切换、封盘或恢复；只称最早可见记录，不冒称初盘。
2. **可比范围**：是否相同线位、结算范围与比赛状态；跨公司、跨市场是否只能作异步有限比较；历史被裁切时说明可见窗口。
3. **支持或分歧**：各公司的同市场是否一致，不同市场是否相互支持或出现分歧。时间精度与覆盖不足时，不声称谁精确领先几秒、谁跟随谁；没有新行不自动证明“毫无反应”。
4. **对具体合约的影响**：只变价时解释价格变化；变线时说明结算边界或临界赛果的支付变化；再结合基本面，说明增强、削弱或不足以改变哪项判断。
5. **解释的证据等级**：已核实新信息、合理但待验证解释、原因未明分别标记。只有记录顺序不能证明资金流向、公司意图、伤停原因或内幕。

可以用简短句式：

> [来源／市场／行号／时间] 从 [旧线与整组价格] 变为 [新线与整组价格]；与 [其他可比记录] 呈 [支持／分歧／无法确认]。这使 [具体合约的价格或支付边界] 发生 [变化]，对原判断的影响是 [增强／削弱／暂不改变及原因]。变动原因 [已核实信息／未明]。

多家公司报价不自动等于多份独立基本面证据。市场变化已进入模型或概率调整时，不能未经说明再次作为独立证据重复加权。读取规范不规定“低水必胜”“升盘必买”等永久方向规则，也不凭市场变化补造独立概率或 EV。

## 6. 固定读取流程

1. **识别身份**：读取比赛、主客、阶段、来源、开球信息和完整性，沿用已确认配置。
2. **划分市场**：按实际表头识别 AH、OU、1X2 及独立报价序列，分别编号。
3. **逐行绑定**：内部读取所有完整可见行，包括封盘与同分钟多条记录；残行单列，不拼补。
4. **沿用排序并查一致性**：本类截图直接采用上新下旧，检查顶部最新记录是否完整，标记真实的分钟、比分或日期冲突；仅对其他未确认的新来源识别排序。
5. **保存与标准化**：保留原文，按已确认配置另列标准值；推定项带依据。
6. **提取最新状态**：本类截图各来源、各市场分别采用顶部最新记录；顶部有价与顶部封盘分别处理，最近有价历史另列，不用全图最大时间统一各表，不把历史封盘延续到更新后的数字行。其他页面按其已确认排序提取。
7. **观察历史反应**：选出变线、明显变价、反复、状态变化和跨市场分歧等关键行，解释对候选的影响。
8. **确定采用范围**：按 §5 区分最新推荐参考、其他历史、已知不适用和假设，局部处理缺口。
9. **第二遍回图**：从拟采用的盘口与赔率反向核对图片、来源、行号、本行时间、整组价格、比赛状态及合约；有差异先修正再使用。
10. **进入分析并记录**：清楚部分直接继续，注明采用行和未确认项；只有影响结论的具体歧义无法自行解决时，才请求补图或说明。

第二遍回图必须覆盖：每个市场最新状态、最近有价记录、实际用于推荐或计算的报价、用于解释的关键变化行、盘口变化、比分变化、封盘前后和同一分钟多行。简化正文不等于省略内部读取与核验。

封盘复核同时检查：是否正确区分顶部封盘和历史封盘，是否已有较新数字行，是否把可能原因写成了确定事件，是否把封盘范围误扩到其他公司或市场。

### 7.1 稳定标识与最低留存粒度

归档字段以框架§25.5的`match-archive-1.0`为统一接口，不另造不兼容的第二套台账。`match_key`定位比赛，`version_id`定位赛前/临场/滚球/赛后版本；包修订不是新增比赛。`source_id`定位证据对象，`quote_id`定位某图片/来源配置、市场及本表某一完整行状态，`contract_id`定位方向、线位、范围与必要起点组成的支付合约。封盘行也可拥有`quote_id`，但没有数字报价时不得生成虚假价格。

采用报价通过`quote_id`连接`source_id`、`image_id`、`source_config_id`、`row_id`和`version_id`，同时保存原行字符、标准值、原始时间与比赛状态、用途角色及真实回图状态。1X2三项或亚洲盘两侧仍属于同一整行；选哪一侧另在合约/投注候选中标明，不能为某一侧借用另一行时间。

`candidate_id`仅表示实际分析过的投注候选；`condition_id`定位原条件；`issue_id`定位问题事件；`improvement_id`表示规则/模型改进候选。一般未采用的历史行无须强建投注候选。真实新报价建新`quote_id`；盘口线、结算范围或必要起点改变时另建`contract_id`。既有ID不因换文件格式或包更新而重编号；别名映射、冲突与纠错保留记录。

**完整观察可见历史，不等于每场强制逐行转录所有历史。**最低结构化留存包括：

1. 每个提供来源×每个可见市场/独立报价序列的顶部最新状态；顶部封盘时另留最近有价历史，无法读取则保留缺口。
2. 实际用于推荐、候选比较、概率/去水/EV计算或条件测算的报价。
3. 支撑市场变化判断的关键历史行，包括有关变线、同线变价、封盘恢复、比分/状态变化和同分钟先后；必须保留影响结论的反方向或冲突记录，不能只挑有利变化。
4. 涉及用户纠正、读图错误、结算争议或后续复核的原行及更正依据。

同一原行同时属于上述多类时只需存一条，并保留全部用途和关联；不同原行即使同分钟或数字相同，仍按§3.2分别保留，不以此合并。已做完整转录的底稿继续保存，不为简化格式删掉。§6的完整可见历史观察、逐行绑定与第二遍回图仍执行；必要字段不清时保留未知，不能因未全量转录而漏读、也不能将未转录的普通历史一律标为未观察。用户明确要求全量转录、专项读图审计或问题需要时再扩展输出。

### 7.2 读图纠错、原报价冻结与赛后结算

发现错读时建立`corrections[]`和关联`issue_id`，逐项记录原字段/原值、正确值或仍待核、证据及图片—市场—行号、发现时间、原版本和更正版本、受影响的`quote_id`/`contract_id`/`candidate_id`/`condition_id`。原报告与原底稿保留；新更正记录引用被更正对象，不静默覆盖原转录。纠错不等于后来市场出现新报价，须在记录类型与时间上区分。

按实际影响回算：身份/主客、盘口正负/线位、赔率制式/数值、时间/状态、全场或剩余结算范围与起点分别检查；再核候选比较、五态、EV（仅有原适用概率时）、主方向/适配、条件、单位收益及实际执行认定。没有受影响也写明核对依据；未完成的重算列待办，不能只改显示文字后宣称修复完成。例如`+0.25`更正为`+0.5`，平局支付由半赢变为全赢，必须重核相应计算；即使最终赛果使两者同赢，错读记录仍保留。

用户赛后只说“搜索一下赛果，反思一下，分析框架有什么可以优化提升的地方”，按框架§18.8进入固定赛后流程。本规范负责把每个原采用/比较合约定位到原报价、原图、原版本和条件，不在赛后替换成更优价格。结算逐票绑定`version_id`、`contract_id`、`quote_id`和赛果证据；滚球剩余让球还绑定原参考或实际接受起点。用户明确确认本场已买可作为执行证据，不强制订单截图；缺金额只限制金额收益，不推定未买。实际合约、价格与必要起点仍须分别有据；缺少执行确认时只做明确标记的原参考合约结算，不能称实盘收益；原图缺失时写明“仅据原文字报价、未回图”，不阻断有依据的局部结算，也不宣称原图核验完成。

先判断是否已有规则未执行，再判断图规遗漏、框架问题或模型问题。问题与改进写入`record.json.audit_delta`，对应原文位置、当时适用条款、现行条款、改动对象和证据/实施/验证状态；无须每场额外生成三份独立台账。全局旧台账不可读时标本场增量待合并，不声称全局已更新。

## 8. 日常输出规则

完整比赛分析按当前框架先给决策卡或滚球状态与合约卡，随后给赔率摘要及影响判断的变化。任务仅为读图或数据核对时，赔率摘要放在最前。

常规回复不展开整张历史表，至少展示：

- 各提供来源、各可见市场的最新状态及本行时间，表中可紧凑合并展示，但数据不跨行拼接；
- 顶部最新封盘时的最近有价历史，明确其用途；顶部已是更新的数字行时按最新报价展示，历史封盘只在影响判断时说明；
- 影响判断的关键变化、跨公司或跨市场支持／分歧；没有明显变化或资料不足时如实写明，不强凑解读；
- 最终推荐采用的完整合约、来源、盘口、赔率、时间及价格性质；
- 会影响结论的时间、状态、制式、方向或完整性问题，以及仅受影响的部分。

只有用户要求完整转录、进行读图审计、排查错误或维护核验样例时，才输出全部可见记录。内部逐行绑定和第二遍核验不因简化输出而省略；默认结构化最低留存按§7.1，不强制把所有普通历史行再抄成庞大表格。

推荐摘要：

| 图片／来源／行号 | 市场与范围 | 本行变化时间 | 分钟／比分 | 最新状态与完整报价 | 价格性质／用途 |
|---|---|---|---|---|---|
| 按图填写 | AH／OU／1X2及范围 | 各表自己的时间 | 原文，空白不填0 | 有价整组／封／未知 | 最新公开参考、推荐采用、历史研究等 |

随后用短段落说明“关键变化及影响”和“推荐采用价”。所选报价已经清楚时，不反复罗列整套时间免责声明，不要求用户补齐其他公司或其他市场才继续。

### 8.1 日常交付、真实核验记录与可移植归档

完整比赛分析按框架§16.5默认提供“HTML阅读报告＋ZIP累计归档”；赛后报告使用框架§18.8统一栏目。HTML供阅读，`record.json`保存结构字段和本场审计增量，ZIP归集实际原件与证据；不要求用户填写JSON或先转成MD。工具限制时可提供完整MD等可读报告并说明归档缺口，不能为了格式完整虚构附件。单纯读图咨询按任务范围输出摘要，不机械生成全场赛后包。

ZIP结构沿用框架§25.4：`report.html`、`record.json`、`manifest.json`，有实际原件时加入`originals/`，实际取得证据/运行产物时加入`evidence/`。原图和原版本只保存实际取得的字节；旧包无需层层嵌套，也不强制每次另交MD、TXT和重复日志。每次更新保留旧版原文、原报价和原条件；包版本上升不修改原比赛日期或原发布时间。

“已检查”与检查的真实材料分别保存。人工回图记录对象、范围、时间、发现结果和未核项，不伪造命令日志；如果实际运行OCR、赔率换算/结算程序或模型接入，记录真实输入、代码/版本、命令或调用、时间、退出状态与输出，保存实际产生的必要凭证。仅保存模型说明TXT、在JSON填写“通过”，或创建空日志均不能证明实际调用/复算；未尝试、资格不适用、读取失败、已读取未复算、调用失败和已复算分开记录；已读取未复算不能作为通过接入核验的数值证据。原赛前执行状态与赛后新增核验状态分开，赛后运行不追溯为赛前已运行。

保存前实际核验：

1. 阅读HTML和`record.json`中的最新状态、采用价、方向/盘口、条件及结算一致；单独交付的HTML与ZIP内报告字节相同，派生预览须另标。
2. `manifest.json`列实际文件相对路径、角色、来源ID、字节数、SHA-256与缺件；不为清单自身计算自引用哈希，外层ZIP哈希如需另存。原件复制前后字节一致，派生件不可冒充原件。
3. ZIP可实际解压，JSON可解析，ID/引用可解析；包内HTML图片/附件使用可达的相对路径，不能依赖本机临时绝对路径。外部网页链接保留来源和获取时间，外部大模型依赖固定引用并标未打包；有外部依赖时不称完全离线可复算。
4. 逐一比对清单中的文件是否存在、大小/哈希是否符合；原图、原报告或日志缺失在清单和记录中显式列明。不以“ZIP已生成”替代内容核验，也不以哈希一致证明分析准确。

这些检查由执行者完成；未做的检查如实标未完成，不复制全勾选清单冒充证据。后续跨场审计可先读索引定位，再回核影响结论的原图与原文；不能只读结构化声明便称全部原件审计完成。

### 8.2 模型访问记录与读图记录分开

涉及模型时按框架§20.12、§25.7和仓库`docs/model-access.md`执行：优先发现并使用已有GitHub连接器，按固定源码/状态提交取得原件；普通网页`DisabledError`或git错误只说明对应通道失败，记录真实类别，不能直接写成全会话认证失败、模型没训练或赛事未覆盖。原件落地、已读取未复算、调用失败、已复算分别留据；访问尝试与清单归入框架约定的证据记录，不混入报价行，也不代替第二遍回图。

本节不改变图片读取、顶部最新、封盘、异步、赔率换算或滚球结算要求；模型访问受阻只限制相应数值，不自动否定已核报价或定性判断。

## 9. 进入比赛分析前的检查清单

- [ ] 比赛、主客顺序、来源和配置依据没有跨图混用；未按图片张数预设市场或公司。
- [ ] 每个实际可见市场已独立识别和编号；本类截图直接沿用用户已确认的上新下旧，顶部最新记录完整性已检查，没有每次重复要求确认排序。
- [ ] 每条采用数据绑定了本行时间、盘口、整组价格、分钟、比分、阶段与报价状态。
- [ ] 没有从相邻行或同高度另一市场借用任何字段。
- [ ] 同分钟多行、反复切换及封盘行保留，未平均、去重或编造秒数。
- [ ] 空白、破折号、红绿文字、“即”和比分高亮没有被错误赋义。
- [ ] 原始盘口、让受方向、赔率制式、时区和结算范围已分别核验；标准值未覆盖原文。
- [ ] 赔率换算正确，没有重复加1或把未知制式当作已确认。
- [ ] 各市场各取最新，没有只选全图最大时间，也没有因异步而自动降级清楚的最新报价。
- [ ] 最新状态、最近有价历史、推荐采用行、当前开放与实际成交证据已分开。
- [ ] 顶部最新封盘没有被旧数值覆盖；历史封盘未被外推到更上方已恢复的数字行，同分钟先后按页面顺序处理。
- [ ] “封”仅确认该来源该市场本行时点封盘；危险球、点球等可能原因未被写成确定事件，也未自动扩大到全场所有报价。
- [ ] 历史变化已用于观察市场反应，变线与同线变价分开，未虚构变动原因或独立概率。
- [ ] 多来源比较没有拼造同时点市场分布、同公司去水价格或真实串关报价。
- [ ] 胜平负去水使用同公司同一完整行；独立备选线与主盘历史没有混淆。
- [ ] 滚球时间、比分、人数、VAR、关键人员与合约起点的相关变化已处理，未仅凭同比分认定同状态。
- [ ] 底部较旧历史裁切仅限制历史覆盖；真正影响最新端或关键字段的缺失已定位到具体部分。
- [ ] 采用报价与关键变化已完成第二遍回图；原图缺失时未声称完成。
- [ ] 推荐未被无关缺口阻断；实际成交未确认时保留未知，未回填或改写历史报告。

- [ ] 原图/文字证据的读取范围、真实归档状态和缺口分开；仅有链接或转录时未冒称已看/已保存原图。
- [ ] 稳定ID能定位原图、报价行和合约；必要转录覆盖最新状态、实际使用、关键变化/反方向证据及纠错行。
- [ ] 纠错保留原值与原版本，支付边界和受影响的计算/结论已核或明确待核；赛后未换成更优价或补写成交。
- [ ] 如有交付包，已核原件指纹、清单、实际文件和报告相对链接；真实执行凭证与自述检查状态分开。
