# F3：评价入口、及时登记与真实报价

本批承接F2。正式框架与图规仍为v1.7修订批次5／v1.2修订批次5；A01、四态、定性判断和90分钟加伤停口径保持。主算法、超参数、固定留出和每日北京时间09:17调度未调整。

## 生产运行

1. 原CLI每完成一个联赛，就用该联赛已完成的独立报告立即冻结预测；账本记录真实登记时刻。后续联赛失败或全任务延迟，不覆盖已经冻结的成功或拒绝。
2. 全任务后仍执行旧前瞻命令，保持原首版评分和严格300秒报价／3600秒预测协议，核查补漏及规范化赛果。
3. `python -m football_model.result_sync --runtime runtime --config config.json` 从已冻结账本寻找待结算比赛，独立查询原API赛程，复用90分钟规范。无需本次训练报告成功；完整身份、终场状态、常规比分和实际取得时间均须通过。已有比分更正只追加，旧缓存不能覆盖较新独立观测。
4. `python -m football_model.collect_quotes --runtime runtime --config config.json --league all --horizon-hours 168 --max-run-seconds 600` 从已有全赛事赛程和当次比赛核查收集真实报价。分页原响应、公司、盘口、价格、源更新时间和取得时刻分别保存，不把采集时间当赔率变化时间。
5. 模型、前瞻、结果、报价、基本面、输出检查和保存分别展示实际outcome。部分成果仍保存；必要步骤失败不会显示为全部完成。

结果常规复查窗口为已结算比赛开赛后7天；未结算比赛不因年龄而停止查证。发现较晚修订时，可显式增大 `--revision-recheck-days`，新结果仍追加，不回写旧评分文件。独立结果与报价不改变 `runtime/data` 或模型，也不因补到新赛果而偷偷重新拟合。

沿用每天5000次服务端日额度校验、分钟限速、重试和缓存。独立结果默认5分钟、报价默认10分钟软截止；它们不新增每轮请求数硬上限。为模型60分钟、结果5分钟、报价10分钟、基本面15分钟及保存留出时间，工作流硬截止从90分钟调整为110分钟。实际请求预算和日程不变，不新增临场轮询、消息推送或自动下注。

## 正式决定与政策研究

F2决定包保留原 `scoring.json` 的未分配状态；F3读取并核验该包，另存评分，不回写决定。实际采用预测由证据绑定确定，不以后台首个合格版本代替。技术入口见 [采用版及三报价协议](s2-decision-scoring.md) 与 [同截点政策评价](s2-policy-evaluation.md)。

三用途分别预注册：`QUOTE_REF`为参考价纸面结算；`QUOTE_OPEN`须另有开放证据；`QUOTE_ACTUAL`须明确成交事实、价格、费用和用途。缺报价、必要条件、成交细节或结果，相关收益保持未知。串关腿可评价该腿的结算分布，不能写成整串实际盈利。

本批同截点政策比较范围是同一正式主候选的行动和影子分级。独立换票、模型×政策、市场融合及整串相关性不由本接口宣称已验证。研究和真正前瞻分别统计；协议、输入、模型、可用报价池与版本选择需事先固定。缺侧、弃权、失败、共同/恢复/失去覆盖均保留，同场版本不累计为独立比赛。

真实比赛分析时先保存F2唯一决定及实际来源，再按已经预注册的用途追加F3记录。未预注册、未实际独立输出影子政策或没有必要证据时如实记录缺口，不能在赛后根据结果补等级、补原概率或制造已执行记录。

## 验收与接续

代码回归、真实原件离线适配、远端CI、合并、真实采集和状态保存各自需要证据。旧40场属于开发材料，不作为新等级或收益效果的干净前瞻集；连续30场仍只诊断流程。没有足够新的同截点样本前，不宣布准确率或盈利提升。

回退可停新采集/评分入口，保留旧严格协议及所有新旧原件；不删除失败或不利版本。后续F4优先做连续数据覆盖、分钟与过程统计质量，再一次少量特征的时序外推与消融；F5再检验分布、市场融合及等级目标。
