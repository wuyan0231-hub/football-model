## 明确的双预算

| 预算 | 限制与作用 |
|---|---|
| 持久传输树 | 500MiB，保持原安全上限；实际暂存树超限禁止提交 |
| 影子新增预留 | 400MiB的保守可保存大小估计；为生产保存留约100MiB |
| 恢复逻辑内容 | 新设独立2GiB有限上限；包括回放解压内容，不是假称仍只有500MiB逻辑容量 |
| 单个原件 | 60MiB，压缩不能绕过原件限制 |

影子预检复用同一归档策略，逐对象按确定性gzip实际字节加保守清单开销增量检查，不扣去重折扣；已有对象复用不重复计费。`runtime_bytes`仍是真实原文件大小，`estimated_persisted_bytes`是保守传输估计，实际提交大小另由保存核验。原400MiB影子阈值与500MiB传输上限不提高；逻辑恢复上限的变更明确披露。

每个压缩对象和恢复原件都核哈希及大小，凭据检查覆盖解压原字节。清单路径须规范相对路径，无重复、穿越、符号链接或文件/目录冲突；未登记对象、无效gzip、额外成员和解压超限拒绝。所有内容验证通过后才恢复或提交，远端状态并发租约仍保留。
