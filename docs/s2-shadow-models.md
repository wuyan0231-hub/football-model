# F4：真实时钟下的模型影子实验

用途是 `prospective_model_experiment`。每日正常任务后，使用已保存且合法的数据及赛程，在真实当前时间分别拟合180天基线、90天候选和365天探索候选。三者使用同一联赛、同一份输入、同一训练截止；仅半衰期不同，ridge与最小训练量来自配置。它们不是生产合格预测，也不是GPT正式选票决定，不自动晋级模型、不输出收益、不下注。

## 执行

```bash
python -m football_model.shadow_models capture --runtime runtime --config config.json --source-commit "$GITHUB_SHA" --league all
python -m football_model.shadow_models score --runtime runtime
```

固定状态离线读取时可提供`--state-commit`的完整SHA；当前工作流尚未保存的新状态不伪填提交，原件指纹和生产来源运行保留。只允许真实时钟命令，不提供`--as-of`。存在`RESEARCH_REPLAY.json`的目录直接拒绝；历史滚动实验由独立研究程序处理。

产物只写`runtime/shadow_models`：

- `protocols`：第一轮拟合前注册的协议，之后同配置沿用原对象，不重写注册时刻。
- `sources/inputs`：数据、赛程、报告、配置、索引、可用场地/赛程补充原件的父指纹与共同输入截止。
- `models/forecasts/coverage/runs`：各臂实际模型参数、比分矩阵、完成/记录时间、全部拒绝与失败。对象按内容寻址，只追加。
- `results/scores/score_runs`：独立赛果原件和每次评分修订，原预测不变。
- `reports/latest.json`与`reports/score-latest.json`：可更新派生摘要，不能替代不可变原件。前者有各臂新记录数及`primary_pair_captures_this_run`本次主比较配对版本数；后者不等于新增独立比赛。

生产`models`、生产前瞻账本和旧预测完全不写。新对象随既有cloud state保存；实际保存成功需另核。

## 状态容量保护

当前cloud state的**实际保存大小**保护仍为500MiB。`state_storage`只在临时传输树中将选定的冷JSON作无损gzip归档；业务runtime的原路径、原字节、指纹、时间和预测含义全部保留，恢复前检查清单、压缩指纹、原件指纹与大小。最新报价、模型和接入索引所需闭包保留原路径读取。逻辑恢复总量另设2GiB上限，包含已有replay gzip的有界解压占用。

影子运行对**整个runtime的保守保存估计**设置400MiB停止新增阈值，给生产任务保留约100MiB空间，不提高500MiB实际保存限额。每次capture/score在写锁下扫描一次，使用与传输归档相同的`estimate_runtime`与`storage_cost`计算：冷原件按确定性gzip真实贡献加逐项清单开销计费，并保留256KiB元数据预算；不折扣压缩对象之间可能的去重。已有内容寻址对象先核原字节，复用时不重复计费；本轮新对象逐个在写入前检查、成功写入后更新预算。派生reports保持inline，按`atomic_json`实际写入字节检查，不能用gzip折扣。

`runtime_bytes`继续表示业务runtime原文件实际字节；`estimated_persisted_bytes`表示保守保存估计；`logical_bytes`额外包含replay解压占用。三者不能互换。raw超过400MiB而保守保存估计仍低于400MiB时可以正常捕获。即使高度可压缩，只要逻辑占用接近2GiB也会停止新增；影子在该硬限内另预留256KiB容量诊断空间。单个新对象也执行传输恢复同一60MiB原字节限制，防止先采样后发现无法保存。`capacity_constraint`区分`estimated_persisted_limit`、`logical_limit`与`file_limit`。超过任何阈值的那次对象写入先被阻止，不能单轮越界后才停。

捕获在启动时已超限，直接延期且不拟合；中途触限保留已经写入的完整对象，退出码1，发布`capacity_deferred`原件及派生摘要，部分捕获量保持未知，不伪填0或本轮全部成功。最多额外使用256KiB保留容量诊断，原件和latest同样按保存贡献及逻辑占用检查；这属于约100MiB生产预留中的极小部分，不是继续采集空间。若诊断原件预算也耗尽，仅更新有限大小的延期摘要：`immutable_event_saved=false`、`capacity_event_id=null`、`diagnostic_evidence=bounded_current_latest_only`。工作流汇总仍明确显示本轮`capacity_deferred`与较弱的诊断证据边界，不能将它变成unknown，也不能声称已有不可变诊断或完整计数。

捕获延期后score仍会核验现有预测并尝试计算；既有相同对象可以复用。如果新增赛果或评分对象无法在阈值内持久保存，评分也明确延期，不把内存计算当作已保存评分。完整生产状态的总量以云端实际runtime及最终传输树检查为准，本地部分下载目录的占用不能代替它。无损压缩解决首轮raw容量误判，但仍不是永久免维护的存储方案；到达实际保存或逻辑阈值后保留延期记录，不能为持续运行删去失败或预测历史。

## 数据和时间准入

从接入索引定位合法最新生产运行及赛程。最新失败不可悄悄回退旧成功；数据观测、赛季原响应抓取/接收、运行报告和预测生成时间必须自洽。缺赛季、错误身份、重复比赛、研究回放及未来观测拒绝。影子180天模型是按同截止重新拟合的公平基线，不能声称逐字复用了原生产预测。

赛程来源是现有日更保存快照。若Q轨道已有较新的单场fixture响应，核原字节指纹、赛事、主客、开赛时间及NS状态；已知改期或停赛继续隔离，不自行改原身份，也不硬编码两场ID。没有新响应时明确日更赛程证据范围，不冒称刚刚查询了官方最新赛程。每条记录先将完整预测payload写入并fsync，完成后读取真实时钟，再追加准入receipt；评分逐一核验payload、receipt、父数据、注册参数和原函数复算。落盘跨越开球时只保留研究payload，不产生live receipt。开赛后完成的计算不能登记为真实赛前影子。

国内联赛仍是原名义主客，实际场地未额外验证；实际比赛的场地变化仍须独立核实。

未知球队、优化失败、参数触边、开赛时超龄均保留原因；候选不可因为拟合失败而消失。无合格未来比赛不为了补时间字段拟合。

## 数值复算口径

原件、父链、payload、保存receipt与真实时钟仍逐项严格核验。使用保存模型参数调用原比分分布函数复算时，`score_matrix`以逐格绝对误差不超过`1e-15`、相对容差为0比较；这用于接纳跨数值环境产生的机器舍入差。两矩阵必须为同形状的数字列表，所有单元有限、非负且不超过1，并通过原`matrix_array`概率总和等门禁。1X2的三个固定字段`probabilities.home_win/draw/away_win`及`tail_mass_before_normalization`分别使用不超过`1e-15`的绝对容差、相对容差为0；两侧都必须是有限的int/float且处于[0,1]，1X2不得缺键或多键。字符串、布尔值、NaN、维度或形状错误、超过容差的真实概率漂移均拒绝。其余全部预测字段继续精确相等；容差不用于期望进球、模型参数、尾部容差常量、矩阵轴、时间、身份或任何原件指纹。

保存的预测、矩阵与模型参数不被改写。capture/score的不可变运行报告及派生摘要附加实际Python、NumPy、SciPy版本与machine架构；score报告及离线诊断另记`numeric_replay_matrix_abs_tol=1e-15`与`numeric_replay_probability_abs_tol=1e-15`。不记录机器名、主机名、目录或凭据。这些是运行环境与复算口径的元信息，不写入实验协议、不改变训练参数、不重注册比较分组；已有缺少环境元信息的预测仍可读取。

PR17真实评分失败后，PR18离线云端核验1110份保存预测，986份通过、124份未通过复算。前20条有界明细仅显示1X2与归一前尾部质量的机器舍入差，最大2.22e-16；相应矩阵差仍在原1e-15范围内，未显示期望进球差异。该明细范围不能代替其余104条的逐字段证据；修复后的全部原预测是否通过须以再次全量云端核验为准。此前位级复算失败、PR17真实评分失败及其舍入差证据继续保留，后续成功不能倒填这些运行。

## 预注册比较和评分

主比较为90对180，365对180另列探索；主指标为1X2对数损失，Brier及大2.5球Brier辅助。每个比较各取同比赛、同输入截止、最终赛程身份一致的首个完整配对，365失败不删除90主比较。后续模型版本与赛果修订不增加独立比赛。改期前版本保留并列出排除ID，新的赛程身份最早配对可以被评分，一场仍只计一次。

评分仅读取现有独立`result_sync`的赛果与原始`/fixtures`响应，再核响应指纹、90分钟`score.fulltime`、赛事、双方及开赛时间。数据尚未成熟、缺结果原件、身份冲突、未知结果保持待结算或拒绝，不填0。不从候选训练数据倒推出“已评分”的结果。独立结果同步尚未覆盖到的影子比赛保持待结算。

当前汇总输出候选减基线的配对差值及场数，负值代表误差减少。这只是描述统计，不输出显著性或自动晋级；0.01对数损失是预声明值得研究的改善量，不是数场达标便认定有效的门槛。足够未来比赛、预定复查节点、比赛/时间块不确定性和多重比较控制另行验收。历史实验结果和此处真实未来结果不能混作一个前瞻样本。

该工具建立模型层新旧对照，不代替框架政策、GPT主方向、单关、串关腿和整串的真实决定配对。
