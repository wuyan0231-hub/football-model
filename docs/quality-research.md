# 按时间前推的质量研究

`football_model.quality` 是离线研究入口，不由每日任务调用，不修改生产参数或现有固定留出报告。它解决“能拟合却不知道是否优于均值基准”的检验缺口；实现及测试成功本身不证明准确率或收益提高。

## 固定协议

1. 显式指定UTC午夜起点与评价截止时间。默认每日一个原点；只在有待评分比赛的窗口重新拟合。
2. 每个原点只使用开赛已满4小时的常规时间终场比分。窗口内所有预测使用窗口开始时的参数；窗口内随后产生的赛果不会进入本窗口模型。
3. 固定比较训练主客平均进球Poisson、原球队Poisson、二者各50%的**比分概率矩阵**混合。混合不是平均λ后再生成Poisson；没有事后搜索最优权重。
4. 附加一个研究用序贯政策：此前已有至少40场共同覆盖且赛果已满4小时的预测后，按这些预测累计1X2对数损失选择候选；此前使用均值基准。并列依次选择均值、混合、原模型。被选候选对当前球队不可用时，明确记录回退到可用均值基准。
5. 三候选和序贯政策的横向比较一律使用同一组共同覆盖比赛。各候选独有覆盖单独评分，仅披露覆盖，不作直接优劣比较。

原半衰期180天、岭强度3及min_train=180为默认值，可通过CLI显式改动。更改候选、权重、参数、日期或选择规则后重跑，仍属于开发；不能把同份数据反复挑选后的结果写成独立验收。

## 指标和复核

- 1X2：三分类Log loss及Brier（各分类平方差之和）。
- 大2.5、主队净胜至少2球：二分类Log loss及Brier（单事件平方差）。净胜2+用于观察深盘相关尾部，不能替代全部让球线验证。
- 大2.25、大2.75：全赢、半赢、走水、半输、全输的五分类Log loss及Brier；不包含赔率，不是EV或收益。
- 每个事件提供固定10等宽概率箱的样本数、平均预测概率和实际频率，空箱保留。1X2与五态按各分类分别校准。
- 每窗口保存原模型完整参数、训练指纹、均值率、选择依据和共同样本1X2损失；逐场保存原点、比分、三个候选及政策概率、市场五态、覆盖与回退原因。可从窗口参数重建比分矩阵。

逐场数据包含实际赛果供评分。序贯选择只读取此前窗口中在新原点前已满足4小时延迟的结果；同窗实际赛果不会参与该窗选型或预测。

## 调用

输入必须是**同一赛事、已经核准的常规时间终场比分**记录列表，或仓库规范`{"matches": [...]}`对象。规范化比赛字段本身不含可认证的赛事/比赛状态，程序不能代替上游核实，也不接受滚球、中止或包含加时的赛果：

```bash
python -m football_model.quality \
  --matches runtime/data/mls.json \
  --start 2025-09-01T00:00:00Z \
  --end 2026-10-06T00:00:00Z \
  --output research-results/mls-walk-forward.json
```

可选参数：`--step-days`、`--half-life-days`、`--ridge`、`--min-train`和`--minimum-selection-matches`。输出包含源文件SHA-256、规范化比赛SHA-256和完整协议。生成的研究结果不应写回生产`runtime`。

## 历史开发与未来验收的边界

所有当前输出固定标记`historical_development_replay`、`deployment_approved=false`、`prospective_validation=false`、`point_in_time_sources_verified=false`。

时间截断只能防止代码使用未来赛果；事后导出的比分文件不能证明早期供应商数据、场地状态和信息发布时间。当时是否已知的修订数据、真实终场时间、伤停和首发均不由本命令重建。即使某候选在本次重演领先，也仅形成继续验证的候选。

未来前瞻验证需要先冻结候选、选择规则和截止时间，在每场开赛前冻结预测及来源指纹，再追加赛果评分；以未来未参与开发的数据检验一致方向、覆盖和各市场校准。应并列给出均值与去水市场概率（取得同截点赔率时），另行进行固定选票规则下的收益检验。本命令不宣称已实现这些未来证据。
