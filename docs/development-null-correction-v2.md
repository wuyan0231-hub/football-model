# R03独立开发：内层允许零修正（2026年10月16日）

这是独立的探索性历史开发v2。英超既有开发结果在设计前已经读取，因此本实验没有未见测试集或确认性资格。现有50文件数值闭包、生产M0、旧协议、380项家族、在跑任务及已有样本身份均未修改。结果不要求优于旧方法，不能据此晋级。

## 问题与唯一改动

现行`choose_alpha`仅在正惩罚强度0.1、1、10之间选，仍会拟合特征修正；当内层历史不足时使用原最强惩罚规则。即使新增特征没有可辨识的增量，它也没有“直接保持M0”这一内层选项。

新入口`python scripts/development_null_correction.py`只在外部调用旧函数，不让任何旧模块反向导入新脚本。新协议为根目录`development-null-correction-v2.json`，身份`s3-r03-null-inner-option-exploratory-epl-20261016-v2`，首轮事先固定英超M_schedule、EARLY，不根据本轮外层结果选择分支。

零修正是`mode=null`且逐字沿用M0分布；**不是alpha=0**，后者代表无惩罚拟合，不能代表零系数。

## 时间与比较口径

- 外层复用冻结的30天基线拟合块，保留全部820场目标；本场结果只在本块选择结束后连接评分。
- 两臂都只使用外层截点前已成熟的同一批真实冻结OOF行。来源使用开赛后4小时可用的历史假设，逐行读取`target_available_at`；不是API当时真实可见证据，也不沿用F5的48小时口径。
- 内层沿用旧选择器的时间顺序80%／20%切分，内层训练还须在第一验证预测截点前成熟。验证结果只须在外层拟合截点前成熟，不得读取当前外层目标结果。
- 新臂在同一内层验证集加入直接lambda0的Poisson损失。非零臂仅在比null改善超过预定`1e-12`舍入平分容差时胜出；平分保留null。内层资料不足时新臂保持M0。
- 旧比较器原样调用`choose_alpha`再`fit_correction`，保留原最强惩罚、拟合失败和回退政策。不是重写旧函数后自称复现。
- 主外层指标仍为比分NLL；1X2、总球、净胜球等分别列诊断。原M0无概率的暖期／未知球队保留未预测，不填0分。
- null沿用M0、非零原生预测、拟合／预测失败回退分别计数；null不能被记作新增特征原生成功。
