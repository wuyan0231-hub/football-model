# 生产更新策略的离线重演

本模块重用 `football_model.cli.run_pipeline` 本身，未另写训练或过期规则，也未改变比分模型、超参数、训练指纹和固定留出检验。它验证相同初始状态、供应商响应和时钟输入能否再次得到相同运行决定与预测；不证明准确率或投注收益提升。

## 在真实运行中录制

```bash
python -m football_model.cli --mode train --league all --record-replay
```

录制默认关闭，工作流可以显式启用。每轮生成 `runtime/replay/bundles/<sha256>.json.gz`，报告 `replay_recording` 给出路径与内容指纹。gzip 只是减小赛季原响应的体积，内容指纹针对规范化后的未压缩 payload，内容相同不会覆盖旧包。

包内仅包含：

- 本轮配置及明确选中的赛事所需的初始模型、对应模型的验证结果；欧国联另保留当前场地登记、查询重试队列和模型引用的场地快照。
- 实际调用 `resolve_league`、`fetch_fixtures`、`fetch_venues` 的参数、返回及失败，`status` 仅记录成功或失败，**不保存账户返回体**。
- 额度的白名单字段、实际读取／修改的请求计数和余额，以及预留额度上下文的进入／退出。
- 线上实际读取的每次时钟；原运行的比赛处理结果与预测，用于同输入对照。
- 影响更新策略的源码及静态场地种子文件指纹；录制开始时已冻结的数值比较政策及版本。

不复制整个缓存，不读取密钥，不记录客户端认证字段。未知配置字段会拒绝录制，以免静默遗漏影响行为的设置或意外采集未来新增的秘密字段。录制出错单独写入运行报告；原预测和模型不因录制失败删除，也不会把无法重演说成已通过。

## 离线运行

在录制包匹配的源码版本及相容的 Python／数值库环境中运行：

```bash
python -m football_model.production_replay \
  --bundle runtime/replay/bundles/实际指纹.json.gz \
  --output-dir replay-results/new-run
```

`output-dir` 必须尚不存在，且不得在生产 runtime 内；包中只允许白名单初始状态路径。回放不构造真实 API 客户端，并阻断 socket 访问。所有API访问和时钟读数按原轨迹匹配，多一步、少一步或参数不同均不能通过。

`replay_result.json` 分别显示精确一致与数值一致，不能混用：

|状态|含义|退出码|
|---|---|---:|
|`matched`|事件完整消费，结构、字段、类型和数值均精确相同；`outcomes_equal=true`|0|
|`numerically_consistent`|事件及离散值完全相同，仅浮点差异满足录制前冻结的政策；`outcomes_equal=false`、`numerical_consistency=true`|0|
|`mismatch`|事件、离散信息或数值未满足比较政策|1|

这里的精确一致针对解析后的结构与数值，不宣称两个原始文件的全部字节相同。原记录可以是失败、无赛程、部分支持或全部不支持；重演原失败不等于业务成功。对照不含生产索引发布；回放不会新建可用生产索引。

比较政策 `replay_outcome_comparison_v1` 固定如下，无操作者可调容差开关：

- 所有一般浮点值仅允许相对误差 `1e-12`，绝对容差为0。极小的正概率从 `1e-30` 变成 `1e-13` 仍然拒绝，不会因小于某个绝对门槛而被隐藏。
- 仅 `predictions/<赛事>/<行号>/prediction/tail_mass_before_normalization` 可额外使用 `1e-12` 的绝对容差。该字段在原模型中明确由 `max(0, 1 - retained_mass)` 得出，近1相减会放大残差的相对误差；它不是直接生成的比分概率。绝对上限沿用现有接入复算的 `1e-12`，此处将用途限定在这个有明确计算依据的残差字段。
- 零与非零变化、符号变化、非有限数值，以及整数、布尔、时间字符串、字段、列表维度或类型的变化，均不使用容差；即使尾部残差也不例外。
- 完整保留每个差异的路径、原值、新值、绝对／相对误差、适用容差与判定，以及差异总数、浮点／非浮点数量、最大绝对／相对误差。另列纯相对比较结果，不能隐藏尾部残差相对变化较大的事实。

源码指纹和比较政策都必须匹配录制包。更改比较代码后，不允许绕过源码检查重跑旧包再称为原政策通过。首轮真实运行曾出现191个事件全部消费但412处浮点不精确相同、最大绝对差异约 `1.11e-16` 的结果；原 `mismatch` 记录保留。用新政策解释已保存的原始输出只属于事后数值诊断。新政策的运行验收必须使用之后按该政策新录制的真实运行；`numerically_consistent` 始终不等于精确重现。

根目录 `RESEARCH_REPLAY.json`、运行报告以及每条预测均明确标记 `research_replay=true`、无新的前瞻资格。目录内的模型、验证、审计及数据都是研究产物；冻结场地快照保留原字节和指纹，不能为添加标记破坏其内容寻址。历史时间来自原观察轨迹，不能解释为今天重新生成了一份当时已经发布的预测。

本CLI没有 `--as-of`、时间覆盖或联网兜底。它只能重演已经录制的运行，不能为此前没有快照的历史补造供应商当时提供过什么。回放也不包含GPT定性判断、截图OCR或实际投注执行；这些分别由证据包、决策记录与真实执行记录检查。

## 功能验收

针对性测试对照真实拟合后的数值，覆盖首次训练、数据未变沿用、相同赛果但有未来比赛且模型超龄时真正重拟合、超龄空窗不重拟合、预测开赛龄门禁、比赛身份错误、接口失败、欧国联场地失败与预算上下文。另验证录制失败保留预测、账户返回体不落档、篡改包或源码不匹配拒绝、旧目录及生产子目录不可覆盖。数值测试另覆盖1 ULP差异、尾部相减残差、极小正概率明显变化、零／符号／类型与非有限值、时间／整数变化，以及真实回放的三种分类。
