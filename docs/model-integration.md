# 自动模型与单场足球分析的执行说明

当前适用：[完整框架 v1.7 修订批次2](football-framework-v1.7.md)＋[截图读取规范 v1.2 修订批次2](odds-screenshot-reading-v1.2.md)。入口同步日期：2026-10-02。v1.7承接v1.6、v1.5修订批次5及A01；旧版本和带日期的接入记录保留历史属性。

首次使用或上下文缺失须实际读适用规范全文，不能凭文件名或摘要称已读；后续回查本场关键条款，文件更新后重读。两份规范保留完整正文并明确当前配套，修订批次2的具体变更见各自首页，原件保留在Git版本历史。必要规则不可得时按框架§0.3尝试可访问原件并记录缺件，不冒称完整执行。

## 你需要做什么

平时直接给比赛双方；日期有歧义时补充比赛日期。有你准备采用的赔率截图就一起提供；没有截图，由分析者查可核实报价。你不需要每天手动训练，也不需要每场上传模型文件。仓库连接如到期，只在身份验证界面恢复授权，不在聊天发送密钥。

日程已经由用户确认开启。现有工作流每天 UTC 01:17（北京时间09:17）尝试更新数据、按需拟合、生成未来7天预测并保存状态；是否实际成功，以相应 Actions 记录和该联赛索引为准。日程、算法、超参数及固定留出保持原样。PR #1处理场地覆盖、跨轮延期与预算保护；修订批次2按用户授权补齐真实时间、场地证据资格、精确城市别名及覆盖分组。相关main推送先测试再自动运行一次 `unl/train`，合并后不重复手动派发。实现、测试、部署和真实运行分别核验，不把文档同步写成已经部署。

## 两个自动化环节

|环节|执行者和触发|实际产物|
|---|---|---|
|后台更新|原 GitHub Actions 每日运行；也可按原入口手动补更|原有模型、预测、验证/运行记录，并自动维护接入索引|
|单场分析|用户在聊天里要求分析某场比赛时，由分析者主动读取|带真实来源的单场模型包、最新基本面核查、具体盘口计算和框架报告|

每日调度不会把全部结果主动推送进每段聊天。固定仓库入口、逐联赛索引及本项目的读取规则连接这两个环节。读取并核验已有合法预测可以复用；重新训练不是每次分析的前提。

## 固定入口与文件

私人仓库：[wuyan0231-hub/football-model](https://github.com/wuyan0231-hub/football-model)。程序与规则在 `main`，运行状态在 `model-state`。分析者先查看最近相关Actions的执行和保存状态，再解析最新状态提交 SHA，用该 SHA 读取同一版本的文件，防止一次分析混用更新前后的状态。若最新任务在写入状态之前失败，旧索引不会知道该次失败；必须把此缺口单列，不能把旧索引当成本次更新成功的证明。

|位置|用途|
|---|---|
|`model-state:runtime/integration/index.json`|机器可读总索引：逐联赛最近尝试、模型、预测位置及失败/无比赛等状态|
|`model-state:runtime/integration/index.md`|便于查看的状态摘要|
|`model-state:runtime/models/<league>.json`|模型ID、真实参数、训练时间、覆盖与验证摘要|
|`model-state:runtime/predictions/<run_id>/<league>.json`|真实比赛ID、主客队ID、时间、完整比分分布与胜平负|
|`model-state:runtime/validation/<league>/<run_id>.json`|该次固定时间留出验证及逐场预测；模型包内亦有验证摘要|
|`model-state:runtime/reports/history/<run_id>.json`|该次运行与来源代码版本；不会因单场分析改写|
|`model-state:runtime/match_calls/`|接入联通检查或后续已保存的单场读取记录；不等于已完成当场基本面分析|
|`main:AGENTS.md`|面向分析助手的固定接入规则|
|`main:docs/football-framework-v1.7.md`|当前完整执行框架v1.7修订批次2；原件可按Git版本历史取得|
|`main:docs/odds-screenshot-reading-v1.2.md`|当前完整图规v1.2修订批次2；原件可按Git版本历史取得|
|`main:docs/football-framework-v1.6.md`|历史框架副本，不作当前入口|
|`model-state:runtime/registries/nations_venues/<摘要>.json`|对应欧国联预测的冻结场地证据，按预测字段取同一状态版本|
|`model-state:runtime/audits/<league>/<run_id>-coverage.json`|新固定留出评估产生时，与上一份已保存逐场验证比较共同、新增、移出和未配对覆盖；保留不可比较原因|

`runtime/reports/latest.json` 只代表最后一次任务，可能只训练了韩国K1，不能据它认定其他联赛没有模型。索引从各次记录归集各联赛状态；不会给旧训练时间换上新的日期。

### 修订批次2：真实时间与历史截点资格

新产物使用 `schema_version=2`、`time_semantics=observed_wall_clock_v1`，以下时间分别保存，不相互替代：

| 字段 | 真实含义与使用限制 |
|---|---|
| `run_started_at` | 任务实际开始时刻，不是资料取得或预测完成时刻 |
| `training_cutoff` | 历史赛果能否纳入训练的截止；不能证明输入在该时刻已经获得 |
| `trained_at` | 兼容旧字段，继续等于原训练截止，保持原陈旧度语义；不能改称实际拟合完成时间 |
| `data_observed_at` | 本次所需来源和场地证据实际取得、核验完成之后的观测时刻 |
| `model_fitted_at` | 模型实际拟合完成时刻；沿用缺该证据的旧模型时保留空值 |
| `forecast_generated_at` / 预测行`generated_at` | 该条预测实际完成时刻；生成时已经开赛则记不支持，不保留数值预测 |
| 运行报告`generated_at` | 全部联赛处理完成后生成报告的时刻 |

来源分别保存各赛季响应的 `fetched_at`、`received_at` 与赛季元数据的 `metadata_received_at`，缓存沿用原取得时间，不给旧响应换新时间。欧国联场地的证据实际可用时间也须不晚于所称资料观测、预测及适用分析截点。重复 `run_id` 拒绝覆盖，旧运行和产物不回写。

**默认当前接入与显式截点接入分开。** 省略 `--as-of` 只按执行时刻核查当前未来比赛；符合其他条件的旧产物可继续使用，但单场包必须保留 `legacy_time_evidence_limited`，不能据此证明历史赛前资格。新预测沿用旧模型时，`model_fitted_at` 保持未知、`model_time_evidence=legacy_time_evidence_limited`；不会仅为补时间字段而重新训练或给旧模型编造拟合时间。

只要显式传入 `--as-of`，就必须有新格式模型和预测及完整、相互一致的时间证据；旧产物或后来才取得的资料会被拒绝。欧国联还要求场地事实在比赛对应时点有来源支持的有效区间；仅有当前抓取/核实时刻而未知有效区间时，不能通过这种历史截点检查。不得把省略参数当成绕过拒绝、证明旧赛前资格的方法。当前模型全部其他来源也未因此自动成为完整历史快照，严格按当时资料重演的质量仍须独立核验。

### 修订批次2：覆盖分组怎样阅读

`coverage_audit` 将上一份和本次固定留出逐场验证分组：`groups.common` 为两份都有且比赛身份、赛果和训练截点配对的样本，保存新旧log loss和Brier；`groups.new_only` 为本次独有的可评分样本，保留自身评分和旧侧排除原因；`groups.removed` 为旧侧独有样本，反向保留同类依据；`unpaired_common` 保留共同ID却不能配对的原因，`exclusions` 各自保留排除记录。没有旧逐场验证原件时，新增数量保持未知，不把本次数量全称作新增。

切分、评价时间窗、训练截点、目标或参数条件不一致时，标记 `noncomparable_diagnostic` 并在 `comparison_eligibility.reasons` 保留原因；缺失的时序证据保持未知。`pure_repair_effect_validated` 不因此变为真。新增/移出可能由滚动时间窗、历史回填或数据修订产生，不自动证明场地修复的纯效果，也不自动属于前瞻样本。共同覆盖、额外覆盖、深盘及收益的效果验收分别报告。

## 每场怎样执行

以下是本仓库接入动作；完整单场仍按框架§2的S00—S11推进，以§21逐项发布检查，不能将这份摘要替代完整足球判断。

1. **确认对象与真实截点。** 查明赛事、比赛ID、主客队ID、开赛时刻、当前赛前/滚球/完赛状态及场地。展示北京时间，同时保留原时区；分别记录请求、分析截点、发布时间、抓取与复算时间，未知不互相替代。记录是否已见赔率或结果，双方队名相似时不得猜测。
2. **取得模型并核失败范围。** 固定真实源码及状态提交，读取匹配的索引、模型、预测、验证与运行记录；核模型版本、训练截止、观测/生成时间和最近目标联赛任务。仅他联赛失败不自动封本联赛，目标失败、全局/索引失败、错配及过期按实际门禁处理，不以显式复用绕过。现有14天与新球队不支持规则保持原样。
3. **生成并保留真实单场包。** 任务适用时实际调用原 `score_distribution()` 复算已存预测，不调用训练函数。执行者保存固定路径、原字节SHA-256及可核时的Git blob；派生转换另记父指纹/转换/派生指纹。分别记录预测来源代码提交与本次复核代码提交、真实命令、退出状态、错误或输出。记录实际λ、矩阵行列数、比分索引范围、尾部/归一处理和验证摘要，不猜方阵尺寸。已开赛、前视时间、错联赛/错队、陈旧模型或输出不一致时拒绝当前赛前数值接入；已经确认任务不适用则记录资格原因直接定性回退，无须为形式完整调用已知不适用命令。
   欧国联预测若带 `registry_snapshot`，须从同一固定状态提交取得其指向的 `runtime/registries/nations_venues/<摘要>.json`，交给原单场命令核验。自动登记流程见欧国联接入说明；不得只拿种子表或最新表替代预测当时的场地证据。
4. **补本场资料。** 自行核查当前赛程是否改期/取消、是否中立场、伤停、预计首发、战术、轮换与赛程背景。机会统计保存供应商、定义、主客列序、实际样本/时间窗及抓取时间；同源修订和异源冲突并列，不能跨供应商拼有利xG或把全场数当特定人数/时段数。当前接入程序不联网核查这些项目，所以包内仍会列待核项；不能将“包生成成功”写成“全部事实已核实”。
5. **核赔率并实际计算。** 有图按v1.2全文逐市场整行绑定，读取完整可见历史并第二遍回图，用户已确认上新下旧时直接各取顶部最新；顶部“封”不跳过，历史封盘不延续到较新数字行。异步变化时间不自动过期，任一提供来源的清楚适用最新价可作推荐参考；原因未明的封盘不推造点球等事件。没有截图则查有来源/时间的报价。参考价、当前开放、实际接受成交分别记录。用合法适用矩阵按框架§10、§11、§22映射真实合约，含四分之一盘五态及临界支付检查；P(R>0)、P(R≥0)、P(R<0)与净EV分开。无适用分布或价格时写未量化，不填0；接入成功不等于已计算EV。
6. **公平比较与适配。** 先审胜/平/负、让球两侧、大/小两侧，再选各市场代表及唯一相对主方向，说明自身机制如何满足具体支付、最强反证如何处理、为何优于最近真实替代。独立评适合/条件适合/不建议/暂无法判断；条件仅用于真正改变该票的关键未决事实，写可观察标准、核查来源、满足/不满足/未知及各自动作。无模型、无xG、普通首发未知、异步市场或没有其他串关腿/成交订单不自动否决；不恢复默认+2%/+5%EV门槛。未建模因素以定性或未加权情景处理，不手调λ、胜率或EV。
7. **检查、发布与保留版本。** 按框架§21记录各项通过/不适用/未通过、依据及修复/局部回退，以§25字段保存实际证据状态。报告注明实际已读规范、模型/预测来源、时间、采用范围、反证、条件及未知项。原r1、失败、条件未知、执行未知保留，更新另存r2；开赛后新登记或输出标记真实取得时间及工程复算/历史复盘范围，不能称原分析截点的赛前预测。

报告的最小接入说明为：

> 本场实际读取框架v1.7修订批次2〔有图时另记图规v1.2修订批次2及回图状态〕。已读取〔源码/状态提交、固定预测路径和原字节指纹〕；模型〔真实ID〕，训练截止〔时间〕，真实分析截点/读取复算时间〔分别填写〕。历史攻防为模型量化；临时阵容及其他未建模因素为定性或未加权情景。模型仍为探索性固定留出基线，本次采用范围〔填写〕。

方括号内容必须来自当次真实操作；没有读取时明确写未读取，不照抄示例。

## 操作命令（分析者使用，用户不需要输入）

以下命令从项目根目录执行，输入是已经授权取得的真实 `runtime` 状态文件。

```bash
python -m football_model.integration match --runtime runtime --config config.json --league mls --match-id 1490209 --state-commit STATE_COMMIT --output runtime/match_calls/example.json
```

`STATE_COMMIT` 必须替换为实际读取的状态提交。1490209只是历史联通检查采用的真实已存赛程ID；分析其他比赛必须改为实际ID。默认分析截点是执行时的UTC时间；可用 `--as-of` 指定带时区的明确截点，但须满足上文的新格式时间证据与历史资格检查，禁止借它进行使用未来数据的历史回算。程序不获取赔率，不修改球员影响，也不生成下注操作。

索引生成由原 `run_pipeline` 末尾自动执行，因此后续每日任务会一并保存索引。仅在取得完整本地状态及运行历史、确需修复索引时才运行 `python -m football_model.integration index --runtime runtime --config config.json`；不在只下载了单场/单联赛的目录重建“最新”索引。单场读取包不是新训练结果；聊天底稿只有实际保存成功后才称已归档，后台不自动保存未上传的聊天记录。

## 遇到缺口怎样继续

|情况|处理|
|---|---|
|有完整且可适用的已存预测|读取、复算核验后使用；仍补查本场资料|
|未来7天预测为0场|如实标无预测；先核对真实赛程和日期，不把0场当零概率|
|比赛找不到或预测窗口外|先核比赛身份及最新赛程；必要时按原工作流补更，未生成对应输出前不填模型概率|
|最新更新失败或模型陈旧|区分目标、仅他联赛及全局/索引失败；按实际程序资格阻断受影响数值，不用旧成功绕过；继续可支持的定性分析|
|旧产物时间证据有限或场地有效区间未知|如实标明范围；旧产物仅可按默认当前未来核查路径使用且保留受限标记，不能证明显式历史截点；不改旧文件、不补时间或强行回算|
|新球队尚不支持|按用户已决定的范围暂缓冷启动；不补默认概率|
|欧冠|国内模型不能直接拼接，继续定性分析|
|场地、开赛时间发生变化|旧包不能直接应用，重新核对并用适用模型/输入重算；不把名义主客模型当中立场已修正|
|关键伤停未进入模型|保留基础概率的真实含义，按A01做情景；不声称已完成数值阵容修正|
|仓库暂不可读|明确实际未读取模型，继续可完成的定性分析；只有认证确实阻断时才请求恢复连接|
|已开赛/完赛，只有赛前基线|不得作为当前滚球预测；历史复盘只使用原截点可得且已保存的对应产物，新补场地不能回写旧预测资格|

## 本次接入不代表哪些能力升级

现有模型是15个国内联赛及欧国联分别拟合的时间衰减正则化攻防泊松基线；不含已训练的Dixon–Coles修正、xG、球员或滚球模块。验证保持固定时间留出，不能改称滚动验证。完整比分矩阵使盘口数学映射可计算，但深盘、大小球和实际收益尚未完成专项验收。美职联、墨西超初步验证仍落后于简单联赛基准；其余联赛的探索性评分也不等于盈利证明。

当前完整政策以v1.7修订批次2为准，A01、三市场判断和原结算代码继续保留。v1.6的真实接入与v1.5修订批次5为历史基线。规则已写入、工程已实现/部署、预测与收益增量已验证是不同状态；历史32场仅用于开发/执行诊断，连续30场仅为流程检查，不作为盈利通过线。

## 2026-09-24：欧国联扩展
