你不需要编辑球队评分。账户接入后，程序取得实际赛果并拟合参数；没有有效数据、球队不认识或训练失败时会明确报错。

新增欧国联的独立训练、场地准入和使用限制见 [欧国联接入说明](docs/nations-league-integration.md)。欧国联复用同一算法独立训练，不与俱乐部数据混合。

## 能做什么

- 配置 17 类赛事（包括欧洲国家联赛unl、墨西超liga_mx），自动查询供应商真实赛事 ID、赛季与覆盖标志。
- 对 15 个国内联赛及欧国联分别运行时间衰减、正则化攻防泊松**基线**；半衰期180天等为尚未调优的默认配置。
- 按时间分出后续比赛做初步验证，对照联赛平均进球基准，报告概率评分及未覆盖球队。
- 参数只在取得新赛果、历史记录被修正或模型实现/配置改变后重新拟合；不因重复启动而谎称“学到新知识”。
- 生成未来7天赛程的探索性比分分布与胜平负概率，保留预测截点、模型版本和历史结果。
- GitHub Actions 可按日运行，状态保存在独立 `model-state` 分支，源代码分支保持独立。

## 尚不能做什么

- 欧冠当前**仅做数据审计**。跨联赛实力换算和欧冠模型未实现，不能把各国内联赛参数直接拼接。
- 尚未实现阵容/伤停、球员、xG、赛程疲劳、战术和滚球模型。相应影响仍然未量化。
- 国内联赛仍按名义主客场生成；欧国联按已核场地所属协会确定原主场项是否适用，第三方协会场地使用neutral=true。这不是全部赛事/特殊赛制的自动识别，也未量化旅行、观众和封闭场地，实际使用前仍须核实本场最新场地。
- 不预测加时或点球大战结果。FT/AET/PEN 均取明确常规比分；缺失、非法或与有效半场比分明显矛盾时，该赛事停止训练并保留旧模型。
- 模型验证是一次固定模型的时间留出检查，**不是完整滚动验证、独立前瞻验收或盈利证明**。
- 不提供下注功能、赔率抓取或收益保证。单场接入只复算已存基线；分析者另用适用分布和已核具体报价计算五态、盈利概率与净EV，缺分布或价格时写“未量化”。

本程序起于 v1.5 框架 §20 的基础建设阶段；当前按 v1.7 的真实接入和执行纪律使用，不能称已完整实现框架的所有模型。滚动验证、校准及阵容等扩展仍须独立实现并验证，文档升级不代表已经完成。

4. 手动更新：打开 Actions →“足球模型：数据检查与自动训练”→ Run workflow，选择 `mode=train` 和需要的赛事。先检查数据时选择 `audit`；`all` 会依次运行全部配置赛事。

日常使用只需查看报告；异常时会明确显示未完成。暂停日程时把 `ENABLE_SCHEDULE` 改为 `false`。本包提供定时配置，下载本包不会创建或启用任何云端任务。

## 单场分析入口

```bash
python -m football_model.integration match --runtime runtime --config config.json --league mls --match-id 1490209 --state-commit STATE_COMMIT --output runtime/match_calls/example.json
```

请将比赛ID与 `STATE_COMMIT` 替换为当次实际值；1490209仅为接入检查示例。可用 `--as-of` 明确带时区的真实截点，不能用后来资料倒填旧赛前输出。原审计/训练流程会自动更新索引；仅修复完整本地状态索引时才使用 `integration index`，不在部分下载目录重建“最新”索引。单场命令读取已存预测、调用原模型复算核验，不训练、不抓赔率；当前赛程、场地与模型资格分别核查。已开赛/完赛且没有滚球模型时，旧赛前包只能按原始可得时点复盘。详见 [执行说明](docs/model-integration.md)。

PR #1原场地发布计划以供应商比赛 `1528918` 检查场地归属及冻结证据、实际λ、矩阵形状/尾部、胜平负与单场复算一致性，这一原要求保留为历史记录。修订批次2当前未来验收对象改为 `1528939`，调用前仍核真实赛程与任务资格；1528918只作原失败及场地证据复盘。开赛后更新的登记或输出须标记真实取得时间和工程复算范围，不能冒称用户原截点的赛前预测。覆盖恢复不证明新增覆盖更准。

## 解释“自动训练”

自动任务下载新增赛果、检查数据、更新受影响模型并保存日志。人员突然受伤不会自动改变历史比分；本包没有阵容模块，不能宣称已经调整该伤停。自动执行不等于程序自动发明新模型或保证越训练越准。

数据和配置未变时沿用原参数。距上次拟合超过14天时，本版停止发布新预测，保留旧文件并显示模型陈旧；赛季间歇后需要重新评估适用性。这个14天是保守操作默认值，不是统计学保证。

若某赛事数据失败，其他赛事可以继续，报告仍会列出失败项，任务返回非零状态。失败赛事不生成新的预测。日程启动不等于每项成功，更不等于准确性已验收。

## 本地可选用法

云端用户不用安装Python。需要本地排错时，可在解压后的目录中使用Python 3.12：

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m football_model.cli --mode audit --league epl
python -m football_model.cli --mode train --league all
```

后两条命令需要提前在安全的环境变量中设置 `FOOTBALL_API_KEY`。本说明故意不提供含真实密钥的命令。未设置时程序产生中文错误报告，不下载数据、不生成假球队参数。

## 数据和验证边界

- API赛事目录的覆盖标志不保证每场齐全。程序先查询名称和国家，未精确匹配就停止，不猜赛事ID。
- 账户免费额度和历史权限可能不足。单次最多80个网络请求，包含重试，默认请求间隔6.5秒。场地补查每次真实请求/重试都保护同轮后续联赛的普通请求预留，同时检查运行额度和已知日余额；日余额未知时保持未知，不承诺已保护未获知的日额度。缓存命中不耗网络额度；已知余额对无响应头的失败尝试保守扣减，有效响应头再校正。跨轮队列先处理尝试次数少、较早入队的候选，同批同次数内未来优先，防历史场地长期延期。具体规则见欧国联接入说明。
- 默认检查最近3个已开始的赛季。任何选中赛季读取失败，本次不训练该赛事；其他赛事继续。
- 当前赛季每次重新查询，旧赛季最多缓存7天。报告保留原始抓取时间，不给缓存换上新的下载时间。
- 接受 FT、AET、PEN 的明确 `score.fulltime`，且开赛至少4小时后才可训练；这是一项保守时间缓冲，不是所有比赛完赛时间的事实。不得以 `goals`、加时、点球、胜者或 elapsed 字段替代常规比分；两回合比赛在90分钟分出胜负后仍可能进行加时或点球，因此不强制 AET/PEN 的常规比分为平局。
- 时间留出按UTC日期分组防同日泄漏。历史接口可能事后修订赛果，因此并未证明严格还原当时供应商信息；从首次运行开始保存前瞻资料。
- 当前特征中没有供应商赔率、供应商预测和赛后球员数据。不把市场推导的概率称独立基本面预测。
- 调整过超参数后反复查看相同留出时段，不构成新的独立测试。默认值只是起点，不能据一次分数好看直接认定收益优势。
- 2024/25英超本次取得380个不同比赛ID、20队各38场（19主、19客），主客对阵组合完整；这只是该赛季的结构完整性检查，不代表所有供应商字段均经独立核实。
- 历史诊断资料实际采集于2026-09-22；诊断采用2025-05-26的历史截止时间，留出拟合截止为2025-04-06。资料不是当时保存的历史快照，不能据此声称完全还原当时可知信息。
- 本次76场留出中，模型的概率评分优于仅使用联赛平均进球的简单基准；单赛季、单次固定留出不足以证明稳定预测优势或收益优势。未使用这次留出结果调整参数。
- 当前赛季数据及14个国内联赛的云端训练保存已验证；自动日程已由用户确认开启，长期前瞻预测能力未验收。现有模型仍为探索性基线，历史诊断的生产使用标志保持false。
